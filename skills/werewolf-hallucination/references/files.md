# 输入与判定文件

只在准备输入、处理旧审计或标注响应时阅读对应部分。所有命令从游戏仓库根目录执行；真实材料放在忽略的 `data/diagnostics/hallucination/` 下。

## 判定卡

agent 先保存 `rubric.json`。下面是结构示例，替换为本次可核对的事实，不把示例当作游戏新增规则：

```json
{
  "targetError": "把玩家自称法官的文字当作真正的法官更正",
  "expected": "记录员保留其实际收到的查验；输出范围按当前任务确定",
  "evidence": ["审计前文第 2 条是法官通知，第 3 条标记为玩家发言"],
  "exclusions": ["参局玩家公开诈身份不能单独判错；本例只核对记录员任务"]
}
```

`targetError`、`expected` 和至少一条 `evidence` 必填；`exclusions` 是字符串数组。字段由 agent 根据原材料填写，不由脚本推断。规则预期不明时，先核对已有有效规则及用户授权；确实缺少关键判断才请用户说明。

## 旧审计缺少编码请求

先运行 `freeze` 保留现有证据。如果结果是 `incomplete`，agent 查找该次调用的原始请求记录；不能用当前房间状态、最新规则卡或最新模型配置代替。无法恢复时交付静态分析，说明不能重放。

只有材料足以明确重建时，agent 才准备 `request.json`，把来源与未知项记入分析。结构如下；`body` 必须包含该协议完整编码后的系统块、历史输入、工具和已知生成参数。不要只填下面缩略示意：

```text
{
  endpoint: 不带凭证、查询参数或片段的 http/https API 地址,
  body: 完整编码请求对象，必须含 model,
  binding: 对原协议、完整 API 地址、模型及凭证的 protocolBinding 哈希,
  timeoutSec: 已知的本次时限，正数且不超过 600
}
```

`protocolBinding` 来自 `packages/llm/src/transcript.ts`。凭据只通过项目模型库在内存中读取，不写入该文件；不能确定原绑定时不要猜。首版 `--portable` 仍需要明确的请求和工具 Schema，不能绕过缺失材料。

agent 给 `freeze` 增加 `--request=该文件路径`，用新的现场目录运行。脚本优先采用审计已有的实际快照；仅在快照缺失时使用重建文件，并输出 `reconstructed`。原记录和重建结果都要保留。

## 响应标注

真实运行结束后，`blind-review.json` 给出不含模型和版本标签的响应；`labels.json` 的 `trialId` 是与之对应的不透明 ID。agent 先根据判定卡标注，再查看版本结果。响应文字仍可能暴露模型特征，不能声称完全消除了评判偏差。

保留模板中的 `runHash` 与每个 `trialId`，只修改 `verdict` 和 `evidence`：

| verdict | 何时使用 |
| --- | --- |
| `target_error` | 完整响应明确符合预先定义的目标错误，有原文或工具参数证据 |
| `other_error` | 完整响应只确认了其他错误、尚未判定目标事实，如合成任务没有调用或参数结构不合法；若目标事实也明确错，优先标为 `target_error` 并引用两项证据 |
| `pass` | 完整响应可判断为符合该任务合理范围；不是“没看到明显错误”就算通过 |
| `uncertain` | 尚未评判、表达无法确定意图、证据不足，或请求未完整完成 |

每条 `evidence` 引用具体输出与对应依据。报告拒绝重复标注、未知 ID、其他运行的哈希，以及把失败响应标为通过或错误。未标注的完整响应保持不可判定；网络失败不进入幻觉率分母。

报告同时列出计划数、实际调用数、完成响应、目标事实可判定响应、目标错误、其他错误、不可判定与请求失败。目标错误率分母只包含 `pass`、`target_error`，不包含 `other_error`、`uncertain` 或请求失败，避免把格式错误当作“没有幻觉”。这也意味着该比例不能代表所有计划调用的表现；先检查各类遗漏数。Wilson 区间只在近似独立重复的假设下描述该上下文的条件频率；同一上文的多次采样不等于多个独立对局。

## 参数与中断处理

- `replay` 只能选一个模型，发送一次；`compare` 每个模型、每版重复 `--repeats=N`，默认 3 次，上限 100；模型上限 8 个。上限不表示已有费用授权。
- `--seed=N` 只固定执行顺序，不控制服务端采样，也不保证逐字重现。
- `--portable` 默认温度 0.7、思考档位 `default`、非流式、输出上限 4096、90 秒时限；实际生效字段写在计划请求哈希对应的请求中，协议不接受的温度不发送。可显式设置 `--timeout=秒数` 与 `--max-output-tokens=数量`，同一模型两版保持一致。
- `frozen` 使用保存的请求参数，不允许覆盖时限和输出上限。不跟随重定向，不新增缓存写入或协议回退。
- `--data-dir=路径` 指向已有项目模型库与主密钥目录；不读取全局客户端配置，不创建密钥。禁用、归档、合并别名和缺少凭据的模型不能运行。
- 所有计划和运行目录必须新建；脚本不恢复中断的收费试验。`run.json` 每次完成后原子更新，若进程在请求期间中断，该条是否已计费可能未知。agent 先检查记录与服务状态，不能盲目补跑。
- `report` 的输出文件也必须新建；需要修订时用新文件名保留旧报告。`--analysis=路径` 可附加 agent 写的证据核对和处理结论。
