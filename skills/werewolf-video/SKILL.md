# 狼人杀对局视频

使用目标仓库里的确定性程序完成机械步骤。使用 skill 的模型负责备料、审核声音、选择节点并润色开场/上帝点评/收尾；脚本不会自动替你完成这项编辑。默认完整对局，用户要求样品时只制作样品。

## 先定位，再运行

目标是 `package.json` 名为 `ai-werewolf` 的游戏仓库。程序位于 `scripts/video/`，依赖由项目锁文件维护。命令在仓库根目录执行：

```powershell
pnpm video:make --room=latest --prepare-only
```

`latest` 只从默认 `data/rooms` 选择已结束对局，不扫描界面测试目录。指定另一数据目录用 `--data-dir=绝对路径`；指定房间用 `--room=ID`。

**首次制作或修改台词必须先读 [制作前准备与台词润色](references/preproduction.md)。** 按其中材料表读取 `plan.json`、`editorial-context.json`，完成声音表、旁白稿与必要的样品选择表，再开始耗时合成。准备成功不等于完成润色；不要只跑下面的命令便交付。原话/法官取舍见 [剪辑规则](references/editing.md)。用户已授权的任务完成内部审核后直接继续，普通审核由模型完成。

```powershell
pnpm video:make --room=ID --resume
```

这一条依次完成导出、材料准备、TTS、自动波形检查、音频时间轴、直接小体积渲染、预览和检查；台词润色须先按上面的手册完成。检测到破音时停止在检查点；已授权的范围内加 `--repair-audio` 可自动重配异常片段并复查。第一遍编码就限制码率，最终只拼接视频并编码主音轨，不先生成大母版再压缩。已成功的音频与视频片段自动复用。没有 pnpm 可直接运行：

```powershell
node node_modules/tsx/dist/cli.mjs scripts/video/workflow.ts --room=ID --resume
```

其他 agent 可用本技能的 `scripts/run.mjs --project=仓库绝对路径` 启动同一程序。如果目标仓库缺少制作程序，使用 `scripts/bootstrap.mjs --project=仓库绝对路径` 安装随技能附带的程序和美术资源，并补齐缺失的依赖声明与启动命令；已有实现保持原样。随后用项目包管理器安装依赖。游戏导出模块仍来自目标游戏仓库。

## 必须保持的约束

- 从真实事实流恢复身份、存活、警徽、票型与昼夜；不要从自然语言或模型思考猜动作，不提前显示后续结果。
- 玩家台词只来自真实提交的 `speak`/密谈原话；动作配音只口述查验、药物、守护、方向等工具的真实选择。不得改写分析、补充理由或虚构回答。完整模式保留全部原话与顺序，分段可还原原文；样品精确保留所选原话。
- 系统超时/托管产生的话语标“系统托管”，不冒充模型原创。`integrity.ts` 在 TTS 前核对原话、朗读文本和动作来源，不能绕过检查来合成修改后的玩家发言。
- 保留必要主持链：夜间询问→真实选择→确认/闭眼；警长询问→真实的起点/方向选择→直接进入发言（视频不重复报）；无警长或警上阶段只报起点和方向，不逐个念全桌号码；投票邀请→结果播报。游戏事实记录仍完整保留。
- 法官与上帝点评分声线、分标签；点评用 `after` 接在事实之后，不覆盖必需播报。行动选择转述须标明来自记录，不能冒充玩家原话。
- 一位玩家固定一个声音，法官、解说分别固定声音。依据昵称、人设与人物图核对声线，不给全桌同一音色。
- 右栏展示本局全部身份的技能，长内容连续循环滚动，不固定展示某一个身份；票型框按行数收紧，投票人号码和票数清楚。
- 底栏左侧使用对应人物头像、编号、真实身份与昵称；法官使用法槌徽记，上帝解说使用眼睛与星芒徽记，各有固定标签与声线。字幕在右侧独立文字区垂直居中；保留“行动转述／系统托管”等来源标记。画面细则见 [制作前准备](references/preproduction.md)。
- 使用实际 WAV 样本数与服务商真实时间戳/强制对齐。无时间戳时停止并做真实对齐；不估算阅读时长冒充正式时间轴。
- 字幕文字以已确认的朗读稿为准，服务商时间戳标签只用于定位；必须核对字幕与原稿，不能把标签里的同音错字直接烧进视频。字词漏增或无法可靠对应时做真实对齐。
- TTS 后检查原始波形，不能只看平均音量或归一化后的峰值。使用自动工具定位异常、有限次重配并复查；正常片段保持缓存。排查破音、使用独立工具或维护检测规则时读 [配音质量检查与定点修复](references/audio-quality.md)。
- 当前成片是上帝视角，含私密夜间信息。玩家/闭眼版本需要先实现权限过滤，不能复用全知显示。
- Qwen 仅用已获准的 Token Plan 凭据；程序在内存读取密钥，产物不包含密钥或房间令牌。鉴权、额度或限流失败时保留检查点并报告，不切换付费线路。

## 可调选项

- `--encoder=cpu`：无需独立显卡；`auto` 自动尝试 NVIDIA 编码并允许软件回退；`gpu` 要求实际使用 NVENC，失败就停，不隐瞒回退。
- `--project-dir=绝对路径`：独立版本目录，保留旧片；不要把样品和完整视频混在同一目录。
- `--video-kbps=750 --max-video-kbps=1200 --audio-kbps=96`：直接限制分段和整片码率，1080p/30fps；先试做昼夜片段再据清晰度调整。
- `--theme=campus|storybook|gufeng|fantasy|urban|future`：六套人物；更换后核对声音与人物是否相符。
- `--voices=绝对路径`、`--narration=绝对路径`：显式使用已整理的配置。
- `--tts-provider=ID --tts-adapter=文件路径`：显式接入其他 TTS；内置仍为 `qwen-token-plan`，不自动换服务或计费线路。
- `--repair-audio`：波形检测失败时，仅重配异常片段，保留原文、固定声线与成功缓存，最多尝试三次；当前自动重配支持 Qwen Token Plan。
- `--through=plan|tts|audit-audio|timeline|render|preview|verify`：停在完整的阶段检查点；旧文件再压缩是独立工具，不在默认流程中。

默认单路编码；显存与性能判断读 [硬件说明](references/hardware.md)。批量配音、Qwen 特例和接入其他服务时，读 [批量 TTS 与适配器修改](references/tts-batch.md)，其中逐项说明改哪些文件、输出什么、怎么配置和验证。维护程序或适配新日志读 [程序设计](references/automation.md)；小体积交付见 [压缩方案](references/compression.md)。

## 验收和交付

以 `output/verification.json` 为程序检查结果；同时看 `output/review/` 的夜间、玩家发言、票型与终局帧，试听至少一个玩家和一个上帝片段。检查底栏长昵称、两位数编号、行动来源标记和法官／上帝切换；字幕应居于右侧文字区中部，不能压住左侧头像与身份。文字、号码和身份标签应清楚，状态不能遮住人物。

默认交付直接编码得到的 `output/latest-match.mp4` 小体积整片。核对 `render-report.json`、`gpu-metrics.json` 和 `verification.json` 的实际编码器、大小与时长，不把短片比例当作整片实测。可附预览、字幕和时间轴，说明是否节选。样品使用独立目录和 `sample-verification.json`，不覆盖原整局。

最终标题与简介保存为对应制作目录的 `output/publish-copy.md`，与成片放在一起，分别使用“标题”“简介”标题。聊天中修改文案后同步更新这个文件；交付时链接该定稿文件，不只把文案留在聊天或制作目录根部。备选标题与讨论草稿另存，不混入最终发布文案。

为节省其他模型的上下文，优先读取 `plan.json`、`workflow-status.json`、`verification.json`。不要把原始房间文件、完整时间轴和音频元数据全部打印进上下文。发布和上传不是默认制作步骤。
