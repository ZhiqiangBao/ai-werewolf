# 狼人杀对局视频

本流程供不同 AI agent 和真人制作者使用，不要求具备某个 agent 的专属工具。使用目标仓库里的确定性程序完成机械步骤；制作者负责备料、审核声音、选择节点，以及制作封面与发布文案。完整上帝视角可润色开场、点评和收尾；单玩家视角只重建指定席位实际可见的历史，具体权限、身份与审核边界见[单玩家视角制作](references/player-view.md)。涉及生图等外部能力时，提供可复制的输入材料和人工操作方法，具体 agent 的内置工具仅作可选实现。默认制作完整上帝视角对局；用户要求样品时只制作样品。

## 先定位，再运行

目标是 `package.json` 名为 `ai-werewolf` 的游戏仓库。程序位于 `scripts/video/`，依赖由项目锁文件维护。命令在仓库根目录执行：

```powershell
pnpm video:make --room=latest --prepare-only
```

`latest` 只从默认 `data/rooms` 选择已结束对局，不扫描界面测试目录。指定另一数据目录用 `--data-dir=绝对路径`；指定房间用 `--room=ID`。

## 从准备材料到启动整片

把命令中的 `ROOM_ID` 换成准备阶段输出的实际房间号，后续固定用它。首次制作或修改材料先读 [制作前材料清单](references/preproduction.md)。上帝视角再读 [上帝解说写作步骤与模板](references/commentary.md)；单玩家视角须加 `--player-seat=N` 并按 [单玩家视角制作](references/player-view.md) 操作。两种视角不能混用素材或审核记录。按下表执行，AI agent 和真人使用相同的文件与检查标准：

| 顺序 | 操作 | 完成标志 |
| --- | --- | --- |
| 1. 生成材料 | 上面的 `--prepare-only` 命令 | 本局目录有 `plan.json`、`editorial-context.json`、`narration.json`、`voices.json`；此时旁白通常是未审核模板 |
| 2. 编辑与审核 | 阅读当前视角可见的事实与完整授权原话；上帝视角写开场、点评、收尾，单玩家视角只核对授权原话并保持空 `edits`；核对声线 | 完成相应视角的实际核对后在 `narration.json` 记录 `review`；原话与事实保持完整 |
| 3. 检查是否可启动 | 下面的 `--check-only` 命令 | `output/materials-check.json` 中 `ready: true`；此步不调用 TTS |
| 4. 制作整片 | 检查通过后执行 `--resume` | 配音、波形检查、时间轴、渲染与视频验证完成；然后完成封面、文案和视听验收 |

```powershell
pnpm video:make --room=ROOM_ID --check-only --encoder=cpu
```

检查通过且 TTS 服务与外发范围已有授权后启动：

```powershell
pnpm video:make --room=ROOM_ID --resume
```

这一条依次完成导出、材料准备、配音前材料检查、TTS、波形检查、独立 ASR 原话核对、字幕时间检查、音频时间轴、直接小体积渲染、预览和检查。默认中文、英语使用已配置的本地 ASR，日语只使用 Qwen Token Plan 在线 ASR；本地服务在需要时自动复用或启动，模型须已安装。ASR 不接收原稿提示，不改写玩家原话；有差异时停在 `output/asr-review/report.json`，核对明确的专名别名后可复用识别缓存续跑。配置、服务选项及恢复步骤见 [本地与在线音频核对](references/local-asr.md)。**首次直接启动也会在材料检查处拦住未审核模板；它不会自动创作完整上帝解说。** `review` 是制作者真实核对的记录，程序检查格式、锚点、音色与原话，表达质量仍需按写作步骤审核。原话/法官取舍见 [剪辑规则](references/editing.md)。

上帝视角检测到破音时停止在检查点；已授权的范围内加 `--repair-audio` 可自动重配异常片段并复查。该选项不支持单玩家视角。第一遍编码就限制码率，最终只拼接视频并编码主音轨，不先生成大母版再压缩。已成功的音频与视频片段自动复用。没有 pnpm，或 PowerShell 的 pnpm 启动器不能运行时，可直接运行同一个入口：

```powershell
node node_modules/tsx/dist/cli.mjs scripts/video/workflow.ts --room=ROOM_ID --resume
```

其他 agent 可用本技能的 `scripts/run.mjs --project=仓库绝对路径` 启动同一程序。如果目标仓库缺少制作程序，使用 `scripts/bootstrap.mjs --project=仓库绝对路径` 安装随技能附带的程序和美术资源，并补齐缺失的依赖声明与启动命令；已有实现保持原样。随后用项目包管理器安装依赖。游戏导出模块、ASR 客户端与本地服务仍来自目标游戏仓库；缺少当前玩家导出或 ASR 能力时，bootstrap 会在安装前停止，先更新游戏仓库。技能包不附带模型权重或凭据。

## 必须保持的约束

- 从真实事实流恢复身份、存活、警徽、票型与昼夜；不要从自然语言或模型思考猜动作，不提前显示后续结果。
- 玩家台词只来自真实提交的 `speak`/密谈原话；动作配音只口述查验、药物、守护、方向等工具的真实选择。不得改写分析、补充理由或虚构回答。上帝视角完整模式保留全部原话与顺序；单玩家视角只保留该席位有权看到的历史事件与原话，含其获准接收的查验结果和密谈，其他席位身份始终显示未知；样品精确保留所选原话。
- 系统超时/托管产生的话语标“系统托管”，不冒充模型原创。`integrity.ts` 在 TTS 前核对原话、朗读文本和动作来源，不能绕过检查来合成修改后的玩家发言。
- 保留必要主持链：夜间询问→真实选择→确认/闭眼；警长询问→真实的起点/方向选择→直接进入发言（视频不重复报）；无警长或警上阶段只报起点和方向，不逐个念全桌号码；投票邀请→结果播报。游戏事实记录仍完整保留。
- 法官与上帝点评分声线、分标签；点评用 `after` 接在事实之后，不覆盖必需播报。行动选择转述须标明来自记录，不能冒充玩家原话。
- 一位玩家固定一个声音，法官、解说分别固定声音。依据昵称、人设与人物图核对声线，不给全桌同一音色。
- 上帝视角右栏展示本局全部身份的技能，长内容连续循环滚动，不固定展示某一个身份；单玩家视角只展示本人身份与简介，其他座位保持未知。授权的查验或密谈原话仍按历史顺序保留，但不能用终局 `review`、`knownIdentities` 或后来获知的信息回填此前身份。票型框按行数收紧，投票人号码和票数清楚。
- 上帝视角底栏按本局 cast 显示头像、编号、身份与昵称；单玩家视角只显示本人真实身份，其他座位标“身份未知”。法官使用法槌徽记，上帝解说使用眼睛与星芒徽记，各有固定标签与声线。字幕在右侧独立文字区垂直居中；保留“行动转述／系统托管”等来源标记。画面细则见 [制作前准备](references/preproduction.md) 与 [单玩家视角制作](references/player-view.md)。
- 使用实际 WAV 样本数与服务商真实时间戳、核实后的独立 ASR 词边界或强制对齐。连续近似均分的词时会被拦截，不估算阅读时长冒充正式时间轴。英语、日语可从同次 Qwen ASR 响应核实原文映射后生成对齐 sidecar；这属于独立转写时间映射，不称作强制对齐。当前中文外部对齐尚不支持，缺少可靠字时就停止。
- 字幕文字以已确认的朗读稿为准，服务商时间戳标签只用于定位；必须核对字幕与原稿，不能把标签里的同音错字直接烧进视频。字词漏增或无法可靠对应时做真实对齐。
- TTS 后检查原始波形，不能只看平均音量或归一化后的峰值。使用自动工具定位异常、有限次重配并复查；正常片段保持缓存。排查破音、使用独立工具或维护检测规则时读 [配音质量检查与定点修复](references/audio-quality.md)。
- `--player-seat=N` 已支持单玩家视角，并在导出时按席位权限过滤；它与含私密夜间信息的上帝视角是不同产物，不能复用全知素材。完整限制和验收要求见 [单玩家视角制作](references/player-view.md)。
- 单玩家视角当前不支持 `--repair-audio` 自动定点重配；需要修复时保留现有项目和产物，在新的项目目录重新制作。不要将上帝视角修复流程用于玩家版。
- Qwen 仅用已获准的 Token Plan 凭据；程序在内存读取密钥，产物不包含密钥或房间令牌。鉴权、额度或限流失败时保留检查点并报告，不切换付费线路。

## 可调选项

- `--encoder=cpu`：无需独立显卡；`auto` 自动尝试 NVIDIA 编码并允许软件回退；`gpu` 要求实际使用 NVENC，失败就停，不隐瞒回退。
- `--project-dir=绝对路径`：独立版本目录，保留旧片；不要把样品和完整视频混在同一目录。
- `--video-kbps=750 --max-video-kbps=1200 --audio-kbps=96`：直接限制分段和整片码率，1080p/30fps；先试做昼夜片段再据清晰度调整。
- `--theme=campus|storybook|gufeng|fantasy|urban|future`：六套人物；更换后核对声音与人物是否相符。
- `--video-locale=zh-CN|en|ja`：覆盖画面标签语言；也可设置环境变量 `VIDEO_LOCALE`。未覆盖时优先使用原局语言，旧记录缺失语言时使用 `zh-CN`。其他语言或方言可通过 `scripts/video/video-locale.ts` 的注册表扩展，并在制作进程中加载。
- `--voices=绝对路径`、`--narration=绝对路径`：显式使用已整理的配置。
- `--tts-provider=ID --tts-adapter=文件路径`：显式接入其他 TTS；内置仍为 `qwen-token-plan`，不自动换服务或计费线路。
- `--asr-provider=auto|local|qwen-token-plan|mimo-token-plan|off`：默认 `auto`，中文/英语走本地，日语走 Qwen；日语显式 local/MiMo 会被拒绝。`off` 明确记录语义核对未执行，字幕时间检查仍执行。准备和材料检查阶段不启动本地 ASR。
- `--asr-aliases=JSON文件`：按片段 ID 记录已经核对的专名或字形映射；差异未解决前不生成正式时间轴。原音频和识别参数未变时复用识别结果。
- `--alignment-provider=qwen-token-plan`：本地/MiMo 识别通过但原字幕字时不可靠时，明确允许额外 Qwen 请求补充英语词边界。日语默认 Qwen 可复用同次响应；中文当前需另行提供可靠字时。没有该选项就停在 `alignment-required`，不悄悄改用在线服务。
- `--repair-audio`：仅上帝视角在波形检测失败时重配异常片段，保留原文、固定声线与成功缓存，最多尝试三次；当前自动重配支持 Qwen Token Plan。单玩家视角不支持此选项。
- `--check-only`：导出并刷新材料，执行配音前检查后停止，不调用 TTS 或渲染；缺项写入 `output/materials-check.json`。
- `--through=plan|preflight|tts|audit-audio|review-audio|timeline|render|preview|verify`：停在完整的阶段检查点；旧文件再压缩是独立工具，不在默认流程中。

画面语言覆盖只改变程序绘制的标签，不翻译历史玩家原话、音频或本局规则正文。规则正文与画面语言不同时，画面标明正文原语言；没有本局对应条款时标明中文默认身份简介。上帝／玩家视角由 `--player-seat` 和权限投影决定，不能把画面语言切换当作权限过滤。

默认单路编码；显存与性能判断读 [硬件说明](references/hardware.md)。批量配音、Qwen 特例和接入其他服务时，读 [批量 TTS 与适配器修改](references/tts-batch.md)，其中逐项说明改哪些文件、输出什么、怎么配置和验证。维护程序或适配新日志读 [程序设计](references/automation.md)；小体积交付见 [压缩方案](references/compression.md)。

英、日真实 TTS 的实际服务、用户反馈、日语 instruction 问题和修正样片范围见 [真实配音样品记录](references/real-tts-samples.md)。独立转写和时间检查不代替声线身份或听感审核，不把样品验收扩大为全局视频验收。

## 制作封面

完整上帝视角对局默认制作一张带个性化短标题的封面。先按 [封面制作](references/cover.md) 的通用模板写好完整提示词，整理当前人物图集与画面参考，保存为本局的 `output/cover-prompt.md`；再通过可用的 AI 文生图／参考图生图工具生成，由 agent 调用或真人在生图产品中粘贴提示词、上传参考图均可。检查人物、文字与缩略图可读性后，将封面保存为 `output/cover.png`，在制作记录中补上工具和实际尺寸。续作时复用已确认的封面；修改版保留旧图。单玩家视角不得使用含其他身份、密谈或终局信息的上帝视角封面。

`video:make` 不会自动调用生图服务。没有内置生图工具的 agent 仍可交接完整提示词和参考素材，按通用操作步骤生成后导入检查。Codex 使用内置生图的可选方法另列在封面参考文档中。视频程序验证通过后仍需检查封面和发布文案是否齐全；用户只要求样品时按样品范围制作。

## 验收和交付

以 `output/verification.json` 为程序检查结果。上帝视角同时查看 `output/review/` 的夜间、玩家发言、票型与终局帧，试听至少一个玩家和一个上帝片段；玩家视角只检查授权可见事件、对应玩家与法官片段，确认身份标签始终只揭示本人。两种视角都检查底栏昵称、两位数编号、行动来源标记和法官切换；字幕应居于右侧文字区中部，不能压住头像与身份。文字、号码和标签应清楚，状态不能遮住人物。

完整上帝视角默认交付直接编码得到的 `output/latest-match.mp4` 小体积整片、`output/cover.png` 封面与 `output/publish-copy.md` 发布文案，并提供这些文件的链接；封面缺失时补齐后再宣布整片交付完成。单玩家视角只交付该席位授权范围内的产物，不复制上帝视角封面或全桌文案。核对 `render-report.json`、`gpu-metrics.json` 和 `verification.json` 的实际编码器、大小与时长，不把短片比例当作整片实测。可附预览、字幕和时间轴，说明是否节选。样品使用独立目录和 `sample-verification.json`，不覆盖原整局。

最终标题与简介保存为对应制作目录的 `output/publish-copy.md`，与成片放在一起，分别使用“标题”“简介”标题。聊天中修改文案后同步更新这个文件；交付时链接该定稿文件，不只把文案留在聊天或制作目录根部。备选标题与讨论草稿另存，不混入最终发布文案。

完整上帝视角简介默认包含逐席表（座位、昵称、实际配置的模型标识或“真人”）及本局完整规则卡。真人席位即使留有模型字段也标真人；不输出密钥、端点或邀请凭证。只在完整上帝视角使用 `video:publish-copy` 从本局存档和 `script.ruleCard` 同步这两部分，保留已定稿的标题和介绍文字；准备和整片验证阶段也会自动更新已有文案文件。单玩家视角不能沿用这类全桌文案，须遵守 [单玩家视角制作](references/player-view.md) 的隐私限制。

为节省其他模型的上下文，优先读取 `plan.json`、`workflow-status.json`、`verification.json`。不要把原始房间文件、完整时间轴和音频元数据全部打印进上下文。发布和上传不是默认制作步骤。
