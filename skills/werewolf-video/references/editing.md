# 剧本：哪些发言值得进入视频

制作前选节点和润色的逐步做法见 [制作前准备](preproduction.md)，本文件说明剪辑约束。

## 完整局的默认规则

程序先导出真实记录，再生成可编辑 `narration.json`。不要重新让模型模拟一局，也不要让模型重写整桌玩家对白。

玩家公开发言、遗言和狼队密谈按 `sourceSeq` 原顺序保留。单次发言超过约 230 字时按句号、逗号分段，保持同一声音和同一事件编号。拆分后的文字必须能还原原文；段间只加短停顿，不插长法官话打断推理。

同一玩家一轮内的完整发言连续播放。说话者切换时点亮新座位；遗言发生在实际出局以后，头像可以同时显示“出局”和“发言中”。不要把别人的怀疑当作事实修改身份。

## 法官取舍表

| 记录 | 配音策略 | 画面策略 |
| --- | --- | --- |
| 板型/开局 | 一两句交代玩法与上帝视角 | 显示完整身份桌面 |
| 天黑/天亮 | 一句章节转场 | 切换对应原画 |
| 守护/查验/解药/毒药/刀口 | 保留叫醒、询问、选择、确认和闭眼；不是只报结果 | 点亮真实目标；转述选择标明来自行动记录 |
| 女巫先得知刀口、然后用药 | 保留刀口询问与用药确认；解药用完之后不得再报刀口 | 只显示该条记录实际授权的信息 |
| 上警 | 读上警名单即可 | 上警/退水分别标记 |
| 发言顺序 | 法官先问警长，转述真实起点/方向后直接进入发言，视频里不再重复；无警长及警上阶段只报起点和方向，不念全桌名单 | 真实顺序保留在事实中；选择回答标注行动转述 |
| 投票 | 法官先邀请投票，再报票数与结论；可用 `after` 独立添加点评 | 邀请阶段不得提前显示票型、出局或新警徽 |
| 出局/平安夜 | 清晰报结果 | 在对应事件更新存活状态 |
| 警徽移交/撕毁 | 必须交代 | 警徽归属同步变化 |
| 终局复盘 | 几个关键因果，避免重念整局 | 身份、存活和胜负结果 |
| 网络等待、Agent问话、重复诊断 | 不配音 | 不占用节目时间 |

模板由 `narration.ts` 产生，主持链由 `hosting.ts` 保证。未知事件保留原播报，不能为“精简”删掉关键动作。编辑原因写入 `reason`；点评附加在事实之后的 `after`。

## 上帝解说的写法

把法官和陪看解说分成两个 `voiceKey`。法官明确、短；解说口语化，转折处可有一点兴趣或轻微幽默。不要每个玩家发言后点评，也不要长篇替观众下结论。

公开 B 站 [夜间主持与警长流程示例](https://www.bilibili.com/opus/1155123079100235777)包含睁眼/选择/闭眼及警长选择方向的衔接；本次核对的是公开文字内容，不声称观看了无法访问的视频。借鉴主持结构，实际行动顺序仍以本项目规则和记录为准，不照搬示例板型。

值得插话的节点：狼拿警徽、真预言家被放逐、女巫毒中狼、警徽在狼队间流转、守卫守中狼刀、残局人数变化。依据已经发生的结构化结果写一两句，通常 3–10 秒即可。

例：一号确实把警徽交给狼队友四号以后，可以说“警徽给了四号。人走了，队友还接着带队。”这是一句基于事实的观察。不能编造“一号早就计划好用警徽骗守卫”，除非记录明确支持该计划。

参考十月枫林尽染的[这期上帝视角](https://www.bilibili.com/video/BV1JGZcBjEBL/)时，抽看的实际画面/内嵌字幕显示：短行动播报、玩家长发言、针对当前局势的简短点评、箭头定位玩家。借鉴的是衔接和节奏；不要声称掌握作者未公开的工程或 TTS 型号，不复制其台词与声线。

## 声音表

12 位人物、法官、上帝解说各固定音色。优先用提供方已验证的系统/基础音色，不通过变速同一声音伪装成全桌不同人物。

看 `plan.json` 中的昵称、风格、人设和默认发音指令。按用户设定调整声线、表达方式和语速；同一座位跨昼夜保持一致。示例人格可写成“年轻、冷静、咬字干净、逻辑清楚、语气克制”；避免只写“自然好听”。使用普通话或用户指定语言，不模仿真人演员。

## 精华版的扩展边界

当前自动程序交付完整玩家发言。若用户要求短版，另存选择表，记录每一节选的 `sourceSeq`、原文起止范围、选择原因；保留身份跳出、关键质疑、回应、归票、投票、遗言和夜间计划的因果链。重复附和可省，关键反驳不能只留结论。

增加短版程序时，让验证器核对“被选原文范围”的精确匹配与顺序；不能继续声称“全部原话保留”。预览节选也要标明非连续片段，避免被误认为完整时间线。
