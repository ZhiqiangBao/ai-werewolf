# 封面制作：短标题、人物与交付

完整对局默认交付带个性化短标题的横版封面。封面与标题简介同属制作流程，由使用 skill 的模型完成；离线 `video:make` 没有图像生成接口。

## 从本局选择画面

先读 `plan.cast` 和已经审核的剧情节点，确定最值得呈现的真实冲突、对应人物与身份。真人参局的宣传点须按座位控制方式核对；角色插画只代表游戏席位。封面可以采用带情绪的宣传文案，不能把新编文字标成玩家原话，也不能虚构对局结果。

查看当前主题人物图集，记录具体行列或人物裁图；同时查看一张本局画面抽帧作为颜色与世界风格参考。提示词分别说明人物参考和场景参考的用途，保留发色、眼镜、辫子、服饰等辨识特征。选择一到两位主要人物通常更适合手机缩略图，构图可重新绘制。

封面短标题可独立于 `publish-copy.md` 的完整标题，用一到两行突出看点；结合本局情绪选择手写、漫画笔刷等个性化字体，明确给出逐字文案。人物脸部、核心道具和标题要有清楚层次。默认接近 16:9 的横版构图，重要文字留出安全边距；用户指定平台尺寸时以其要求为准。

## 生成与检查

使用会话可用的图像生成工具；有 `imagegen` skill 时按其流程操作。传入已查看的本局人物与场景参考，要求简体中文正确、标题在小图中醒目。沿用用户已授权的服务范围；续作优先复用已确认封面，工具不可用时如实说明未完成的封面项。

打开生成结果检查：

- 文案逐字正确，字体虽有个性仍容易辨认，缩到手机缩略图大小后主标题清楚。
- 角色外观和实际身份对应，真人／AI标签与本局记录一致。
- 人脸、手部、道具完整，标题不挡表情，边缘文字不易被裁切。
- 构图、颜色和成片主题相符，检查实际像素尺寸，不把提示词中的目标尺寸写成实测结果。

发现问题时修改原图或提示词生成新版，并保留已有版本。首次完整封面可直接作为样品展示，用户未要求单独确认时按授权继续完成其余交付。

## 保存与交付

将选定图片复制到**本局制作目录**的 `output/cover.png`，保留生成工具的原始文件。保存 `output/cover-prompt.md`，记录最终短标题、最终提示词、参考素材路径或人物位置、使用的生成工具和实际尺寸。已有 `cover.png` 需要替换时先保留旧版。

最终核对同一 `output` 中的成片、封面、`publish-copy.md` 和封面制作记录，展示或链接成品封面。视频验证报告只证明其实际执行的检查；封面仍需上述视觉核对。具体房间的图片、真实对局材料和制作缓存留在忽略的数据目录，GitHub 技能包只包含通用流程与工具。
