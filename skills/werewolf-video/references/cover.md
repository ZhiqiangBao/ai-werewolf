# 封面制作：短标题、人物与交付

按每个交付版本、画幅和授权视角制作带个性化短标题的封面。本流程可由任意 AI agent 或真人执行：整理素材 → 写好提示词 → 使用 AI 生图工具 → 核对 → 保存交付。先完成可复制的输入材料；生图可由 agent 调用工具，也可由真人在生图产品中操作。离线 `video:make` 负责视频流水线，封面按以下步骤单独完成。

## 从本局选择画面

先读该版本获授权的事实与已经审核的剧情节点，确定实际出现且值得呈现的真实冲突、对应人物及该视角可公开的信息。真人参局的宣传点须按座位控制方式核对；角色插画只代表游戏席位。封面可以采用带情绪的宣传文案，不能把新编文字标成玩家原话，也不能虚构对局结果。

读取本局 `art-manifest.json`，按所选席位查看其实际图集路径、行列、外貌和声线，并从对应图集裁取人物参考；行列从左上角开始，按四列三行排列。同时查看一张本局画面抽帧作为颜色与世界风格参考。提示词分别说明人物参考和场景参考的用途，保留发色、眼镜、辫子、服饰等辨识特征。选择一到两位主要人物通常更适合手机缩略图，构图可重新绘制。

封面短标题可独立于 `publish-copy.md` 的完整标题，用一到两行突出看点；结合本局情绪选择手写、漫画笔刷等个性化字体，明确给出逐字文案。人物脸部、核心道具和标题要有清楚层次。依发布平台与本版画幅安排横竖构图，重要文字留出安全边距。

## 先写好可复制的生图提示词

在本局制作目录的 `本版素材目录的 cover-prompt.md` 写入完整提示词和参考图片清单，任何人都能据此继续制作。用本局实际内容填完下面的模板，最终记录中不保留待填项：

```text
用途：狼人杀对局视频封面，按本版发布画幅构图，适合手机缩略图观看。
本版真实看点：[用一两句说明当前视角允许公开的冲突与结果]。
整体风格：[当前人物图集与成片的风格、色调、背景主题]。

参考图 A：[人物图集或裁图文件名]。
使用其中[第几行第几列]的[人物一]：[发色、眼镜、服饰等关键特征]；
使用其中[第几行第几列]的[人物二]：[关键特征]。
保留人物辨识特征，重新绘制适合封面的动作与表情。
参考图 B：[本局画面抽帧文件名]，用于场景和颜色参考。

构图：[人物左右位置、表情、代表本局冲突的道具、背景]。
人脸清楚，人物和标题层次分明，重要元素与画面边缘留有余量。

画面中文字必须逐字写为：
第一行：[简短标题上句]
第二行：[简短标题下句；如只需一行则删除此项]
小标签：[已核对的真人／AI等宣传标签；不需要则删除此项]
字体：[与剧情气氛相符的手写／漫画笔刷等个性化字体]，
大字、强对比、清楚描边，缩小后仍可辨认；文字避开人物脸部。
仅包含以上文字，不添加游戏界面、字幕框、额外标语或水印。
```

提示词内的文件名须对应实际可上传的图片；同时在记录中列出本机路径和人物行列，交给其他人时附上这些文件。只交一段依赖上一段聊天的描述，无法保证他人复现相近画面。

## 使用 AI 生图工具生成

选择当前可用且在授权范围内的 AI 文生图工具。支持参考图的工具更容易保持本局人物一致：

1. 新建横版图片任务，设置约 16:9 的比例；平台有封面尺寸要求时使用其指定尺寸。
2. 复制已填写完整的提示词，上传清单中的人物与场景参考图；按实际工具说明配置参考用途。
3. 生成后下载原图，按下一节检查；有问题时保留旧版，调整具体有误的文字、人物或构图后再生成。

开始前，agent 确认当前会话是否有已授权的生图工具。如果有，就用 `本版素材目录的 cover-prompt.md` 和清单里的参考图生成；如果没有，不要把视频流水线成功当作封面完成，也不要自行切换到未授权的网页或计费服务。将完整提示词文件及每张参考图的实际路径交给用户或已有的授权生图操作者，等待对方返回生成图片；收到后保存为 `本版素材目录的 cover.png`，按下节核对并继续交付。真人可在生图产品网页或应用中执行同样步骤。通用流程不依赖特定 agent 工具或接口。

若工具仅支持纯文生图，在提示词中完整描述人物外观并逐项对照参考图。短标题必须与画面一起由生图模型绘制；文字不准确时修改提示词重新生成，直到可用。不要采用无字留白再后期贴字的路线。

## 检查生成结果

打开生成结果检查：

- 文案逐字正确，字体虽有个性仍容易辨认，缩到手机缩略图大小后主标题清楚。
- 角色外观及可公开的身份与本版视角一致，真人／AI标签与本局记录一致。
- 人脸、手部、道具完整，标题不挡表情，边缘文字不易被裁切。
- 构图、颜色和成片主题相符，检查实际像素尺寸，不把提示词中的目标尺寸写成实测结果。

首次完整封面可直接作为样品展示，用户未要求单独确认时按授权继续完成其余交付。

## 保存与交付

将选定图片保存或导出为 PNG，放到**本局制作目录**的 `本版素材目录的 cover.png`，保留生成工具的原始文件。在已写好的 `本版素材目录的 cover-prompt.md` 中补全最终短标题、最终提示词、参考素材路径与人物位置、使用的生成工具、实际尺寸，以及实际提交的含定稿短标题的提示词。已有 `cover.png` 需要替换时先保留旧版。

最终核对同一 `output` 中的成片、封面、`publish-copy.md` 和封面制作记录，展示或链接成品封面。视频验证报告只证明其实际执行的检查；封面仍需上述视觉核对。具体房间的图片、真实对局材料和制作缓存留在忽略的数据目录，GitHub 技能包只包含通用流程与工具。

## 可选方式：Codex 内置生图

Codex 会话提供内置图像生成能力时，可使用该能力执行上面的生成步骤；若同时提供 `imagegen` skill，先阅读它的工具使用说明。查看人物和场景参考图后，将同一份完整提示词及参考图传入生成工具，生成后把原图复制到 `本版素材目录的 cover.png`，按通用标准检查并补全制作记录。

此节仅说明一种可选工具接法。其他 agent 和真人直接使用前面的通用流程，无需安装 Codex 或具备其内置工具。

## 逐版材料绑定

每版选择该版实际可见的真实看点，并据此撰写发布标题和封面短标题；核对标题、人物和结果与该版事实一致。提交生图时使用包含定稿短标题的完整提示词，保存实际提交内容和最终 PNG。

每版在 `publication-draft.json` 记录 `{ "highlight": { "sourceSeqs": [本版可见来源序号], "description": "真实看点" }, "coverTitle": "定稿短题", "submittedPrompt": "实际提交的完整生图提示词" }`。将该版授权且实际出现的来源序号写为 JSON 数组文件；不能用整局序号代替短版，也不能用上帝视角材料代替玩家视角。定稿保存在 `publish-copy.md`，生成图保存为 `cover.png`。实际审核事实、文案、已提交提示词和生成图片之后执行：

```powershell
node --import tsx scripts/video/publication-materials.ts --record --materials-dir=本版目录 --room=房间号 --version=版本名 --visible=本版来源序号.json --reviewed-by=实际复核者
```

程序自动写入绑定当前文案、提示词和图片的 `publication.json`，不修改作者正文；修改任一材料后须重新审核登记。程序会拒绝纯类型套语标题和明确要求无字画面的提示词。制作者仍需核对本局看点、实际提交的任务和最终图中的每个字。实际输出的文字与当前版视角一致；竖屏画面无需添加固定“节选”标签。
