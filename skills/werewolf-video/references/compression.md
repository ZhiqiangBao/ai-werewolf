# 压缩：先保证文字清楚

这类视频只有头像、字幕、状态和声波在变化。先保留 1920×1080 与 30fps，调整编码质量、预设和关键帧间隔，再考虑降低分辨率。

## 默认推荐

H.264 + AAC 兼容性优先。程序已提供独立分享版：

```powershell
pnpm video:compress --crf=27
```

默认保留母版，输出 `output/latest-match-share.mp4`。使用 `libx264 medium`、静态画面调优、CRF 27、8 秒关键帧间隔、AAC 96kbps。CRF 越大体积通常越小；先试 26–28，观察细字、金色边线、头像与夜景暗部，再决定。

快速检查而不等整局：

```powershell
pnpm video:compress --seconds=12 --crf=27 --output=data/video/ROOM/output/compression-test.mp4
```

`--input` 可指定源文件。正式版本不要传 `--seconds`。压缩程序写临时文件，成功后重命名，并保存时长、大小和编码信息。

## 大小怎么算

质量模式不会保证固定体积。若采用平均视频码率 0.8–1.2Mbps、音频 96kbps，43分13秒的视频约为 **290–420MB**（十进制、少量容器开销另计）：

`大小 ≈ 时长秒 × (视频码率 + 音频码率) ÷ 8`

这是码率预算，不是保证同等画质的实测结果。需要硬性大小上限时用两遍平均码率编码，并先测文字可读性；不应把一次短片压缩比例直接套到整局。

## 其他选择

- HEVC / AV1 可作为进一步缩小体积的候选；先确认观看设备、播放器、剪辑软件支持，再做同画面的比较。
- 720p 可以作为手机小文件版；号码、身份和昵称会变小，需要另做版式或实际检查。
- 对以发言为主的节目，AAC 80–96kbps 可先试；需要音乐和更多音效时重新评估。母版保留更高质量音轨。
- `faststart` 有助于文件开始播放，不会显著缩小体积。

参数含义与可用编码器以 [FFmpeg 编码文档](https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb)为准。首版压缩程序只自动实现并验证 H.264 路径；更换编解码器应补充实际播放测试。
