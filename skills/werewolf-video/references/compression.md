# 上传画质与体积控制

完整片、高光、精华和样片默认使用 `compact`，视频平均上限 750 kbps、编码器最大码率参数 1200 kbps，AAC 96 kbps。显式指定 `--encoding-profile=upload` 才使用 upload；其他显式码率参数覆盖配置默认值。同一任务的各交付版本和断点续作应使用相同参数。

`--video-kbps` 设置视频轨平均码率上限，`--max-video-kbps` 设置编码器最大码率参数，`--audio-kbps` 设置 AAC 目标，`--max-total-kbps` 可选设置最终文件总平均码率上限。`upload` 的默认值分别为 8000、12000 和 96 kbps；编码参数发生变化时缓存失效，已有配音可复用。

编码器根据视频和可选总码率预算设置较小的 VBV 缓冲，并为码率留少量余量；平均码率以最终成片的实测为准。`--video-quality` 控制 NVENC 的 CQ 或 CPU 的 CRF（质量值减 2），最终码率仍受 VBV 约束。内容简单时码率可能低于上限，画质和体积会随画面复杂度变化。

最终 MP4 使用 FFprobe 测量视频轨平均码率，并按照视频包解码时间计算任意连续两秒窗口内的视频包字节数，除以窗口长度得到峰值；窗口可以跨片段边界。片长小于两秒时窗口长度取视频轨实际时长，并用该时长作除数。最终文件的视频平均超限会报错；峰值如实报告，不作为失败条件。报告另记录 MP4 实际字节数、实际总平均码率和时长；总码率包含音频与容器开销，不等于视频码率；设置总码率上限时也会检查该上限，未设置时只报告。高峰可能高于平均值，视频加音频目标不能当作文件大小保证。

## 画面转场与清晰度检查

昼夜切换和同一场景内的人物切换使用硬切。开场、终局及其他章节边界使用 4 帧淡出、4 帧淡入。昼夜硬切沿用本版的码率设置。逐段编码参数一致时，最终拼接继续复制视频流。

进入整局渲染前，先用样品检查代表性白天、夜间、人物切换和 phase/chapter 边界。对每类切换点抽取切点前后的连续帧，暂停逐帧查看小字、细线、头像和边缘是否清楚；只看场景中间的静态帧不足以检查转场。整局成片也要按相同方式抽查关键切换点，并完整播放。

从 `timeline.json` 或选段边界取准确切点秒数，以下示例在切点前后连续导出 12 帧（30fps 下约 0.4 秒），再按文件序号逐张检查：

```powershell
$boundarySeconds = 360.0 # 替换成实际 phase/chapter 或人物切换时间
$startSeconds = [Math]::Max(0, $boundarySeconds - 0.2)
New-Item -ItemType Directory -Force -Path review-cuts | Out-Null
ffmpeg -ss $startSeconds -i output/latest-match.mp4 -frames:v 12 -fps_mode passthrough review-cuts/cut-%03d.png
```

对文字、票源号码和细边缘，在画面暂停状态下放大确认；只有静态中间帧清楚，不能代表切换前后每帧清楚。

## 历史 compact 实测

2026-11-01 的 46 分 04 秒对局使用当时的原生小体积配置：1080p/30fps、158 段全部 NVENC，直接导出 262,076,815 字节（约 262MB），实际平均总码率 758.4 kbps。较旧版 944,392,555 字节减少约 72.2%，51 条玩家原话完整保留。这是旧 compact 配置的历史实测，只说明该局结果，不代表当前实现或其他对局的结果。

## 实际验证与记录

先生成真实时间轴，再用 `render.ts --only=片段ID` 试做，保持同一项目环境、声音和字幕文件。不同参数比较使用独立导出目录。配置和底图变更后不要复用旧成片来判断效果；`render.ts --plates-only` 只能看静态排版，不能证明编码、转场或细字在视频中清楚。

- `encoding-settings.json`：采用的配置和第一遍编码参数。
- `segments/*.mp4.json`：逐段实际编码器、大小和耗时；强制显卡模式必须全部为 `h264_nvenc`。
- `output/render-report.json`：整片大小、耗时、配置是否从第一遍生效、最终拼接是否重新编码视频。
- `gpu-metrics.json`：整卡显存与编码器利用率采样，包含其他程序，不能冒充进程独占显存。
- `output/verification.json`：实际帧数、音画时长、原话完整性、章节和实际平均总码率。

## 仅对用户指定的旧文件压缩

`compress.ts` 仅在用户明确要求压缩已有文件时使用，并输出到新路径：

```powershell
pnpm video:compress --input=已有视频路径 --crf=28 --output=新文件路径
```

它使用 libx264 medium 与静态画面调优；默认读取项目 `encoding-request.json`，显式环境变量和命令行参数优先。`--crf` 优先于质量设置，`--seconds` 与 `--start` 可选截取；最终文件也要通过视频平均及可选总平均码率校验，峰值仅供报告。它无法恢复源图细节，也不更新旁白、规则卡或画面规范。删除房间号页脚、修复模糊或调整转场时，修改源画面后用新导出目录重渲染，并复用已核验的音频；不要对已编码整片套 `delogo` 或再压缩。
