# 制作执行者与程序边界

本参考只用于维护技能和排查流程，不是首次制作的操作步骤。

制作执行者是接手任务并读取本技能的执行者。它可以是 Codex、Cursor、Claude Code、Copilot、Gemini CLI、Qwen Code 或人工制作者。用户提供制作目标、授权、偏好和需要主观确认的结果。

视频工作流程序包括 `scripts/video/workflow.ts`、`prepare.ts`、`synthesize.ts`、`audit-audio.ts`、`timeline.ts`、`render.ts`、`verify.ts`，以及它们调用的 FFmpeg 和 TTS 服务。程序负责导出事实、建立清单、执行已批准的分段、维护缓存身份、审计音频、生成字幕、渲染画面、恢复阶段和输出报告。

制作执行者需要决定并写入材料的内容包括视角、版本、语言、主题、TTS 模型、ASR 路由、编码配置、叙事内容、声线策略、外发范围、封面文案和主观听感。程序遇到这些决定缺失时，应报告具体字段并停在对应阶段。

程序可从房间和稿件派生的机械内容包括事实、规则卡、座位表、玩家原话索引、分段边界候选、缓存键、词索引、时间轴、字幕、帧数、哈希、渲染片段和交付校验。制作执行者不需要重复计算这些内容。

程序不得替制作执行者决定叙事取舍、视角权限、声线风格、ASR 路由、外发范围、封面文案或听感结论。主题、立绘、声线、模型、端点、音频和时间轴必须绑定到同一个项目身份，任何绑定变化都应产生新的检查点或明确要求重新准备。

维护或扩展 TTS 配置时，新增模型必须同时提供模型 ID、端点、凭据环境、系统声线目录、声线性别和适用主题映射。目标模型没有对应声线时，执行者先提供已授权的参考音频和目标模型，程序调用声音创建接口并保存 voice ID、`target_model`、参考音频哈希、状态和试听结论。声音创建完成后才允许把 voice ID 写入项目声音表。

切换 TTS 模型时，执行者显式选择 `--tts-model`，程序生成新的声音绑定和项目身份。已有音频、时间轴、字幕和渲染输出只在模型、端点、声线表、脚本和缓存身份全部一致时复用。省略模型参数表示沿用当前项目配置，不触发静默迁移。
