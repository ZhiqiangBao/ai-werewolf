## 外部客户端

### BUG-AGENT-LOCALE：外部代理唤醒未明确携带对局语言

- **优先级：** P1
- **状态：** 待客户端实现与验证
- **事实依据与边界：** [外部代理接入评估](外部代理接入评估.md)记录：本机客户端当前读取座位视图但未读取或输出 `room.locale`／`projection.locale`；事件及工具说明使用固定中文包装。英文局中文输出有语言上下文缺口这一可能解释，但未检查实际私有提示和运行记录，不能将单次输出归因于唯一原因。服务端已经提供座位投影语言字段；改内置模型提示词不等于修复外部唤醒器。建议先沿用真人席位 API 加外部唤醒，不新增原生 agent 接口；若后续有多个框架统一接入需求，再另行评估。
- **验收标准：** 每次唤醒明确提供 `projection.locale ?? room.locale ?? 'zh-CN'`；英文、日文和旧房间中文默认的合成局覆盖公开发言与狼队密谈；规则和工具参数保持原样，断线、重复、过期、暂停、超时及跨席信息边界通过合成验证。实际模型是否遵循语言提示另行观察。

## 架构、运行与验证

### ARCH-OBSERVABILITY：补齐提供方延迟指标与双桌合成基线

- **优先级：** P1
- **状态：** 实施方案已形成，待排期实现与验证
- **事实依据与边界：** 现有审计**已经**记录逐请求 `firstDeltaMs`、`latencyMs`、`usage` 与 `purpose`，并有请求数、正式行动／旁听数量及总耗时统计。历史单局记录为 798 次调用（122 次行动、676 次旁听），中位数 5.210 秒、P95 16.297 秒、最大 90.017 秒；这是单次历史样本，不是当前性能基线。待补的是提供方排队时间、按提供方聚合分析和可复现的两桌以内合成负载观察；不应说现有审计没有首段响应或逐请求耗时数据。
- **实施方案：** [ARCH-OBSERVABILITY 实施方案](ARCH-OBSERVABILITY实施方案.md)（2026-11-02），基于已拆分的房间服务、三协议适配器、HTTP transport 与保存审计组件；含数据流、指标／接口草案、合成矩阵、示例报告及分阶段验收。
- **验收标准：** 合成报告按提供方聚合分层耗时、现有首段响应延迟、总延迟、token 用量及旁听／行动数，注明负载、环境与时间范围；提供方排队仅使用有可信定义的数据，否则标不可观测，不以首段延迟或差值冒充。最多两桌的基线可重复运行，能提供本地阻塞与服务端等待的分层证据；新旧审计兼容、计数与取消完整、输出白名单及采集开销验收通过。不得将模拟数据混称为真实服务表现。

### ARCH-PASSIVE：评估被动旁听策略与提供方并发预算

- **优先级：** P1
- **状态：** 建议待评估，当前策略不变
- **事实依据与边界：** 当前网络旁听按事件、按座位保留来源及上下文顺序，并等待整波请求结束后推进。此逐事件整波等待是现状约束，不代表已经采用完成即推进或跳过迟到请求的策略；不得在无明确决策下改动旁听行为、行动问话边界、原生续接或缓存策略。
- **验收标准：** 先以假服务测量候选策略和并发预算；证实每席顺序、权限、行动窗口与协议续接不被破坏。若提出运行行为变更，需单独列出决策和回归证据。

### ARCH-ABILITY：评估通用且库存独立的 Ability 实例

### ARCH-EVENT-STORE：测量事件追加与快照存储的可行性

- **优先级：** P2
- **状态：** 建议先测量，尚未决定迁移
- **事实依据与边界：** 当前状态保存会克隆和序列化整局数据，历史评估提出长局、多房间和观看者可能放大成本；尚无相应负载基线。此条要求评估事件追加与定期快照的可行性，不预设全面替换现有文件存储。
- **验收标准：** 对代表性长局测量写入、签名、恢复耗时和存储量；原型在崩溃恢复时无行动丢失或重复，并保留现有导出格式。基于数据再决定是否实施。

### ARCH-HTTP-FACTORY：评估 HTTP server factory

- **事实依据与边界：** 当前服务入口在 `main.ts` 顶层创建存储与管理器；独立启动进程使部分 HTTP 场景难以隔离测试。本项是测试和生命周期边界建议，不要求改变路由语义。

### AUDIO-LIFECYCLE：测量首音频延迟并明确取消语义与每席音色
