## 架构、运行与验证

### ACCESS-REMOTE：明确远程管理认证、凭证轮换与席位转交

- **优先级：** P2
- **状态：** 需求与威胁边界待确认
- **事实依据与边界：** 当前凭证链接持有人可代表该席行动；尚无独立账号、抢座或席位转让功能。远程部署额外需要管理认证和凭证撤销／轮换策略。本项不把单机／局域网邀请当作多租户账号系统。
- **验收标准：** 先确认管理面、玩家面与观战面的权限需求，再定义凭证轮换和席位交接规则；管理、座位、观战的 HTTP 权限、撤销、过期和旧存档兼容均有测试。

### AUDIO-PLAYBACK-RESILIENCE：保留失败后的待播内容并明确真人决策窗口

- **优先级：** P2
- **状态：** 队列问题待修复，时限语义待设计；尚未实施
- **来源：** 2026-11-03 [AUDIO-LIFECYCLE 评估](评估/AUDIO-LIFECYCLE评估.md#生命周期和权限核对)及 [Astra 独立审查](评估/四项评估审查.md)。`SpeechPlayback.tsx` 的失败分支清空当前项及队列，而游标已将事件记为 seen；此结论为源码路径核对，尚未做 React hook 端到端复现。
- **事实依据与边界：** 重新同步相同投影不会补入所有未播项，重新开启只选择最新一条，因此合成或播放失败可能丢失待播内容。后端行动 deadline 与音频无联动，等待或听取音频可能消耗真人决策时间；不能把“不阻塞调度”说成“不挤占真人时间”。已有播放、缓存和并发限制继续有效。
- **验收标准：** 用真实播放 hook 或等效组件场景复现首项失败、后续已有两项、失败后新事件、暂停晚到及来源失效；意外失败时失败项和后续项可按明确操作重试，顺序不重不漏，主动停止的弃队列语义单独定义。由产品方案明确等待、播放与决策起点的关系，再验证慢合成及失败情况下的行动窗口、超时、重连和席位隔离；不能仅暂停浏览器倒计时而改变服务端事实。

### AUDIO-CANCEL-CONTRACT：明确共享合成任务的取消与资源收尾

- **优先级：** P2
- **状态：** 语义待设计，尚未实施；不承诺提供方停止计费
- **来源：** 2026-11-03 [音频实测与本地 HTTP 中止测试](评估/AUDIO-LIFECYCLE评估.md)，回归 `packages/session/test/audio-lifecycle-http.test.ts`。
- **事实依据与边界：** 浏览器停止会取消客户端等待；服务端未将 HTTP 断连传给 `SpeechService.render`。本地可控提供方在客户端断开、连接确已关闭后仍继续合成并写缓存。相同内容会合并为共享任务，不能因一个客户端离开就取消其他等待者；现行超时信号不证明远端撤销、停算或退款。该现状不是已验证的计费漏洞。
- **验收标准：** 明确断连后继续缓存还是按订阅者/引用计数取消，定义零订阅者、重连、排队、超时和忽略取消的提供方的行为；用两个等待者、全部退出、迟到成功/失败等场景验证任务去重、并发槽位和资源释放。文档分别说明页面停止、HTTP 中止、提供方收到取消与实际计费；计费未知保持未知，不以本地信号替代服务契约或账单。

### MODEL-UNSUPPORTED-CERTAINTY：复核模型把未证实局面说成确定事实的表达

- **优先级：** P2
- **状态：** 具体样本已记录，待变体复现与评估；非已确认的提示或协议缺陷
- **来源：** 2026-11-03 [MODEL-QUALITY 报告](评估/MODEL-QUALITY评估.md)、[原始合成输入与响应](评估/MODEL-QUALITY测量.json)及 [Astra 逐项评分](评估/MODEL-QUALITY评分.json)。明确样本为 `villager-current-high-2` 的“这局必然一真一假”；另有把公开出局直接表达为狼刀或未救的诊断标记，按评分理由区分证据强度。
- **事实依据与边界：** 被测平民仅见1/2号的对跳陈述，没有法官确认其身份，也未排除双狼或其他可能性。问题是可见证据不支持确定性措辞，不能用上帝已知的真实身份给模型评分。每局面每格仅两次，不支持把现象归因于来源提示、思考档位或型号整体能力；工具合法不代表推理已证实，玩家策略性表达也不能直接视为内在记忆错误。
- **验收标准：** 固定投影、型号与协议，使用多种角色真相但相同公开信息、说话顺序和措辞变体，预定义“事实/玩家声称/推测/无法判断”评分；扩大交错配对样本并进行盲化语义核对，保留失败和有歧义表达。确认可复现后再决定是否调整提示或其他流程，分别比较修改与支持档位；不得以增加提示段本身作为改善证据，也不要求模型泄露私密信息或替狼人强制诚实。

## 真人与跨设备体验

### VOICE-ASR：提供可选择的语音输入入口

- **优先级：** P2
- **状态：** 方案待确认，未实施
- **事实依据与边界：** 当前只提供系统／输入法听写说明，没有项目录音按钮或 ASR 服务。浏览器系统听写唤起能力不统一；可能方案包括系统指引、在线 ASR 或本地服务。
- **验收标准：** 明确平台能力、语言、音频格式、密钥存放、失败和取消语义；识别结果写入当前席位草稿，经玩家检查和手动确认后再提交 `speak`，不代写或修改观点。

### MOBILE-CROSS-DEVICE：完成手机与第二台设备验收

- **优先级：** P2
- **状态：** 待真实设备验证
- **事实依据与边界：** 已在桌面浏览器和同一电脑的局域网地址上验证部分页面；尚未真实手机扫码，也未由第二台设备验收。不能把窄视口检查等同于 iOS／Android 或跨设备适配。
- **验收标准：** 分别记录 iOS、Android 原生输入／朗读可用性，并用手机和另一台局域网设备检查扫码、候场、发言、跨应用返回和断线重连；按实际验证设备和系统列出结论。该验收只证明被测设备上的页面与会话体验，不证明草稿在设备间同步。

### DRAFT-CROSS-DEVICE：确认真人草稿是否需要跨设备同步

- **优先级：** P2
- **状态：** 建议待确认
- **事实依据与边界：** 真人发言草稿当前保存在浏览器标签页的会话存储中，可在同一页面刷新恢复；跨设备草稿同步尚未实现。手机页面／重连验收不能替代同步能力验证。
- **验收标准：** 先确认是否需要在同席的不同设备间同步草稿及冲突规则；若实施，验证席位与决策隔离、重连和并发编辑，不能让旧决策草稿提交到新行动窗口。

### INVITE-SHORTLINK：评估站内邀请短链

- **优先级：** P3
- **状态：** 建议待确认
- **事实依据与边界：** 当前可生成本地座位／观战二维码和完整邀请链接，按权限区分；尚无站内短链。本项仅在完整链接仍不便分享时考虑，不依赖第三方平台转存凭证。
