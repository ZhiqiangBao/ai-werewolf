# 模型库内部维护

本指南供在项目工作区执行任务的 AI 助手和有终端经验的维护者使用。它说明如何安全地确认模型条目、预览影响，以及执行停用、归档、恢复、启用、归并和证据记录。

按目标选择入口：日常新增、编辑、删除通过本机网页完成；需要停用、归档、恢复、启用、归并或记录维护证据时，停止服务后使用本机命令。不要直接编辑 `models.json` 或手工删除 `.writer-lease`。

## 日常新增、编辑和删除

模型库页面的新增、编辑和删除请求只允许从运行服务的电脑发出。请在该电脑上通过 `http://127.0.0.1:<端口>/` 打开首页；默认端口是 `5173`。不要从局域网设备、域名或反向代理页面进行这些修改。

在首页展开「模型与语音」的「模型库」：

1. 新增时选择接口协议，填写模型名称和 `baseURL`，再选择直接填写密钥或从项目已登记的环境变量中选择。变量名清单、设置方法和重启步骤见 [README](../README.md#统一模型名单)。
2. 编辑时点条目旁的「编辑」，修改后点「保存修改」。直接密钥输入框留空会保留原密钥；环境变量来源可改选已登记的变量。编辑不会改写已有房间保存的配置。
3. 删除时点条目旁的「删除」。此操作会将模型归档并从可选列表移除；密钥与历史房间记录仍保留。已归并的来源别名不能在页面中编辑或删除；归并目标不能编辑，但在没有未结束房间的 AI 座位使用时可以删除。若删除被阻止，按提示的房间编号处理引用后重试。

成功后页面会显示新增、更新或移除提示并刷新模型列表。页面操作影响运行中的服务；无需先停止服务。恢复已删除条目或管理其生命周期时，使用下文的本机维护命令。

## 准备本机维护

### 确认条目 ID

命令所需的 `modelId` 是项目模型库内部 ID，不是厂商模型名称。新建条目通常是 `m_` 开头；迁移的旧条目保留原 ID。页面列表不显示内部 ID，因此从项目根目录安全列出辨认字段：

```powershell
$dataDir = if ($env:WEREWOLF_DATA) { $env:WEREWOLF_DATA } else { 'data' }
(Get-Content -Raw -Encoding UTF8 (Join-Path $dataDir 'models.json') | ConvertFrom-Json).models |
  Select-Object id, name, model, apiProtocol, baseUrl, lifecycle, mergedInto | Format-List
```

按名称、协议和接口地址确认目标，再复制 `id`。该命令刻意不输出密钥密文。如果条目有 `mergedInto`，它是已归并别名；后续维护应针对规范目标 ID，不要对别名执行停用或归档。若多个条目仍无法区分，先停止，不要猜测。

### 停服务、备份并保持环境一致

1. 在项目根目录停止**所有使用同一数据目录**的服务。前台 `pnpm dev` 在其终端按 `Ctrl+C` 并等进程退出；由项目后台管理的服务执行 `pnpm stop`。只关闭浏览器不会停止服务。
2. 备份该数据目录中的 `models.json`、`model-key-envs.json`（如有）和服务实际使用的主密钥。默认目录是项目下的 `data/`；默认主密钥是 `data/secret.key`。若服务用 `WEREWOLF_DATA`，维护命令也必须使用同一路径。若服务通过 `WEREWOLF_SECRET` 使用环境变量密钥，维护进程必须拿到完全相同的环境变量值；该变量优先于 `secret.key`。采用环境变量的供应商密钥也须由维护进程继承，且变量值须另行妥善备份。如在新终端操作，先恢复与服务相同的环境设置。不要把密钥发给 AI 助手、写入跟踪文件或贴到工单／聊天中。
3. 从项目根目录执行命令。所有写操作和预览命令都需 `--old-server-stopped`；该参数是操作者对旧版服务已停止的确认，不能替代实际停服。工具会取得数据目录租约；发生 `MODEL_STORE_BUSY` 时不要删锁文件。

维护命令不会主动调用模型供应商。它会读取模型库和房间元数据并输出本地盘点结果。命令读取当前 PowerShell 进程的环境变量；若服务使用 `WEREWOLF_DATA` 或 `WEREWOLF_SECRET`，先在同一个维护窗口设置与服务一致的值，再用该窗口停止后台服务、列出条目和执行维护。不要把完整 `models.json`、`secret.key`、`WEREWOLF_SECRET`、API Key 或含密钥的日志交给助手或提交到 Git。预览输出也可能包含本地房间 ID 和模型标识，只在需要的本机范围内分享。

## 预览影响并执行生命周期操作

先用上节确认的 ID 预览。以下命令均在项目根目录和同一个 PowerShell 窗口执行：

```powershell
$modelId = Read-Host '粘贴目标模型条目 id'
pnpm models:maintain preview $modelId --old-server-stopped
```

预览结果是 JSON。重点检查：

- `exactRefs`：房间座位明确引用该模型；`possibleRefs`：按模型名、协议和路由匹配到的可能引用，需逐项确认。
- `credentialDependencies`：维护实现能识别的凭据依赖。
- `blockers`、`canArchive`：归档阻碍及是否满足归档条件。`setup` 是待开局，`running` 是进行中，`ended` 是已结束；待开局和进行中的引用会阻止归档，即使房间暂停也需按仍未结束处理。
- `revision`、`inventoryDigest`：本次预览的校验值。不要自己计算；每次写操作都从紧邻该操作之前的预览复制最新值。库或房间盘点有变化时会报 `MODEL_PREVIEW_STALE`，应重新预览并复制新值。

`disable`、`archive`、`restore`、`enable` 和 `merge` 需要 `revision` 与 `inventoryDigest`；`scope` 和 `record` 只需要 `revision`。

在 PowerShell 中用 `Read-Host` 粘贴校验值，避免手工改写或复制引号：

```powershell
$revision = Read-Host '粘贴本次预览中的 revision'
$inventoryDigest = Read-Host '粘贴本次预览中的 inventoryDigest'
pnpm models:maintain disable $modelId $revision $inventoryDigest --old-server-stopped
```

输出 `"lifecycle": "disabled"` 表示停用成功。停用后新房间不能选用；已有房间记录和凭据不删除。若仅想阻止新选用，到这里即可。

要归档，必须重新预览并检查最新结果中的 `blockers` 和 `canArchive`。只有 `canArchive` 为 `true` 才运行：

```powershell
pnpm models:maintain preview $modelId --old-server-stopped
$revision = Read-Host '粘贴这次预览中的 revision'
$inventoryDigest = Read-Host '粘贴这次预览中的 inventoryDigest'
pnpm models:maintain archive $modelId $revision $inventoryDigest --old-server-stopped
```

输出 `"lifecycle": "archived"` 表示归档成功。归档将条目从模型选择列表隐藏，但保留密钥和历史对局；它不是清除凭据的安全删除方式。若 `canArchive` 为 `false` 或命令返回 `MODEL_IN_USE`，先在网页中结束或改配引用它的房间，再重新预览。

恢复归档模型也需要停止服务、备份和重新预览：

```powershell
pnpm models:maintain preview $modelId --old-server-stopped
$revision = Read-Host '粘贴本次预览中的 revision'
$inventoryDigest = Read-Host '粘贴本次预览中的 inventoryDigest'
pnpm models:maintain restore $modelId $revision $inventoryDigest --old-server-stopped
```

`restore` 成功后模型仍是停用状态。再预览一次并使用新的两个校验值执行 `enable`：

```powershell
pnpm models:maintain preview $modelId --old-server-stopped
$revision = Read-Host '粘贴本次预览中的 revision'
$inventoryDigest = Read-Host '粘贴本次预览中的 inventoryDigest'
pnpm models:maintain enable $modelId $revision $inventoryDigest --old-server-stopped
```

输出 `"lifecycle": "active"` 才表示模型重新可选。若结果带有 `warnings`，先按警告核对仍有效的停供证据和适用范围，再决定是否启用。

## 归并重复条目

归并会把来源 ID 映射到目标 ID；旧 ID 和历史房间快照仍保留。只归并确认实际是同一模型的条目：两项必须处于启用状态，协议、规范化后的实际端点和密钥必须相同。密钥一致由工具在本机比较，不要打印或传递密钥。模型名称不同还必须有官方证据证明它们是同一模型；无法证明时不要归并。

分别从安全列表中确认来源和目标 ID，在同一 PowerShell 中保存并预览：

```powershell
$sourceId = Read-Host '粘贴来源条目 id'
$targetId = Read-Host '粘贴目标条目 id'
pnpm models:maintain preview-merge $sourceId $targetId --old-server-stopped
$revision = Read-Host '粘贴本次预览中的 revision'
$inventoryDigest = Read-Host '粘贴本次预览中的 inventoryDigest'
```

检查返回的来源和目标影响摘要及 `equivalence`。若 `equivalence` 是 `identical_model`，从这次预览复制顶层的 `revision`、`inventoryDigest` 并执行：

```powershell
pnpm models:maintain merge $sourceId $targetId $revision $inventoryDigest --old-server-stopped
```

若模型名称不同，需先准备官方别名证据 JSON，并在预览与执行命令中传入同一个文件路径：

```powershell
$evidencePath = Read-Host '粘贴官方别名证据 JSON 路径'
pnpm models:maintain preview-merge $sourceId $targetId $evidencePath --old-server-stopped
$revision = Read-Host '粘贴本次预览中的 revision'
$inventoryDigest = Read-Host '粘贴本次预览中的 inventoryDigest'
pnpm models:maintain merge $sourceId $targetId $revision $inventoryDigest $evidencePath --old-server-stopped
```

证据至少要匹配本次预览的来源模型名、目标模型名、服务商主机名、协议和来源路由摘要；含 HTTPS 来源 URL、SHA-256 来源摘要、检查时间及简洁说明。结构要求见[维护实现](../packages/session/src/model-maintenance.ts)。证据 URL 不得包含用户名、密码、查询串或片段；说明中不要放 URL、Bearer 值或密钥。

## 记录停供、可用性或故障证据

维护命令不会替你探测服务，也不会把 HTTP 错误自动判断为停供。只有拿到可归因、可复核的来源时才记录；鉴权失败、未开通套餐、网络错误或暂时故障不能写成厂商停供。

先预览取得当前 `revision`，再准备本地 JSON 文件并执行：

```powershell
pnpm models:maintain preview $modelId --old-server-stopped
$revision = Read-Host '粘贴本次预览中的 revision'
$evidencePath = Read-Host '粘贴证据 JSON 路径'
pnpm models:maintain record $modelId $revision $evidencePath --old-server-stopped
```

记录成功后命令会输出新预览；写入证据会改变模型库版本，后续写操作须使用新预览的值。实现接受的字段、类型、证据种类和校验见[证据定义](../packages/session/src/model-retirement.ts)及[维护实现](../packages/session/src/model-maintenance.ts)。概要要求：

- 必须与预览的 `evidenceTarget` 精确匹配服务商、模型、协议和路由；`scope` 要含匹配的 `routeId`、`version: 1`、`accountScope` 和 `region`。
- `sourceDigest` 是 64 位十六进制 SHA-256；`checkedAt` 是有效且不晚于当前时间的日期；`reasonCode` 以英文字母开头，最多 80 个允许字符；`summary` 必填且不超过 500 字，不含 URL、Bearer 值或密钥。
- `official_retirement`、`documented_retirement` 需要 HTTPS `sourceUrl` 和已生效的 `effectiveAt`；`verified_available` 需要未来的 `expiresAt`。来源网址不得包含凭据、查询串或片段。
- 证据范围不能从密钥推断。`unknown` 范围不能证明停供；只有确知证据范围为全局时才标 `global`，不要用它代替未知。

如需为账号／套餐或区域建立稳定的匿名范围 ID，可单独执行 `pnpm models:maintain scope-id` 生成随机 UUID v4。它不读取模型库，也不需要 `--old-server-stopped`。账号维度应对应一个账号／套餐组合，区域维度对应实际区域；不要使用账号原文、密钥、它们的散列或其他可逆标识。可在本机受保护的位置维护 UUID 与实际范围的对应关系。

若要把匿名范围绑定到某模型，按预览目标准备 `scope.json`，形如：

```json
{
  "version": 1,
  "accountScope": { "kind": "specific", "id": "生成的 UUID v4" },
  "region": { "kind": "specific", "id": "生成的 UUID v4" }
}
```

`kind` 也可为 `{ "kind": "global" }` 或 `{ "kind": "unknown" }`，后者不能确证范围。先预览并把 `revision` 读入变量，再执行命令；它会写入范围并输出新预览。范围绑定不迁移旧证据，旧证据是否适用仍须按输出检查。

```powershell
pnpm models:maintain preview $modelId --old-server-stopped
$revision = Read-Host '粘贴本次预览中的 revision'
$scopePath = Read-Host '粘贴 scope.json 路径'
pnpm models:maintain scope $modelId $revision $scopePath --old-server-stopped
```

## 错误反馈与停止条件

| 输出／错误 | 下一步 |
| :--- | :--- |
| `MODEL_STORE_BUSY` | 还有进程或维护命令持有数据目录租约。确认所有同目录服务和并行命令已经停止后再试；不要手动删除 `.writer-lease`。 |
| `MODEL_PREVIEW_STALE` | 库或房间数据已在预览后改变。重新预览，检查结果并复制新的校验值。 |
| `MODEL_IN_USE` | 待开局或运行中的房间仍引用条目。先在正常房间界面处理引用，再预览。 |
| `MODEL_NOT_FOUND` | 核对项目根目录、`WEREWOLF_DATA` 和 ID；不要改用相似名称猜 ID。 |
| `已有模型库但主密钥缺失，维护停止` | 恢复服务原本使用的主密钥上下文后再运行；不要生成新密钥、覆盖旧密钥或尝试重加密。 |
| `MODEL_MERGE_MISMATCH`、`MODEL_MERGE_CONFLICT` | 条目不满足归并条件或状态冲突。不要绕过校验；确认条目、协议、端点、密钥和生命周期。 |
| `MODEL_ALIAS_EVIDENCE_INVALID`、`MODEL_EVIDENCE_INVALID` | 对照当前预览的目标字段和源码中的结构校验修正 JSON；不要把凭据或原始账号写进证据。 |

遇到 `MODEL_INVENTORY_INVALID`、不认识的错误、文件损坏迹象或服务运行状态无法确认时，停止写操作并保留原文件和错误输出，交由维护者检查。不要删除租约、手改模型库来绕过校验。

完成时检查命令返回的 JSON 状态：`disabled`、`archived`、`active` 或归并后的来源映射。重新启用需看到 `active`；保存证据或范围后应使用命令返回的新预览作为后续依据。
