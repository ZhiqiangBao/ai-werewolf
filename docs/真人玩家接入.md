# 真人玩家接入

更新：2026-11-02。真人与模型均提交结构化工具调用，由同一个规则引擎校验和结算。

## 如何参与

1. 房主在配置页将座位设为「真人」，发送该座位的邀请链接。房主本人要参加游戏，也应进入自己的座位链接。
2. 玩家打开链接，确认昵称、阅读规则，点击「确认昵称并准备」。其他玩家和房主会看到准备、连接状态。
3. 新房间要求所有真人准备后才能开局。更换版型或游戏规则会取消准备，需要玩家重新确认。克隆房间也重新准备。
4. 开局后本页自动显示本人的身份、私密记录、公开对话与当前行动。顶部「轮到你了」可直接前往行动区。
5. 点击目标并提交发言、投票或技能，法官接受后显示回执。其他同时行动者尚未提交时，页面显示等待状态。

房主链接始终是上帝视角；座位链接始终是该座位的权限。参与者的昵称和准备状态不会改变凭证权限。持有同一座位链接的多个页面可以操作同一席，因此链接只交给对应玩家；当前没有独立账号、抢座或转让席位功能。

## 警上退水

新开局使用 `electionVersion=3`，真人与 AI 共用同一退水规则：

- 轮到本人普通竞选发言时，可使用原有的「退水」工具，同时附带这一段发言，或留空结束发言。
- 在其他候选人的普通警上发言期间，未退水候选人可点击顶部「可退水」前往行动区，再单独点击「退水」。此时不能追加发言，也不结束他人的发言；公开退水记录立即出现。
- 全部普通竞选发言结束后，尚未退水者同时确认「继续竞选」或「退水」，收齐后公布并开始投票。该次确认提交后不能修改，超时默认继续竞选，最后一名发言者也有机会退出。
- 全部退水则没有警长；仅剩一名确认继续的候选人时直接当选。退水者是否有首轮投票权仍由本局 `sheriff.withdrawnCanVote` 决定。
- 竞选 PK 和投票开始后不能退水。延期竞选保留原退水记录、候选人与投票轮次，次日仍先确认自爆再直接续投，不重开发言或退水确认。

口头说「退水」不会自动执行退出，必须提交对应行动。`sheriff_withdraw` 在非本人发言窗口要求 `content` 为空；提交多余发言、旧窗口或重复请求都会被引擎拒绝。最终确认的保留资格动作是无参数 `sheriff_stay`。

版本缺省／1、2 的旧房间保持原流程与工具目录，不插入新阶段，不改写过去的行动。新建或克隆后开局才启用版本 3。

## 局域网邀请

默认启动支持局域网连接。配置页自动选择局域网分享地址，即使房主从 localhost／127.0.0.1 打开也会使用真实网卡的地址生成座位与观战邀请；复制和二维码使用相同地址及凭证。二维码在网页本地生成，不调用外部二维码服务。其他设备按 [README 的局域网步骤](../README.md) 扫码后可作为真人准备、行动，或以观战权限旁听。

多网卡可切换「分享地址」，换网后刷新；也可手动填写反向代理网址。经外部域名／HTTPS 打开时保留当前网址和部署路径。回环地址、未指定监听地址、带账号或房间凭证的地址不能作为分享网址；没有可用地址时禁用对应复制和二维码。显式仅本机监听时提示重启为局域网监听，不能仅把 URL 改成局域网 IP 就声称可连接。当前尚无站内短链；房主链接仍保留当前本机地址，不作为普通玩家邀请分发。

## 刷新、离线和时限

- 发言和工具表单的草稿保存在当前浏览器标签页的会话存储中，按房间、座位、决策和工具隔离；刷新同一页面可以恢复。法官接受后清除对应草稿。
- 服务端保存已接受的行动、昵称、准备状态与对局；在线状态来自当前实时连接，不写成历史事实。一个页面断开不会误把同席其他连接记为离线。
- 页面重新连接时拉取完整的授权投影，继续当前决策。断线不重置服务器上的行动时限。房主暂停期间不执行超时托管，恢复后按现有房间规则重新计时。
- 配置真人时限为 0 时不限时；开启时限时，发言、遗言与密谈为 180 秒，放逐和警长投票为 90 秒，其他技能使用配置值。超时走现有引擎托管，并向本人发送私密说明。
- 默认监听 0.0.0.0，允许局域网连接；显式设置 HOST=127.0.0.1 可限制为本机，改变监听地址后需重启。邀请其他设备时，使用邀请区生成的分享链接。

## 接口与数据

| 接口 | 凭证 | 行为 |
| --- | --- | --- |
| GET /api/v1/rooms/:id/invite-network | 房主 | 返回实际监听是否仅限本机及可选择的分享地址；不信任请求的 Host／Forwarded 头，不写入对局历史或玩家投影。 |
| POST /api/v1/rooms/:id/participate | 本人座位 | 候场时接受 name、ready；空对象表示接入或重连。运行中仅允许空对象。 |
| GET /api/v1/rooms/:id/view | 各自凭证 | 返回该受众投影；候场只返回房间名单、准备状态和规则卡，不返回发牌、模型配置或其他凭证。 |
| POST /api/v1/rooms/:id/act | 真人座位 | 接受 decisionId、tool、args。参数对象和决策标识必填。 |
| POST /api/v1/rooms/:id/speech | 各自凭证 | 接受本人投影中的 eventSeq，仅生成已接受的公开发言音频。 |
| GET /api/v1/rooms/:id/stream | 各自凭证 | 更新通知；客户端随后重新读取自己的 view。 |

真人侧使用协议中的 SeatActionInput。模型适配器也返回 ToolCall，再由会话层附上座位与决策标识；二者都进入 RoomManager.apply → engine.submit，没有单独的真人规则处理器。

插入行动也绑定 actionWindowId。上一段发言页面中的自爆、上一轮表单的重发均不能落入下一决策。引擎拒绝过期和重复提交，错误只发给本人。服务端不依据页面传来的座位号或视角提升权限。

RoomRecord.participants 是可选字段。旧存档不补写历史、运行中的旧房间不重新候场；缺少该字段的旧配置仍可按原方式开局。新房间和克隆房间启用准备门槛。

## 验证范围

自动化覆盖候场门槛、输入与凭证边界、规则变更、多个实时连接、重载与克隆、旧存档、过期行动、混坐整局，以及真实 HTTP/SSE 首次连接的响应头。相关文件：

- packages/session/test/human.test.ts
- apps/server/test/human-http.test.ts
- packages/session/test/session.test.ts

本次补充退水的普通／最终窗口、并行发言、过期与重复提交、PK、延期续投、持久化和新旧版本重放回归。完整测试 32 个文件、323 项通过，TypeScript 检查与网页生产构建通过；提交前另复核会话隔离测试 26 项通过。测试使用合成数据，没有新增真实模型或 TTS 调用。

Terra 在独立合成房间中实测发言后退水、最后发言者最终确认、刷新保留、投票开始后入口关闭，以及邀请二维码展示、切换、收起和本机地址提示。未操作真实房间，未进行真实手机扫码或第二台局域网设备验证。

之后的局域网邀请修复通过服务器与网页 6 个测试文件、64 项回归，以及类型检查和生产构建。Terra 从 127.0.0.1 房主页确认自动使用 WLAN 的局域网地址，实际进入该地址下的真人席位并准备、打开观战页、复制后粘贴核对完整邀请，验证网卡切换、手动填写与回环地址拒绝；显式仅本机监听的对照服务没有默认二维码。另将页面实际绘制的二维码 SVG 独立解码，确认网址、席位与凭证均与可见邀请一致。以上是同一电脑通过真实 LAN 地址的验证，仍未代替实际手机扫码或第二台设备的网络验收。

对局记录提供自动朗读、单条重听、暂停和语速控制，来源与配置见 [发言朗读](发言朗读.md)。早期真实服务与浏览器的操作记录见 [架构评估与后续演进](架构评估与后续演进.md)。系统听写操作说明在 README；ASR 按钮、手机专项、账号与席位转交仍属于后续工作。
