## 固定实施契约

- 观测缺省关闭；新接口只增加可选项。原有审计、房间格式、公开方法和 `RoomStore` 接口保持兼容。
- 新耗时使用单调时钟；墙钟与旧 `latencyMs`、行动截止时间沿用原定义，不跨时钟相减。
- 每层有独立 ID、开始和幂等终态：运行、房间、波次、工作项、行动片段、模型调用、适配器执行、请求变体、HTTP 尝试、退避及本地 I/O。
- 观测不修改请求内容、协议、缓存、纠错次数、HTTP 重试、总预算、逐事件整波旁听与行动问话边界。
- 未知值使用 `null` 与缺失原因；提供方队列默认不可观测，不从首段时间推算。诊断输出严格投影白名单，不携带正文、思考、密钥、原生块或原始地址。
- 收集器和异步缓冲独立于业务保存；待写批次计入容量，采集故障隔离，正常收尾等待诊断输出不计入对局时间。
- 基线只使用固定快照、模型桩和独立本机模拟服务；同时最多两桌。正式矩阵、专项分支、计时误差和 AB／BA 开销须分别记录实际执行范围，不能用快速样本冒充完成。

## 实现位置与使用

- `packages/protocol/src/observation.ts`：固定版本的观测字段、缺失原因、来源、引用和可选配置。原审计只增加可选关联。
- `packages/session/src/observability/collector.ts`、`buffer.ts`、`identity.ts`：单调时钟、幂等终态、60 秒迟到清理、有界异步批次、本机随机映射和输出白名单。
- `packages/llm/src/observation*.ts`、`transport.ts` 及三协议适配器：请求变体、实际 HTTP 尝试、原退避、响应头／字节／语义内容、解析、原始 usage 存在性。
- `room-runtime.ts`、`room-persistence.ts`：工作项与行动片段、调用者取消和迟到、获准打断与引擎结果、整波等待、尾部等待和同步 I/O。
- `observability/report.ts`：分层计数、nearest-rank、按提供方／模型／协议／purpose 聚合、用量覆盖率与历史审计的独立口径。
- `observability/synthetic-*.ts` 与配套脚本：固定快照、独立回环服务、异步上下文、注入计划、服务真值、源码与环境 manifest 及开关配对。
- `observability/acceptance.ts`：对齐每个尝试的独立时段，检查样本覆盖、源码一致性、重复／未闭合终态、丢失、工作清单和误差门槛。

默认服务入口不启用采集。合成运行器显式使用 `ManagerOptions.observability` 与 `BufferedObservationSink`；业务入口保持同步语义，合成程序在测量窗口结束后等待诊断缓冲排空。诊断映射及数据只在忽略的 `data/diagnostics` 下保存，不增加公开 HTTP/SSE 端点。

```sh
# 仅显示计划，绝不冒充执行结果
pnpm observability:baseline --plan
# 单次运行及正式单桌矩阵；S02/S03 为双桌同／不同端点
pnpm observability:baseline --scenario S01 --protocol responses
pnpm observability:baseline --scenario S01 --formal
# 指定故障分支；各分支分别生成可复查目录
pnpm observability:baseline --scenario S07 --case network --protocol responses
pnpm observability:baseline --scenario S13 --case file --protocol responses
pnpm observability:baseline --scenario S15 --case write_failure --protocol responses
# 真实关闭／开启生产观测，AB／BA 交替，固定窗口测试夹具相同
pnpm observability:baseline --overhead --scenario S01 --protocol responses --pairs 30
# 运行目录可以多个；缺省要求三拓扑三协议正式矩阵
pnpm observability:accept RUN_DIRECTORY... --output data/diagnostics/accuracy-acceptance
```

原始产物为 `manifest.json`、`observations.jsonl`、`synthetic-truth.jsonl`、`workload.json`、`summary.json`、`report.md`。manifest 记录源码哈希起止、精确环境、种子、负载、波次、计时、采集状态和实际终止原因；`--plan` 仅为计划。开销关闭组不保留观测端口；两组复用测试专用 `prepareWave` 窗口夹具和回环 fetch 包装，不更改生产调度器或请求体。

同源不同路由只有在 `providerAliases` 显式配置非敏感分组键时才分开；原地址只用于本机匹配，不进入诊断标签或身份映射。缺省仅按规范化 origin 分组，不把接入端点当作背后模型厂商。
