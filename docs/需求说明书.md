| 项 | 内容 |
| --- | --- |
| 版本 | 1.0 |
| 日期 | 2026-10-30 |
| 状态 | 待实现的基线需求 |
| 首发形态 | 网页 |

本文把「每个座位可接大模型、法官做规则判决、技能做成身份工具、信息按身份隔离、系统信息包含本场规则」补成一套可实现、可测试、可扩展的需求。本版提供九人与十二人两套版型，规则都在同一套引擎里。

## 1. 需求追溯

| 原始要求 | 本文落点 | 补充后的完整含义 |
| --- | --- | --- |
| 每个位置接入大模型 API | 第 8、17 章 | 每个座位独立配置模型、密钥、温度和性格。人和 AI 走同一套行动接口，可以混坐 |
| 法官判断技能并决定发言顺序 | 第 6、7、10–15 章 | 法官是确定性规则引擎。落刀、查验、用药、守护、投票、警徽、自爆、猎人、胜负都由引擎判决，模型不能改判 |
| 工具跟随身份 | 第 16 章 | 身份工具只发给持有该身份、且当前阶段合法的座位。公共工具（发言、投票、上警）按阶段发给存活玩家 |
| 每人只看到该看的信息 | 第 9 章 | 事件在写入时冻结受众。网页和模型使用同一份座位投影，座位凭证读不到上帝视角 |
| 系统信息包含本场规则 | 第 5、8 章 | 规则卡由本场规则对象生成，开局发给所有座位，并且每次决策都附带同一份摘要 |

另外补上的必要需求：胜负条件、夜间结算真值、平票与警长 1.5 票、遗言、自爆、超时托管、复盘明牌、信息屏障验收、引擎与网页分离。这些不写清，上述五条无法稳定落地。

## 2. 目标与非目标

### 2.1 目标

1. 房主可以创建一局游戏，选择板子，为每个座位指定「真人」或「某个大模型」，然后自动跑完一局。
2. 真人用网页完成发言、投票和技能；模型用工具调用完成同样的事。
3. 法官对每一次行动给出符合本场规则的判决，并公开它该公开的结果。
4. 任意座位的网页与模型请求都不包含该座位无权知道的信息。
5. 核心规则不依赖网页。以后做桌面端、机器人和别的客户端时，复用同一引擎、同一套事件和同一套投影。

### 2.2 非目标（本版不做）

- 账号体系、匹配、排位、商城、观战大厅里的陌生人社交。
- 语音。本版发言是文字。
- 法官由大模型扮演。模型只扮演座位。
- 白痴、骑士、白狼王、狼美人、石像鬼等扩展身份的具体规则。本版只预留身份模块接口。
- 首夜之前先上警。本版固定「先夜后日」。
- 手机原生应用。网页座位页要能在窄屏完成操作。

### 2.3 已定默认

下列选择是本版规则，不是实现时再议的空项。房主能改的只有第 5.3 节标成「可改」的开关。

1. 法官是纯规则引擎，判决来自状态和行动，不来自模型自由发挥。
2. 闭眼局：出局不公布身份。全场结束后才公开复盘。
3. 身份配置公开（有几狼、有哪些神），座位分配不公开。
4. 夜间顺序固定为：守卫、狼人、预言家、女巫。缺少的身份跳过该阶段。
5. 女巫默认不能自救；同一晚不能既救又毒。只有解药还在的夜晚才被告知刀口；解药一旦用掉，之后不再得知刀口。毒药可以毒当晚刀口。
6. 守卫可以空守，可以守护自己。限制只有一条：不能连续两晚守护同一人。上一晚空守之后，下一晚不再禁守任何座位。
7. 同守同救则刀口出局。
8. 猎人被狼刀、被票出、因同守同救出局时可以开枪；死因含毒则不能开枪；放弃开枪不公开猎人身份。
9. 狼人互相认识，可以空刀，可以刀队友（自刀）。空刀不计票。只有所有存活狼人都空刀，当晚才没有刀口；否则得票最多的座位成为刀口。
10. 投票为同时秘密投票，全部提交后公开完整票型（谁投了谁）。
11. 警长票权重为 1.5。内部用整数：普通票记 2，警长票记 3，展示时除以 2。
12. 放逐平票先 PK 一次，再平则平安日。竞选警长平票则本局无警长。
13. 狼人自爆会立刻死亡。若自爆者是警长，由他自己选择移交警徽或撕掉警徽，然后发表遗言。尚未完成的发言和尚未产生结果的放逐取消。
14. 有警长时，白天发言从警长选定方向的下一名存活者开始，警长最后发言。无警长时，从夜间死亡锚点的下一名存活者开始。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 板子 | 人数、身份数量、胜负方式和开关的一套预设 |
| 座位 | 1 到 N 的玩家位置。座位号不变，身份发到座位上 |
| 闭眼 | 出局时不公布身份 |
| 刀口 | 狼人当晚选择的目标，尚未经过守护和用药结算 |
| 空刀 | 狼人当晚不选择目标 |
| 自刀 | 狼人把刀口选在狼队友或自己身上 |
| 空守 | 守卫当晚不守护任何人。这是合法行动。空守当夜没有人被守住 |
| 金水 / 查杀 | 预言家查验结果为好人 / 狼人。好人不再细分神或民 |
| 同守同救 | 守卫守护了刀口，且女巫对同一刀口使用了解药，刀口仍然出局 |
| 屠边 | 狼人杀死全部平民，或杀死全部神职，即狼胜 |
| 屠城 | 狼人杀死全部好人，才算狼胜 |
| 警徽 | 警长标记。持有者放逐投票权重为 1.5，并负责选择发言方向、死亡时移交或撕毁 |
| 归票 | 警长在本轮发言的最后表明投票意向 |
| 退水 | 上警玩家在竞选发言阶段退出竞选 |
| 平安日 | 放逐投票没有产生出局者 |
| 遗言 | 有资格的出局者发表的最后一段公开文字。谁有资格见第 6.5 节 |
| 复盘 | 游戏结束后公开的身份与夜间行动记录 |
| 投影 | 按受众从事件日志生成的可见信息。网页和模型都只消费投影 |
| 上帝视角 | 房主用于审计的全量视角，不是一个玩家 |

座位环：编号增大的方向称为顺时针，编号减小的方向称为逆时针，从 N 与 1 处闭合。界面同时展示方向和由此得到的完整发言顺序，避免只写「左 / 右」。

## 4. 模块与依赖

网页只是客户端。规则只存在于引擎中。

```text
packages/protocol    事件、行动、规则对象、座位投影的数据结构
packages/engine      纯函数规则引擎。不访问网络、数据库和模型
packages/session     房间、事件日志、凭证、调用模型、推进对局
packages/llm         模型适配器。把「投影 + 合法工具」变成一次工具调用
apps/web             网页。只通过会话层读写投影和提交行动
```

依赖方向：

- `engine` 不依赖 `llm`、`session`、`web`。
- `llm` 可以依赖 `protocol`，不依赖 `engine` 内部状态。
- `session` 编排引擎、投影和模型。
- `web` 不实现任何胜负、结算或可见性判断。前端可以提前提示非法操作，服务端引擎的判决为准。

对局推进只有这一条路：

1. 引擎根据状态给出当前待行动座位和合法工具。
2. 会话层用该座位的投影组装上下文。
3. 真人在网页提交工具调用，或适配器向该座位的模型请求工具调用。
4. 引擎校验并执行，追加事件。
5. 投影更新，推送到对应凭证。

模型的自然语言发言若不是工具参数，引擎不采纳。引擎不解析「我感觉 3 号像狼所以刀他」这种自由文本来猜测行动。

建议实现顺序（不削减本文范围）：先让引擎在模拟玩家下跑通九人局和信息屏障测试，再接真实模型与网页，并验收十二人警长局。阶段机从第一天就包含守卫、警长、自爆这些步骤；某块版型的身份列表里没有守卫时跳过守护，而不是事后再插入新流程。

身份模块声明自己的阵营、是否计入神职、单局人数上限。预言家、女巫、猎人、守卫计入神职，本版上限各为 1。平民计入平民。狼人计入狼人。屠边统计读模块声明，引擎里不写死身份名单。

版型校验：

- 屠边：开局至少 1 名狼人、1 名神职、1 名平民。
- 屠城：开局至少 1 名狼人、1 名好人。
- 每种身份的数量不超过该模块声明的单局上限。
- 人数等于身份列表长度。
- 列表中的每个编号都必须已经注册。
- 不满足则拒绝开局并说明原因。

### 5.2 版型

版型是数据，不是另一套流程。一份版型只包含人数、身份多重集，以及第 5.1 节的规则开关。发牌、夜间顺序、结算、发言、投票都读这份数据，并调用身份模块。九人和十二人的差异只有身份列表里有没有守卫、狼和民的数量。引擎里不出现「如果是九人就走这个函数」这种分支。

本版界面只提供下面两套预设。不设计六人局，预设、开局页和验收里都不出现六人身份表。

| 预设 | 人数 | 身份 | 默认胜负 | 警长 |
| --- | --- | --- | --- | --- |
| 九人经典 | 9 | 狼人 ×3，预言家，女巫，猎人，平民 ×3 | 屠边 | 开 |
| 十二人预女猎守 | 12 | 狼人 ×4，预言家，女巫，猎人，守卫，平民 ×4 | 屠边 | 开 |

身份列表里没有守卫时，跳过守护阶段。没有猎人则不会出现开枪职责。警长关闭则跳过竞选、警徽和 1.5 票。以后增加版型，只新增一份预设数据；身份种类不够时，再注册身份模块。这两件事都不改投影、发牌和模型适配器。

### 5.3 系统信息

系统信息是法官发给座位的正式说明，分两段，都由程序从规则对象和身份模块生成。

**公共规则卡**，所有座位收到的文字完全一致，包含：

- 人数、身份配置（不含座位分配）、胜负条件。
- 夜间顺序，以及缺少的身份会跳过。
- 各技能的合法与非法（第 5.1 节里写入规则卡的条目）。
- 发言顺序、投票、平票、警长、自爆、遗言、闭眼、结束后复盘。
- 本座位当前可用的信息范围说明：公共日志、自己的身份、自己的技能记录。
- 工具使用方式：决定必须通过工具提交，法官不接受口头行动。

**身份附录**，只发给对应座位，包含：自己的座位号、身份、该身份的私密记录、当前合法工具名称。狼人附录包含队友座位。

禁止在提示词或网页帮助文案里手写第二份规则。规则变更的做法是：改规则对象或身份模块，更新由它们生成的规则卡，再改结算测试。

每次向模型要行动时，都附上整份公共规则卡和该座位的身份附录，避免只在开局说一次、后面被长对话冲掉。规则卡不另做一份会走样的「摘要版」。

运营限制不写入规则卡：单局超过 15 个白天仍未结束，法官宣布流局并进入复盘，不分胜负。这是防止对局无法结束的上限，不向玩家公布，避免利用「拖局」做策略。

### 5.4 十二人默认规则卡必须表达的意思

生成文本可以调整用词，但信息量不得少于下面这段：

> 本局 12 人，身份配置为狼人 4 名、平民 4 名、预言家、女巫、猎人、守卫各 1 名。配置公开，座位不公开。好人获胜条件：所有狼人出局。狼人获胜条件：所有平民出局，或所有神职出局。神职指预言家、女巫、猎人、守卫。
>
> 先进行夜晚，再进入白天。夜间顺序：守卫、狼人、预言家、女巫。守卫可以守护一名存活玩家，也可以空守。可以守护自己。不能连续两晚守护同一人；上一晚如果空守，下一晚可以守护任意存活玩家，包括更早守过的人。狼人互知队友，可以空刀，可以刀队友。每名存活狼人各提交一次。空刀不计票。只有所有存活狼人都空刀，当晚才没有刀口；否则得票最多的座位成为刀口。得票并列时重投一次，仍然并列则座位号较小的目标成为刀口。只剩一名狼人时，他的提交直接生效。预言家每晚查验一名其他存活玩家，结果只区分好人或狼人。女巫有解药和毒药各一瓶。只有解药还在时，法官才告诉她当晚刀口；没有刀口时告诉她今晚没有落刀。这个刀口是狼人选择的原始目标，不包含守卫是否守中。解药用过之后，女巫不再得知刀口，也不会被告知「今晚没有落刀」。解药只能救当晚刀口，不能自救。同一晚不能既救又毒。毒药可以毒任何其他存活玩家，包括当晚刀口，不能毒自己。毒刀口就是这一瓶用毒药：刀口没被守住则出局且死因含毒，猎人不能开枪；刀口被守住时刀失效，毒仍然使其出局。解药已经用掉、毒药还在时，女巫仍可毒人，但她不知道刀口是谁。两瓶药都用完后，女巫夜晚不再行动。同一晚若守卫守护了刀口且女巫也救了刀口，该玩家出局（同守同救）。
>
> 天亮只公布谁出局，不公布是被刀、被守、被救还是被毒。猎人被刀、被票出或因同守同救出局时可以开枪带走一名存活玩家，也可以放弃。放弃不公布猎人身份。死因里包含毒药时，猎人不能开枪。开枪会公开射手身份。第 1 夜猎人开枪带走的人有遗言。第 2 夜及以后，猎人夜里开枪带走的人没有遗言。猎人白天被票出后开枪，被带走的人有遗言。
>
> 有遗言的是：第 1 夜出局的人、第 1 夜猎人开枪带走的人、被投票放逐的人、自爆的人，以及猎人因被票出而开枪带走的人。第 2 夜及以后夜里出局的人没有遗言，这些夜里猎人开枪带走的人也没有遗言。第一天若有人有遗言，遗言在竞选警长之前。可以不上警。无人上警、全员上警，或竞选票数最终平票，则本局没有警长。警长的放逐票记为 1.5 票。警长选择顺时针或逆时针，从相邻存活玩家开始发言，警长最后发言。警长出局时由他自己把警徽移交给一名存活玩家，或撕掉警徽。警长自爆同样由他自己选择移交或撕掉，不能由系统直接撕掉。
>
> 没有警长时：若昨夜有人因刀或毒出局，发言从狼刀出局者的下一位存活玩家开始；若刀口未死、只有毒药出局，从该出局者的下一位开始。方向由法官宣布。昨夜平安且没有警长时，法官指定一名存活玩家开始，并宣布方向。
>
> 放逐为同时投票，票齐后公开谁投了谁。平票的玩家 PK 发言后再投一次，被 PK 的人不能参加这次投票。再次平票则平安日，无人出局。存活玩家超时未投票记为弃权。
>
> 狼人可以在白天发言、竞选发言、PK 发言和遗言开始前自爆。正在收取投票时不能自爆。自爆者立刻出局，身份公开为狼人，并发表遗言。若他是警长，先由他自己选择移交或撕掉警徽，再发表遗言。已经生效的死亡和放逐保留；尚未产生的放逐结果取消，剩余发言取消，随后进入夜晚。
>
> 出局玩家不公布身份。游戏结束后的复盘包含两样东西：对局中已经公开的发言和遗言，以及此时才公开的每个座位的身份和全部夜间行动。夜里没有遗言的人，复盘时看的就是这份终局公开。
>
> 你只能依据法官发给你的公共信息和你自己的身份记录做决定。发言里声称身份，不会得到法官的证实或否认。

九人版型以及房主改过的开关，按实际规则对象生成，不套用这段十二人原文。九人规则卡里的身份配置没有守卫。

## 6. 对局流程

### 6.1 开局

1. 房主锁定规则，为每个座位选定真人，或选定模型配置。
2. 发牌是随机的。取出该版型的身份多重集，用本局种子做 Fisher-Yates 洗牌，再按座位 1 到 N 依次发给洗牌结果。不按座位号预绑身份。同一版型、不同种子，各座位身份不同；同一种子重放，发牌结果相同。种子和洗牌结果写入上帝事件。每个座位只收到自己的身份，狼人另外收到队友座位。
3. 向每个座位发送：公共规则卡、自己的身份。向每名狼人发送完整狼队友列表（含自己）。
4. 进入第 1 夜。开局天数记为 1，第 1 夜与第 1 天共用这个计数；每次进入下一夜时加一。随机结果只公开法官已经宣布的可见后果，例如发言方向。种子只进入上帝事件。

### 6.2 夜晚

按 `nightOrder` 执行。该身份无人存活则跳过。夜晚开始时存活的玩家参与当晚对应阶段；夜晚中途没有人提前出局。

1. **守卫**：存活守卫提交一名守护座位，或明确空守。空守合法。
2. **狼人密谈**：存活狼人不止一名时，按座位号各说一轮，每人一句。只有一名存活狼人时跳过密谈。
3. **狼人落刀**：存活狼人同时提交刀口或空刀。提交期间互不可见。全部提交后，这些狼人看到每人的提交和合并结果。空刀不计票。只有每一名存活狼人都空刀，当晚才是空刀。只要有人落刀，得票最多的座位成为刀口：4 名狼人里 2 人刀同一座位、另外 2 人空刀，刀口成立。两边刀口同票则并列，公开选择后重投一次；仍然并列时，座位号较小的目标成为刀口，不能因此变成空刀。只剩一名存活狼人时，他的提交直接采纳。
4. **预言家**：存活预言家提交一名查验目标，并立刻在私密记录中得到「好人」或「狼人」。
5. **女巫**：女巫已出局，或解药与毒药都已用完，则跳过本阶段，不发送刀口。解药还在时，先把原始刀口写入她的私密记录（空刀则写明今晚没有落刀），再要求她提交用药。解药已经用掉、毒药还在时，不写刀口、也不写「没有落刀」，只要求她决定毒谁或不用毒。

然后引擎结算，产生出局名单和每人的公开/私密后果。结算细节见第 11 章。

### 6.3 天亮到入夜

下列顺序是规范性脚本。某步条件不满足就跳过，进入下一步。

1. 公布昨夜出局名单。平安则公布平安。不公布死因。
2. 处理猎人开枪职责。新的开枪死亡立刻公布。
3. **在开枪结束后**判定胜负。已分出胜负则只给第 6.5 节有资格的人遗言，然后复盘并结束。这场遗言不再提供自爆、投票和技能。
4. 若警长已死且警徽还在，由这名出局警长本人选择移交或撕徽。移交目标必须是当前仍存活的玩家。没有遗言资格的警长也要做这个选择。
5. 遗言。只包含第 6.5 节有资格的人，按座位号从小到大。第 1 夜出局者在此发言，第 1 夜猎人开枪带走的人也在此发言。第 2 夜及以后的夜间出局者跳过，这些夜里猎人开枪带走的人也跳过。每段遗言之前按第 14 章询问自爆。
6. 若是第 1 天且本局有警长竞选：上警、竞选发言、投票、必要时 PK。详见第 13 章。竞选过程中的自爆按第 14 章处理，竞选作废。
7. 决定白天发言顺序。详见第 10 章。
8. 按顺序发言。发言窗口内的自爆按第 14 章：警徽选择、遗言，然后取消剩余发言和放逐。
9. 同时放逐投票，公开票型，必要时 PK。详见第 12 章。
10. 公布被放逐者。被放逐的猎人处理开枪。开枪目标立即公布。再次判定胜负。
11. 若警长因放逐或这次开枪出局，由他本人选择移交或撕徽。对局还继续时，这次选择从下一轮投票才生效；本轮 1.5 票已经记在原警长身上。
12. 遗言：被放逐者有。猎人因这次被票出而开枪带走的人有。按座位号从小到大。
13. 若第 10 步已分出胜负：遗言之后进入复盘并结束。否则进入下一夜，白天计数加一。

死亡职责是唯一允许「已经出局的座位」继续行动的窗口：

| 职责 | 谁来执行 | 完成后 |
| --- | --- | --- |
| `hunter_shoot` | 有开枪权的出局猎人 | 未开枪则不公开身份 |
| `badge_dispose` | 持有警徽的出局警长 | 超时则撕徽 |
| 遗言 `speak` | 第 6.5 节有资格的出局者 | 超时则遗言为空 |

职责做完后，该座位行动通道关闭。之后只接收公开信息，不接收新的私密事件。

### 6.5 遗言资格

遗言不改变胜负，也不公开身份。有资格的人按座位号从小到大说。没有资格的人不进入遗言队列。

| 出局方式 | 有无遗言 |
| --- | --- |
| 第 1 夜出局 | 有 |
| 第 2 夜及以后，夜里出局 | 无 |
| 被投票放逐 | 有 |
| 自爆 | 有 |
| 猎人第 1 夜出局而开枪带走 | 有 |
| 猎人第 2 夜及以后夜里出局而开枪带走 | 无 |
| 猎人因白天被票出而开枪带走 | 有 |

猎人自己夜里出局时：第 1 夜的猎人有遗言，第 2 夜及以后的猎人没有遗言。他的开枪职责照常处理。第 1 夜被他带走的人有遗言；第 2 夜及以后被他在夜里带走的人没有遗言。猎人白天被票出时，他本人有遗言，被他开枪带走的人也有遗言。

### 6.6 无行动者的步骤

公布、结算、胜负、发言顺序公告由引擎直接完成，不调用模型。

## 7. 法官引擎

### 7.1 职责

引擎是唯一裁判。它负责：

- 维护阶段，决定谁行动、能用哪些工具、参数是否合法。
- 合并狼刀、结算夜晚、计票、处理警徽、处理自爆、判定胜负。
- 生成法官公开文案。
- 为每个事件写入冻结后的受众。
- 拒绝非法行动，并把原因只返回给行动者。

引擎不负责：调用模型、保存密钥、渲染网页、替玩家编造发言内容。

### 7.2 状态与事件

事件日志是对局的事实来源。当前状态可以由「初始状态 + 种子 + 事件」重放得到。数据库里的状态快照只是缓存。

每次成功行动追加一条或多条事件。事件至少包含：序号、天数、阶段、类型、写入时已经解析成座位号列表的受众、载荷。受众使用具体座位号，不使用「所有狼人」这种会随死亡变化的动态条件。上帝视角可以看到全部事件，但不写进玩家受众。

公开文案只允许使用受众为全体的事件。私密结果不生成公开句子。

### 7.3 合法行动

引擎对「当前状态 + 座位」输出合法工具及参数约束。网页按钮和模型工具列表都来自这份输出，而且只包含当前合法的工具。

校验失败时不改变状态，不产生公开事件。行动者收到错误码和中文原因，可以在同一决策内重试，最多 2 次。仍然非法则按第 18 章超时托管。

错误码至少包括：

| 错误码 | 返回给行动者的原因（含义） |
| --- | --- |
| `NOT_YOUR_TURN` | 当前没有轮到该座位 |
| `TOOL_NOT_LEGAL` | 该身份或阶段不能使用这个工具 |
| `ALREADY_ACTED` | 这一步已经提交过 |
| `TARGET_DEAD` | 目标已经出局 |
| `TARGET_NOT_IN_GAME` | 没有这个座位 |
| `TARGET_SELF_FORBIDDEN` | 这个行动不能选择自己 |
| `POTION_USED` | 对应的药已经用过 |
| `SAME_NIGHT_BOTH_POTIONS` | 同一晚不能既救又毒 |
| `CANNOT_SELF_SAVE` | 本场规则不允许自救 |
| `GUARD_REPEAT` | 不能连续守护这个座位 |
| `BADGE_REQUIRED` | 只有现任警长能做这个行动 |
| `INVALID_ARGUMENT` | 参数不完整或类型不对 |

原因里只解释这条规则，不附带其他人的刀口、查验、用药或守护。

### 7.4 法官不回应身份声明

玩家在发言里说「我是预言家」或「我昨晚救了人」，法官不证实、不否认、不补充隐藏事实。只有工具产生的公开后果会进入公开日志，例如投票结果、自爆、猎人开枪、警徽移交。

### 7.5 胜负检查点

检查点位于：天亮开枪全部处理完之后；放逐开枪全部处理完之后。遗言不改变胜负。

在检查点统计开枪完成后的存活人数：

1. 存活狼人为 0：好人获胜。
2. 否则若规则为屠边，且开局存在的神职已全部出局，或开局存在的平民已全部出局：狼人获胜。
3. 否则若规则为屠城，且好人全部出局：狼人获胜。
4. 否则对局继续。

因此，最后一名神职如果是猎人并在出局时开枪带走了最后一名狼人，好人获胜。若他带走的不是最后的狼人，狼人获胜。被毒死的猎人没有开枪步骤，直接用毒死之后的人数判定。

同一检查点若狼已死光，优先判定好人获胜。

### 7.6 随机

洗牌、平安夜起始座位、方向、竞选发言起点，都使用本局种子的单一随机流，并按发生顺序记入上帝事件。重放时不重新抛随机数。模型输出不是随机流的一部分，重放直接使用已经提交的行动。

## 8. 座位与大模型

### 8.1 座位配置

每个座位在开局前配置：

| 项 | 说明 |
| --- | --- |
| 控制者 | `human` 或 `ai` |
| 适配器 | 本版为 `openai_compatible` 或 `mock` |
| 接口地址 | OpenAI 兼容的基地址 |
| 模型名 | 由该服务定义 |
| 密钥 | 只在服务端保存 |
| 温度 | 默认 0.7 |
| 超时 | 发言、遗言和狼队密谈 180 秒；放逐投票和警长投票 90 秒。其余行动：模型 HTTP 默认 60 秒，真人默认 90 秒 |
| 扮演风格 | 只影响发言措辞 |

密钥加密保存。接口返回、事件、投影、提示词和错误日志都不出现密钥明文。配置页再次打开时只显示掩码。测试连通性的请求不携带任何对局信息，只确认地址、密钥和模型能否返回一次工具调用。

不同座位可以使用不同模型。一局中可以部分真人、部分模型。模型先加入名单：填写名称、接口地址和密钥，或直接使用 Qwen Code settings.json 里已经写好的模型。座位只从这份名单里选择。密钥只写入本机 data/，不进入仓库，接口响应里也只有掩码。每个座位可以测试所选模型的连通性。

### 8.2 适配器契约

适配器输入：该座位的消息列表、当前合法工具的 JSON Schema。  
适配器输出：恰好一个工具调用。

- 没有工具调用、工具不在合法列表中、或一次返回多个工具调用：视为这次失败，把错误发回模型重试。
- 网络失败可重试 2 次。
- 适配器不做「从一段话里猜他想刀谁」。
- 模型若不支持工具调用，适配器可以要求它返回唯一一个 JSON 对象，再转换成工具调用。转换失败就重试，最后走托管。引擎看到的仍然是工具调用。

### 8.3 扮演风格

预置风格：冷静逻辑、激进强势、保守谨慎、直觉、均衡。房主可以另写一段性格说明。

风格文本追加在规则卡和身份附录之后。它只改变措辞和冒险倾向。它不能增加工具，不能要求模型索取隐藏信息，不能覆盖规则卡。

### 8.4 无密钥试玩

内置模拟适配器必须能在不配置任何密钥时跑完整局。模拟玩家使用同一套工具接口和同一套投影，用于验证规则和信息屏障。模拟玩家的发言可以模板化，但行动必须合法。

### 8.5 自动推进

默认自动推进：轮到模型时，服务端自行请求并提交。轮到真人时等待网页提交。房主可以暂停，或单步执行下一次模型决策。

同一时刻需要多人同时决定时（落刀、放逐投票、上警、自爆询问、警长投票），会话层先为所有行动者生成投影，再并行请求。任一结果在全部提交前，都不进入其他人的投影。其中一人非法重试时，仍然不能看到其余人尚未公开的选择。

## 9. 信息可见性

### 9.1 总原则

每一条事件在写入时就有受众座位列表。投影只收录受众包含该座位的事件。上帝投影收录全部事件。

网页座位页、该座位的模型提示词、以及该座位凭证能请求到的接口，三者使用同一份座位投影。禁止为了「让模型玩得更像」向提示词追加投影里没有的字段。

测试必须能直接比较：座位页使用的 JSON，与组装提示词使用的 JSON，是同一投影。

座位凭证请求上帝视角时拒绝。仅有房主凭证可以读取上帝投影。把 `perspective=god` 放在查询参数里不能提升权限。

| 狼队友名单 | 开局时的全部狼人座位 |

| 当轮尚未集齐的落刀 | 仅提交者；集齐后的各狼提交和合并结果只写给当时存活的狼人 |

已出局的狼人不再收到此后夜晚的密谈和刀口。他保留出局前已经收到的私密记录。

预言家查验谁，不通知被查者。守卫守护谁，不通知被守护者，也不通知狼人。女巫是否用药，不通知狼人。

### 9.3 各身份在对局中掌握的信息

全体存活玩家和观战都能看到：

- 本场规则卡。
- 座位列表、谁存活。
- 公开发言、遗言、上警过程、警长是谁、警徽移交或撕毁。
- 票齐之后的完整票型，包括弃权和警长 1.5 的权重。
- 天亮出局名单（无死因）、被放逐公告、自爆公告、猎人开枪公告。
- 结束后的复盘。

在此之外：

| 身份 | 额外掌握 | 明确不掌握 |
| --- | --- | --- |
| 狼人 | 队友座位；自己存活期间的密谈；自己存活期间每晚合并后的刀口 | 查验、用药、守护、他人票未公开前的选择 |
| 预言家 | 每次查验的目标与「好人/狼人」 | 刀口、用药、守护、狼队 |
| 女巫 | 解药尚未使用的夜晚：当晚原始刀口，空刀则得知没有落刀。自己的药量和用药记录在整个对局中保留 | 解药用掉之后的刀口，包括「有没有落刀」。守护是否生效、查验、狼队。法官不向她发送「同守同救」；她只能根据自己救下的人和次日公开死亡自行推断 |
| 守卫 | 自己每晚守了谁，或当晚空守。上一晚空守时，下一晚没有禁守座位 | 刀口、查验、用药、狼队 |
| 猎人 | 法官在他有开枪权时询问他。没有开枪权时不询问 | 不因「未被询问」而收到「你被毒了」的私密通知 |
| 平民 | 无额外私密信息 | 上表所有私密项 |

警长不因为持有警徽而获得任何隐藏信息。警徽只带来权重、发言方向和移交权。

### 9.4 公开文案边界

天亮公开文案只允许：

- `昨夜平安，无人出局。`
- `昨夜出局：8号、10号。`（座位号升序）

禁止出现：被刀、被毒、被守、被救、同守同救、查验、狼队、药瓶。

这些行动的公开文案是固定的：

- 放逐：`7号被投票放逐。`
- 自爆：`4号自爆出局。`
- 开枪：`7号开枪，2号出局。` 此句公开 7 号是猎人。
- 放弃开枪：没有公开文案。

### 9.5 终局复盘

分出胜负或流局后，复盘使用两份已经存在的材料。一份是全程公开日志，里面有每个人说过的发言和遗言。另一份是此时追加的全体可见复盘事件：每个座位的身份、每个夜晚的刀口、守护、是否救人、毒药目标、每次查验结果、警徽沿革，以及谁开枪带走了谁。第 2 夜之后的夜间出局者，以及这些夜里猎人开枪带走的人，都没有遗言，复盘时看的就是这份终局公开。复盘事件不追溯修改夜里那些私密事件的受众。

复盘不包含密钥、提示词和模型原文思维过程。提示词审计留在房主的调用日志里。

### 9.6 出局座位与观战

出局座位的页面分成两块：已经获得的私密记录（冻结），以及持续更新的公开日志。  
观战凭证只有公开投影。  
房主若同时占用一个座位，玩家页使用座位凭证，上帝页使用房主凭证。同一个座位接口不能顺便带回全量状态。

## 10. 发言顺序

### 10.1 定义

`nextAlive(from, direction)`：从 `from` 的顺时针或逆时针方向找下一名存活玩家，跳过出局者，编号在 1 与 N 之间折返。

死亡锚点：

1. 昨夜狼刀目标确实出局：锚点是该刀口。
2. 否则昨夜只有毒药出局者：锚点是该出局者。
3. 昨夜多人时，锚点仍只取上一规则选出的那一个，不随机改选另一个死者。

### 10.2 决定顺序

进入白天发言前，按下面第一条满足的规则决定，并向全体公告完整顺序。

1. **场上有警长**：由警长选择顺时针或逆时针。第一名发言者是 `nextAlive(警长, 方向)`。顺序绕环一圈，警长最后发言。
2. **没有警长，且本段存在死亡锚点**：法官用随机流决定方向。第一名是 `nextAlive(锚点, 方向)`。锚点本人已出局，不发言。
3. **没有警长，且平安**：随机流在存活玩家中指定第一名，并决定方向，再按方向绕环。

第一天既有首夜死者又选出了警长时，讨论发言使用警长规则。首夜死者已经在此之前发表遗言，不再充当讨论起点。第 2 天及以后，夜里出局的人没有遗言。

警长在选择方向前，页面和模型都要看到两种方向将产生的完整顺序。

### 10.3 其他发言顺序

- 竞选发言：只包含仍在竞选的玩家。随机流决定起点和方向，沿环寻找下一名候选人。
- PK 发言：只包含平票玩家。沿用本白天已经宣布的方向；若还没有方向，按座位号升序。
- 遗言：按座位号升序，不使用警长方向。

### 10.4 示例

存活玩家 1、2、3、6、8。昨夜锚点是 5 号，方向顺时针。发言顺序为 6、8、1、2、3。

警长是 3 号，选择顺时针，存活同上。发言顺序为 6、8、1、2、3。3 号最后。

## 11. 夜间结算

### 11.1 不变量

女巫收到刀口，仅发生在她当晚仍持有解药时。内容等于狼人阶段合并出来的原始目标，不包含守卫结果。空刀且解药还在时，只告诉她今晚没有落刀。解药已经用掉之后，不向她发送刀口，也不发送「没有落刀」；她的投影里不能出现可用来反推刀口的空字段。

结算在守卫、落刀、查验、用药都结束后一次完成。查验不改变生死。空守视为当晚没有守护。

### 11.2 合法行动才进入结算

下列情况在提交时拒绝，不会进入结算表：

- 解药目标不是当晚刀口，或没有刀口却选择救人。
- 自救不被本场规则允许。`first_night` 只允许第 1 夜自救，`always` 允许任意夜晚自救，`never` 始终拒绝。
- 同一晚 `save = true` 且毒药目标非空。
- 毒药目标是自己或已出局者。毒药目标可以是当晚刀口，无论女巫此刻看不看得到刀口。既救又毒仍然拒绝；毒刀口时解药必须是不用。
- 守护目标已出局，或不允许守自己时选择自己，或与上一夜实际守护的座位相同。空守没有目标，始终合法。
- 查验自己、查验已出局者、查验不存在的座位。
- 刀口不是存活玩家，且也不是空刀。规则不允许自刀时，刀口是狼人则拒绝。

被拒绝的守护不更新「上一夜守护座位」。成功守护某人后，下一晚不能再守该座位。成功空守后，上一夜守护座位记为空，下一晚没有禁守座位。例如第一夜守 3 号，第二夜不能守 3 号，但可以空守；第二夜空守之后，第三夜可以再守 3 号。

### 11.3 结算表

记刀口为 A。G 表示守卫守护了 A。S 表示女巫对 A 使用解药。B 表示另一名被毒的存活玩家。毒药目标写成 A，表示女巫毒的就是刀口。

| 编号 | 刀口 | 守住刀口 | 解药 | 毒药 | 出局 | 猎人在 A 时 | 猎人在被毒者时 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| N1 | 空 | — | 不能救 | 无 | 无人 | — | — |
| N2 | 空 | — | 不能救 | B | B | — | 不能开枪 |
| N3 | A | 否 | 否 | 无 | A | 能开枪 | — |
| N4 | A | 是 | 否 | 无 | 无人 | — | — |
| N5 | A | 否 | 是 | 无 | 无人 | — | — |
| N6 | A | 是 | 是 | 无 | A | 能开枪 | — |
| N7 | A | 否 | 否 | B | A 与 B | 能开枪 | 不能开枪 |
| N8 | A | 是 | 否 | B | B | — | 不能开枪 |
| N9 | A | 否 | 否 | A | A，死因含毒 | 不能开枪 | — |
| N10 | A | 是 | 否 | A | A，刀被守住，毒仍生效 | 不能开枪 | — |

N6 的死因是同守同救，不含毒，猎人能开枪。N7 中 A 若是猎人，可以开枪；B 已经同时出局，不能被选为开枪目标。N9、N10 是毒刀口：没被守住时死于含毒的出局，被守住时刀失效、人仍被毒出局。这两种情况下猎人若在 A，都不能开枪。解药早已用完时不能再救，死亡结果与表中「不用解药」的对应行相同；区别只是女巫看不到刀口。既救又毒在提交时拒绝，不进入本表。

药瓶在成功提交时消耗。被拒绝的提交不消耗。解救是否最终让目标活下来，都不返还解药。同守同救时解药已经用掉。

### 11.4 对女巫的话术

只有解药还在时才发送下面两句之一。

有刀口：`狼人今晚选择刀 X号。`  
空刀：`狼人今晚没有落刀。`  

禁止使用「X号已经死亡」「X号倒牌，即将出局」。解药已经用掉的夜晚，不发送这两句，也不用其他措辞转述刀口。

## 12. 放逐投票

### 12.1 投票

进入放逐后，自爆窗口关闭。每名存活玩家必须提交一名存活目标，规则允许投自己。票齐之前，投影里只有自己的选择。

票齐后公开：每个座位的目标、弃权、普通票与警长票。展示票数等于内部权重除以 2，因此会出现 1.5、2.5、3.5。

警长权重只在警长当前存活且本票属于放逐或放逐 PK 时使用。竞选警长的投票全部按普通票。

### 12.2 计票示例

这些例子是验收用例，内部权重写在括号里。

| 例子 | 票 | 结果 |
| --- | --- | --- |
| 两点压过一点五 | 警长单人投 3 号（3），两名玩家投 5 号（2+2） | 5 号出局 |
| 警长带两票 | 警长与另外两人投 3 号（3+2+2=7），三人投 5 号（2+2+2=6） | 3 号以 3.5 对 3 出局 |
| 警长没投到的两边打平 | 警长投 3 号（3），4 号得两票（4），5 号得两票（4） | 4 号与 5 号 PK，3 号不进入 PK |
| 无警长平票 | 4 号两票，5 号两票 | 4 号与 5 号 PK |

权重为 3 的警长票是半票，不可能与某一侧的整数普通票在总和上相等之后又和自己打成平票。平票发生在没有警长的时候，或发生在警长没有投票支持的那几名玩家之间。

### 12.3 平票 PK

1. 最高票人数不少于 2 名时，这几名玩家按第 10.3 节发言。
2. 其余存活玩家同时重投，目标必须是这几名玩家之一。被 PK 的玩家不能投票。警长若不在被 PK 之列，仍按 1.5 计。
3. 重投后再平，或没有任何有资格的投票者：平安日，无人出局，警徽不动。
4. PK 只进行一次。

超时未投票记弃权，公开出现在票型里，权重为 0。

## 13. 警长

仅当 `sheriff.enabled` 且进程走到第 1 天竞选时发生。

1. 每名存活玩家同时选择上警或不上警。已出局者不能上警。
2. 无人上警，或所有存活玩家都上警：本局没有警长。
3. 只剩一名候选人：直接当选，不投票。
4. 多名候选人按第 10.3 节发言。发言者可以在自己的竞选发言时退水。退水后可以参加投票。全部退水则没有警长。
5. 未继续竞选的存活玩家投票，权重都是 1。候选人不能投。目标必须是仍在竞选的玩家。
6. 平票则在平票者中 PK 发言后再投。再次平票：本局没有警长。不随机指定警长。
7. 当选结果公开。

警徽在此后的白天给持有者 1.5 的放逐权重，并让持有者选择发言方向。

持有者出局时，由他自己选择移交给一名当时仍存活的玩家，或撕掉。出局原因包括夜死、放逐、猎人开枪和自爆。系统不代替警长撕徽，也不限制移交目标的阵营，不能移交给自己。  
超时未选择：撕毁。

竞选尚未产生警长时发生自爆：竞选作废，本局不再补选。

## 14. 自爆

存活狼人拥有自爆工具。平民和神职没有。

### 14.1 窗口

`speaker_only`：轮到该狼人发言（白天发言、PK 发言、竞选发言）时，合法工具为「发言」或「自爆」，必须选一个。

`between_speeches`（默认）：在每一段白天发言、PK 发言、竞选发言、遗言开始之前，所有存活狼人同时做自爆决定。多人同时选择自爆时，座位号最小的一人自爆，其余选择自爆的狼人收到私密说明：这次由更小座位执行，自己仍然存活。选择不自爆的狼人不知道有谁尝试过。

遗言开始前的自爆不撤销已经生效的死亡和放逐。它会取消其他人尚未开始的遗言、尚未开始的投票和剩余发言。自爆者自己的遗言仍然要说。

进入放逐投票阶段后不能自爆。投票、PK 重投进行中不能自爆。

### 14.2 后果

自爆者立刻出局，公开文案标明自爆，因此公开他是狼人。他不能开枪。顺序固定为：

1. 若他持有警徽，由他自己选择移交或撕掉。
2. 他发表遗言。
3. 判定胜负。已经结束则进入复盘，不再入夜。
4. 尚未结束则取消当天剩余发言、未完成的竞选、尚未产生结果的放逐，进入下一夜。

## 15. 猎人

开枪是死亡职责，不是夜间技能。

可以开枪的死因：狼刀出局、放逐出局、同守同救出局。  
不能开枪的死因：任何包含毒药的出局。若同一人既被刀又被毒，按不能开枪。

被询问时可以指定一名当前存活玩家，或明确放弃。放弃没有公开文案。开枪的公开文案见第 9.4 节。

开枪目标在开枪当时必须存活，不能是自己，也不能是同一结算批次里已经出局的另一人。开枪造成的死亡可以再触发该死者的警徽职责。遗言是否给予开枪目标，只看第 6.5 节：第 1 夜猎人带走的人有遗言；第 2 夜及以后猎人在夜里带走的人没有遗言；白天被票出的猎人带走的人有遗言。本版没有第二名猎人，所以不会连锁开枪。

胜负检查在开枪之后，见第 7.5 节。

| `vote` | 有投票资格的存活玩家 | 放逐或 PK | `target` | 票齐后全体 |
| `sheriff_signup` | 存活玩家 | 上警 | `run` 布尔值 | 全部提交后全体 |
| `sheriff_withdraw` | 正在发言的候选人 | 竞选发言 | 无 | 全体 |
| `sheriff_vote` | 有资格的投票者 | 竞选投票或竞选 PK | `target` | 票齐后全体 |
| `set_speak_direction` | 存活警长 | 决定发言顺序 | `clockwise` 或 `counterclockwise` | 全体看到公告后的顺序 |
| `badge_dispose` | 持徽的出局警长 | 警徽职责 | `transfer` 加目标，或 `tear` | 全体 |

女巫用一次 `witch_act` 同时表达救与毒，避免两个工具先后提交造成双开。不用药是 `save=false` 且 `poisonTarget=null`。解药已用时，`save=true` 直接拒绝，且本阶段的投影里没有刀口。毒药也已用完时，不再进入女巫阶段，不提供 `witch_act`。

### 16.2 身份模块

狼人、平民、预言家、女巫、猎人、守卫从本版起就是独立模块，各自注册，不写进引擎的身份分支。新身份走同一条注册路径。

每个模块声明：

- 身份编号、阵营、是否计入神职、单局人数上限。
- 占用的夜间阶段；没有夜间行动则不占阶段。
- 工具及参数约束。
- 私密投影：哪些事件进入该座位的身份附录。
- 写进身份附录的技能说明。

引擎只做三件与身份有关的事：按版型的身份列表发牌，按 `nightOrder` 找到仍有存活持有者的阶段并调用对应模块，按模块声明统计神、民、狼。结算表里的守卫、毒药、解药由女巫模块和守卫模块提交行动，再由引擎的通用夜间结算消费这些行动。增加白痴、骑士、白狼王时，注册模块并把它放进新版型的身份列表，不改投影和模型适配器。

本版不实现下列身份，接口要容得下它们以后注册：

| 身份 | 将来要挂上的能力 |
| --- | --- |
| 白痴 | 被放逐时翻牌并可留在场上，之后失去投票权 |
| 骑士 | 白天决斗 |
| 白狼王 | 被放逐时带走一名玩家 |
| 隐狼等特殊狼 | 改变「谁算狼队友、查验显示什么」 |

这些身份的具体合法性等到做它们时另补规则，不在本版结算表里默认生效。

## 17. 上下文与提示词

每次决策的模型输入由四部分顺序组成：

1. 系统层：公共规则卡、身份附录、扮演风格、输出要求（必须调用且只调用一个合法工具，并在该座位的时限内返回）。
2. 公共日志：该座位投影中的公开事件，按序号排列。
3. 私密记录：该座位投影中的私密事件。
4. 当前任务：阶段名称、存活座位、合法工具。由适配器附带工具 Schema，不在正文里再描写一套参数。

发言内容作为引用数据放进日志，不作为系统指令。其他玩家的文字不能扩大本座位的工具或受众。

提示词禁止包含：其他座位的身份、未公开票、原始刀口（只有解药尚未使用的女巫在当晚除外）、查验（预言家除外）、用药（女巫除外）、守护（守卫除外）、狼队（狼人除外）、密钥、房主审计。解药已用的女巫，与平民一样看不到刀口。

当前任务若是同时行动，不包含本轮其他人尚未公开的选择。

## 18. 超时与托管

发言、遗言和狼队密谈限时 180 秒。放逐投票和警长投票限时 90 秒。其余行动沿用该座位的模型时限（默认 60 秒）或房间的真人行动时限（默认 90 秒）。模型在 HTTP 超时或两次非法提交后，真人在行动时限内没有提交，都走托管。托管是确定性的，并记一条只有行动者可见的说明。若托管产生公开行为，公开日志只显示该行为本身。

| 场景 | 托管结果 |
| --- | --- |
| 发言或遗言 | 公开文本：`我这轮过。` |
| 密谈 | 文本：`过。` |
| 落刀 | 该狼人这张票视为空刀 |
| 查验 | 本夜不查验 |
| 用药 | 不救不毒。解药还在时，刀口通知已经在阶段开始时写入；托管不再补发。解药已用时，托管也不写入刀口 |
| 守护 | 空守 |
| 开枪 | 放弃 |
| 自爆询问 | 不自爆 |
| 上警 | 不上警 |
| 竞选或放逐投票 | 弃权 |
| 发言方向 | 顺时针 |
| 警徽 | 撕毁 |
| 退水 | 不退水，并以 `我这轮过。` 完成竞选发言 |

守护超时按空守处理，并把上一夜守护对象记为空。查验超时不自动替预言家选人，避免系统替他产生一条他没有决定的查验。

## 19. 网页

### 19.1 页面

| 页面 | 使用者 | 内容 |
| --- | --- | --- |
| 创建页 | 房主 | 预设、可改开关、每个座位的真人或模型、连通性测试、开始 |
| 座位页 | 该座位凭证 | 规则卡、自己的身份、公共日志、私密记录、票型图、当前合法工具 |
| 观战页 | 观战凭证 | 只有公开日志和票型 |
| 上帝页 | 房主凭证 | 全部身份、结算明细、事件受众、每个座位实际发出的提示词、暂停和单步 |
| 复盘页 | 终局后的各类凭证 | 终局公开复盘。上帝页仍可查看调用审计 |

座位页的行动区由合法工具的 Schema 生成：选座位、布尔选择、短文本。不为每个工具写死一个独立页面。新增工具时，通用表单能提交；需要座位选择器的工具复用同一个选择器。

票型在公开后用图表展示谁投给谁，并标出 1.5。未公开前，座位页只显示「你已投票」或仍显示投票表单，不显示别人的票。

### 19.2 接口约束

对局接口带版本前缀。至少支持：创建房间、修改开局配置、开始、按凭证获取投影、提交行动、暂停、单步、订阅本凭证的更新、测试模型连通性。

订阅按凭证过滤。公开频道的推送里不出现上帝载荷。客户端收到更新后重新拉取自己的投影。

服务端在本地开发时用嵌入式数据库即可，要求一条命令启动，不强制单独安装数据库。存储通过会话层端口访问，引擎不出现 SQL。

### 19.3 客户端以后怎么接

桌面端、机器人或其他版本只做三件事：用凭证拿投影、展示、提交工具调用。它们不复制结算代码。若某次改动需要在两个客户端各写一遍规则，说明规则放错了层。

## 20. 数据与审计

需要持久化的内容：

- 房间、锁定的规则对象、随机种子、座位控制者和模型配置（密钥加密）。
- 房主凭证与每个座位的凭证、一个观战凭证。
- 事件日志。
- 模型调用审计：座位、时间、模型名、请求中的投影版本、返回的工具调用、成功或失败。审计不保存密钥。

审计只有房主能读，用于核对「模型是不是看到了不该看的东西」。玩家接口不返回审计。

导出的对局记录分两种：公开记录（终局玩家也能拿到的投影），上帝记录（事件全量，不含密钥）。两种都由投影或事件生成，不手工整理。

## 22. 与现有原型的关系

工作区中的 `modular-ai-werewolf-system.zip` 是一份早期网页原型。本文是后续实现的基线。原型里已经触到的方向可以保留：座位独立模型配置、日志带可见性、夜晚先收集行动再结算、屠边、同守同救、守卫不连守。

原型还没有成为本需求的实现，差距至少包括：

| 原型现状 | 本文要求 |
| --- | --- |
| 规则主要写在网页接口里 | 规则在纯引擎中，网页只提交行动 |
| 模型用自然语言做决定，再由解析器猜测 | 只接受当前合法的工具调用 |
| 没有警长、自爆、遗言、PK | 第 10–15 章全部纳入同一阶段机 |
| 发言顺序含随机打乱 | 使用第 10 章的锚点、方向和警长归票 |
| 可见性是日志字段，提示词另拼字符串 | 座位投影同时驱动网页和提示词 |
| 密钥明文放在座位记录里 | 加密，且不进入投影和日志 |

实现时以本文验收表为准，不逐行移植原型里的流程代码。

## 23. 维护约定

- 改技能、发言、票数或可见性时，先改本文相应章节和规则对象，再改引擎测试，最后改网页文案。
- 公开规则卡只有一个生成函数。发现提示词和网页规则不一致，视为缺陷。
- 新身份以模块接入。若必须修改投影类型或行动提交通道才能加上一个身份，先回到第 16.2 节补接口，再写该身份。
- 模型只能增加「会说话的座位」。它不能成为第二个法官。
