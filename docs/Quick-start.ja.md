# クイックスタート

[简体中文（README）](../README.md) · [English](Quick-start.en.md) · 日本語

このガイドでは、手元のパソコンでゲームを起動し、部屋を設定してプレイヤーを招待します。このリポジトリはアプリのソースを提供します。以下の手順でホスト型のゲームサービスに接続するわけではありません。

## 1. インストールして起動する

**Node.js 22.12 以降**と **pnpm** を用意します。pnpm が使えない場合は、次のコマンドでインストールできます。

```bash
npm install -g pnpm
```

リポジトリを取得し、開発モードを起動します。

```bash
git clone https://github.com/ZhiqiangBao/ai-werewolf.git
cd ai-werewolf
pnpm install
pnpm dev
```

ブラウザーで **http://127.0.0.1:5173/** を開きます。開発ページと API は同じローカルサービスを使います。

本番モードで起動する場合は、先に `pnpm build`、続けて `pnpm start` を実行します。Web のソースを変更したら再ビルドし、サーバーのソースを変更したら再起動してください。

## 2. 画面の言語を選ぶ

ホームまたは部屋の画面で言語を選びます。画面の言語は現在のブラウザーに保存されます。これは個人の設定であり、部屋の対局言語は変更しません。

## 3. 部屋を作り、対局言語を選ぶ

ホームで **対局を作成** を選び、部屋の設定を行います。

1. 版型を選び、ルールを確認します。
2. **対局の言語**を選びます。新しい部屋は簡体字中国語（`zh-CN`）が初期値で、英語（`en`）と日本語（`ja`）も選べます。この言語はルール、司会のシステムメッセージ、モデルに求める発話言語に使われ、ゲーム開始後は固定されます。
3. 各席をシミュレーションプレイヤー、モデル操作、または人間プレイヤーに設定します。

シミュレーションプレイヤーは外部モデルサービスや API キーなしで動作します。実際のモデルを使う場合は、プロトコル、エンドポイント、モデル名、API キーを指定してプロジェクトのモデルライブラリに追加し、席に割り当てて **接続テスト** を行います。失敗した場合は、選択したプロトコルに合うエンドポイントか、モデル名とキーが正しいか確認します。

## 4. 人間プレイヤーを招待して開始する

設定画面の **招待リンク** を開きます。ホスト用リンクは自分で保管してください。各人間プレイヤーには担当する席のリンクを渡し、観戦者には観戦リンクを渡します。リンクごとに閲覧できる範囲が異なるため、対象者にだけ共有してください。

各人間プレイヤーは自分の席のリンクを開き、名前を入力して準備完了にします。人間席がすべて準備でき、設定の確認項目が残っていなければ、ホストがゲームを開始できます。役職の配布と進行はルールエンジンが行います。

## 5. プレイして記録を確認する

席の画面には現在の課題と許可された行動が表示されます。選択可能な行動と対象を選び、自分の言葉で発言を入力して送信します。プレイヤーが書いた発言・計画・主張は、送信時の言語と文面のまま保存され、自動翻訳されません。画面の言語は操作部品やラベルに適用され、ルールとシステムメッセージは部屋の対局言語に従います。モデルにもその言語で話すよう求めますが、常に従うとは限りません。

ホスト画面ではゲーム全体を確認できます。席の画面にはその席に許可された情報が表示され、観戦者には公開情報だけが表示されます。イベントログから、自分の視点で見られるメッセージと結果を確認できます。

リンクを開いたときに違う画面が表示された場合は、ホストに正しいホスト・席・観戦リンクを送り直してもらいます。人間プレイヤーが行動できない場合は、ゲームが開始済みか、担当席のリンクを開いているか確認してください。部屋を開始できない場合は、画面に表示された設定確認項目を解消します。

## 言語と保存済みの記録

画面の言語を変更しても部屋の設定や履歴は変わりません。開始済みの部屋は対局言語を保持します。言語情報のない旧部屋は `zh-CN` として扱います。プレイヤーの発言は送信されたまま保存し、確実に再構成できない履歴を新しい言語に合わせて書き換えることはありません。動画出力は従来のロケール用インターフェースとの互換性を保ちますが、字幕、音声、過去の文章がすべてローカライズされていることを意味しません。
