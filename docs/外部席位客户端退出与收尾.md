# 外部席位客户端退出与收尾

日期：2026-11-03。对应独立客户端 `agent-v0.1.2`。

## 原有缺口

此前 `wait` 只在整局结束时返回停止状态，外部客户端没有读取引擎已存在的本席职责完成判断；后台等待及网络重试也没有整体时限、父进程退出检测和统一取消路径。上一版的入座、提交、语言与断线恢复测试不能证明退出后的进程和连接已清理，缺少这部分验收。

## 实际行为

服务端本席投影新增可选 `me.canStop`，直接复用引擎已有的 `seatTasksComplete`。它检查尚未展开或排队的死亡职责、当前决策、警徽、同批遗言和扩展能力职责。只有当前没有任务不能据此退出。该字段只给获授权的本席投影，不写入公开事件，不向旁观者分发。

客户端收到完成信号且没有未提交任务或可用中断工具时，返回退出码 `0` 并说明本席参与结束；不把本席结束说成整局结束。已经读过同一完成状态后再运行 `wait`，也会立即退出。旧服务端没有字段时解释为未知，保留有界等待直到终局。

每次 `wait` 的整体时限为 60 秒，包含首个 HTTP 请求、SSE、轮询和重试。到期关闭连接并返回待处理状态，由仍在运行的 agent 决定是否继续。可用 `--max-wait-ms` 缩短至 100–60000 毫秒；生命周期测试使用短时限，不冒称实等了默认 60 秒。

命令监听取消、父进程退出和 IPC 断开，并向在途 HTTP、SSE、轮询和行动开放等待传递取消。父进程退出或收到取消时使用退出码 `44`，玩家指引要求停止而不自动重新启动。行动尚未开放时失去父进程，不会随后再提交行动。其他命令也有整体时限和单次请求时限。

父进程是启动命令的进程，不保证等同于 agent 应用。宿主在 agent 退出后仍保留父进程时，无法仅据父 PID 识别 agent 状态；当前 `wait` 的 60 秒整体时限负责结束这次等待。游戏服务独立运行，不随一个玩家退出而关闭。

## 验证

- 客户端全部测试及打包测试共 **25 项通过**，其中 9 项专门验证生命周期：安静 SSE 到期、首个 HTTP 响应挂起、已读完成状态退出、空菜单等待后续完成信号、保留未交任务、旧服务端兼容、取消后断开连接、真实父进程结束后的分离子进程退出、父进程结束后不再延迟 POST。
- 测试实际启动父子进程及本机 HTTP/SSE 服务，核对进程退出、连接归零和读取游标不被提前消费；没有只检查提示文字或返回码。

- HTTP、房间兼容和上下文边界 **5 文件、22 项通过**。旧黄金摘要只显式排除新增 `canStop` 元数据，原事件、行动、消息、计时的摘要没有重录。
