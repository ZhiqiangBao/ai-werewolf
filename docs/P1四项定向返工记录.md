<a id="m-01"></a>

### M-01：独立绑定脱敏范围

实现位置：[范围定义与分类](../packages/session/src/model-retirement.ts#L3)、[维护目标](../packages/session/src/model-maintenance.ts#L28)、[绑定和录入](../packages/session/src/model-maintenance.ts#L82)、[持久化](../packages/session/src/model-library.ts#L183)、[本机命令](../scripts/model-maintenance.ts#L10)。

维护目标在模型条目上独立保存 `maintenanceScope`，证据另行声明自身范围；不从证据反向设置目标，不根据原始密钥猜测账号。账号维度对应一个账号／套餐组合，区域是独立维度。两者均采用 v1 的三种明确形式：

| 表达 | 含义 | 匹配规则 |
| --- | --- | --- |
| `{ "kind": "specific", "id": "随机 UUID v4" }` | 一个确定的账号／套餐组合或区域 | 仅匹配相同维度的相同具体标识 |
| `{ "kind": "global" }` | 来源明确适用于所有该维度范围 | 覆盖具体、全局或未知目标；另一维度仍须匹配 |
| `{ "kind": "unknown" }` | 依据不足，尚不能确认 | 作为证据时始终不能确证，包括 unknown 与 unknown |

`routeId` 仍须相同，模型／提供方／协议／时效等旧条件仍检查。未知或不匹配的结构化证据可以留存待复核，但分类为 unknown，不误判停供。新入口拒绝省略维度、旧字符串、非 UUID 具体标识、额外范围字段和额外顶层字段；`reasonCode` 仅允许短代码。

**标识来源边界：** 使用 `node --import tsx scripts/model-maintenance.ts scope-id` 生成新的随机标识；此入口不访问模型库，不接收账号、套餐、区域或密钥参数。维护者在私下核对标识所代表的范围，再分别为目标和证据赋值。不得使用原始账号、密钥或其散列作为标识。UUID 格式校验不能证明输入是随机生成，也不能自动核实来源声明；来源摘要及公开链接仍须人工脱敏。没有宣称自动识别真实账号权限。

停服并按原租约流程维护时，`scope <modelId> <revision> <作用域JSON路径> --old-server-stopped` 设置目标范围；JSON 为 `{version:1,accountScope:...,region:...}`。随后重新 preview 取得 revision，再以 `record` 录入独立证据。证据 scope 在上述结构上增加 preview 给出的 routeId。

**旧记录规则：** 缺字段、无 v1 版本或旧字符串范围的证据原样保留，解释为无法确证，不自动升级为 global。preview 不回写旧库；设置新目标范围不补写旧证据。证据集合继续保守处理：任一旧、过期、不符或冲突项都会使集合为 unknown，新证据不会静默覆盖旧记录。归档和恢复仍由授权维护命令决定，不因分类变化自动撤销已授权维护。别名条目各自保留原始维护范围和证据，不因归并把来源范围当作目标范围。

[模型维护测试](../packages/session/test/model-maintenance.test.ts#L27)共 21 项通过，其中 6 项为本轮新增：账号／套餐匹配、账号不符、区域不符、两个未知维度、明确全局、旧省略与旧字符串兼容、修改目标后不重新解释原证据、陈旧 revision、失败落盘，以及真实本机 CLI 的绑定／录入／非零拒绝。既有密钥、别名、旧房间和归档恢复断言保留并通过。只使用合成库；未读取或修改真实模型库、房间、密钥和备份，未重探测模型。

### P-01：从冻结输入独立重建工作分母

实现位置：[重建器](../packages/session/src/experiments/passive-plan.ts#L16)、[完整性门禁](../packages/session/src/experiments/passive-validator.ts#L19)、[独立账本读取](../packages/session/src/experiments/passive-budget.ts#L12)、[采集调用](../packages/session/src/experiments/passive-loopback.ts#L112)。

重建器仅接收冻结 config／frames，不读取生产者 expected／trace；从两段、房间、席位、任务变化和故障尝试独立生成身份、投影哈希、history、HTTP 状态及原生回执顺序。验收器双向核对声明与计划、四端 trace、必要字段、预算上限及独立账本。源码 pin 与 expectedHash 继续核对，但不再充当工作分母。

[联合删项夹具](../packages/session/test/passive-validator.test.ts#L53)完整删除一项 expected 及其 client/server start/end，再重算 expectedHash／reserved，仍因独立计划失败；[归档级夹具](../packages/session/test/passive-revalidation.test.ts#L62)进一步重打包、更新 proof 和合成账本，CLI 仍非零。缺失、额外、重复、跨运行、必需字段、原生回执、history、时间顺序及预算损坏门禁保留。另以三协议 × 单／双桌 × 无故障／429／503 的计划对照检查重建器，无 HTTP 请求。

统一自验还用外审索引独立清点 34 组原始包／manifest，并比对 68 个文件的字节和 SHA-256，避免目录中整组材料消失后只检查剩余项。该清点与窗口内部任务重建分别执行。

### P-02：续跑摘要绑定包内内容

实现位置：[有界归档读取](../packages/session/src/experiments/passive-archive.ts#L34)、[共同验收门禁](../packages/session/src/experiments/passive-revalidation.ts#L50)、[续跑入口](../scripts/passive-experiment.ts#L53)、[只读补验](../scripts/passive-revalidate.ts#L7)。

先校验压缩／解压字节及 proof，再有界读取并重新校验用于解析的字节。JSON 摘要上限 1 MiB，归档压缩和解压上限各 128 MiB，流读取块 64 KiB；拒绝符号链接、异常大小、非法 UTF-8 或 JSON。比较文件场景身份、run、源码／输入 pin、sourceEntries、环境、完整配置、status、errors、failure、expectedHash、计数和 segments，并进入 P-01 的独立计划与账本核验。续跑和新窗口返回成功前使用同一门禁。

[损坏夹具](../packages/session/test/passive-revalidation.test.ts#L74)覆盖仅修改 manifest 分段指标、包内失败而 manifest 声称 complete／空 errors、改变输入或源码成员后重打包、预算不符、超限 proof；拒绝结果和 CLI 非零均有断言。保留失败、损坏或版本不兼容材料，不覆盖、不删除、不转为成功续跑。

最早失败预检使用无源码前缀的历史 run `preflight`。显式 `--legacy-failed true` 仅检查该失败格式，仍核对源码／输入、摘要、计划及原始账本，输出 `recorded_failure` 且始终退出 1；常规续跑拒绝该材料。新验收器的提交和哈希独立记录，未将其冒充旧采集源码。

### V-01：逐桌夹具与历史接受决定

历史旧脚本和两批三语输出全部保留。当时每批同时三个 running 房间，全部 human、逐语言请求、没有模型调度；不能写成全程遵守两桌约定。用户在本次会话了解情况后明确回复：**“不用，接受这次偏离。”** 接受决定不改写历史，也不等于独立复审通过。

后续入口为 [scripts/client-server-check.mjs](../scripts/client-server-check.mjs)，旧 data 目录脚本只作历史证据。新入口按语言逐桌创建、验证、释放：每个内存／隔离存储只含一桌，管理器持久收尾、服务正常退出和写者租约释放均确认后，才创建下一语房间；上限为 1，满足最多 2 桌约定。冻结房间文件保留，文件中的历史 running 状态不当作仍有活跃所有者。创建或验证失败也清理所有者，释放失败则保留材料并停止，不进入下一桌。

[生命周期测试](../scripts/test/client-server-fixture-lifecycle.test.mjs)7 项全部通过，覆盖顺序、创建／验证失败、释放失败、真实记录计数超限、成功释放后保留存储、租约未释放时停止。新联调脚本仅做语法和离线生命周期测试，本轮未启动服务或重新运行历史联调。
