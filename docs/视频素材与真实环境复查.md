在这次快照中，78 次与 26 次带新审计标记的正式行动请求，其最后一条用户消息均没有直接禁止调用工具。历史里的禁止句不能一概判错：它们可能是以前的旁听轮次。问题集中在过期问话被重播、诊断重复进入历史，以及用上一轮相同尾句推断本轮许可。

本轮修正：

- 普通旁听误调用只作为本次工具反馈返回；只有该次请求发起时已允许、返回时仍合法的打断技能交给引擎执行。
- 引擎拒绝和托管诊断不会再被追加为新的法官发言，引擎原始记录与模型审计仍可追查。
- 过期的行动问话不再送入上下文；旧存档中合并了问话的刀口等事件，在旁听时只还原事实。
- 行动许可绑定当前决策。上一轮相同的“可以使用工具”尾句不能授权下一轮。
- 如果旧存档已有当前许可，但末尾又出现了禁止提示，追加当前问话恢复许可，不改写已缓存的历史前缀。

### 8号警徽为何交给5号

房间 `c55d6d2c4d` 的审计 #681（决策 `d1jo7mt1m6w31u`）是 8 号 qwen3.7-flash 的首次正式行动，耗时 24.064 秒、提交成功。该次接口回复的思考末尾是“决定：移交给12号”，但流式拼接后的工具调用为 `badge_dispose`，参数字符串为 `{"target": "5"}`。送入引擎的参数同样是 5，事件 #162 因此记录“8号将警徽移交给5号”。没有发生超时托管；警徽托管规则是撕毁，不是自动选择5号。

因此可确认的边界是：接口输出的思考与工具参数不一致，本地没有将12换算或改写为5。字符串“5”会被兼容性规范化为数字5，座位号保持不变。仅凭当前客户端审计，不能进一步区分原模型生成不一致与服务商工具调用转换的问题。

随后 #691 是旁听请求再次尝试移交给11号，被拒绝，没有改变已经交给5号的事实。这类旁听误调用在本轮修复后只返回私有反馈，不会再变成法官播报。

## 离线制作素材

制作顺序是：事实记录 → 配音文案 → 每段音频 → 字幕与时长 → 重建画面 → 合成视频。模型请求的等待时间不进入成片时间，不需要实时录屏。

房主的“导出视频剪辑稿”在浏览器处理已经授权的上帝投影；本地也可以运行：

```bash
node --import tsx packages/session/scripts/export-video.ts --room=ROOM_ID
```

格式 `werewolf-video-script` 第 1 版包括：

- `cast`：座位、名称、底牌、阵营和稳定的 `voiceKey`。
- `chapters`：按昼夜分章的配音条目，提供说话者、原文、可见范围、票型等数据和 `sourceSeq`。法官使用 `judge` 配音标识，每个座位使用独立标识。
- `events`：给画面重建的事实流。已合并播报的出局等事实以及夜间结算仍保留，`spoken=false` 表示不重复配音。
- `timing=untimed`：暂不伪造时间码；配音完成后按实际音频时长安排停顿、转场和字幕。

剪辑稿保存在 `data/exports/`。它不含 Agent 问话、技术错误、密钥、凭证或模型私下推理。原始上帝导出继续用于完整审计。

当前已完成记录筛选、剪辑稿和事实流导出；下一步应接入可选 TTS、音频缓存与字幕对齐，再构建离线播放器和渲染器。渲染器从事实更新座位存活、警长、身份和夜间技能卡片，从音频驱动镜头时长，支持暂停、重试和复用已生成音频。
