# 四项评估的验收设计与独立审查

日期：2026-11-03。范围：`ARCH-EVENT-STORE`、`ARCH-HTTP-FACTORY`、`AUDIO-LIFECYCLE`、`MODEL-QUALITY`。

本文先记录实施前的验收设计与源码事实，随后按实际产物追加独立审查。本文不是另一份待办清单；未解决事项只在[待解决问题](../待解决问题.md)维护。评估完成、实验原型通过、生产能力实现、真实服务测量分别表述，不能互相替代。

## 基线与证据层级

首次检查工作区时只有 `.gitignore` 存在未提交改动，属于其他任务，本审查不修改。审查没有读取密钥、调用模型或 TTS，也没有操作浏览器；真实实验由主代理统一安排。

| 证据 | 可支持的结论 | 不可支持的结论 |
| --- | --- | --- |
| 源码与接口契约 | 当前边界、缺失字段、明确分支行为 | 真实延迟、生产成功率、模型能力提升 |
| 本地注入与合成记录 | 指定故障的确定性行为、可重现的成本比较 | 外部服务取消计费、真实模型质量 |
| 实际 HTTP / 子进程 | 当前环境网络路径和进程生命周期 | 断电耐久性、全部操作系统行为 |
| 真实模型 / TTS 样本 | 指定日期、版本、协议、配置及样本的观测结果 | 未测试版本、全局统计优势、提供方计费撤销 |

所有测量应记录环境、提交或源码摘要、命令、数据规模、样本数、失败数和时间定义；不得把失败样本静默剔除。缓存命中与未命中分开，不用少量样本的分位数制造统计确定性。

## ARCH-EVENT-STORE

### 已核对的边界

[`RoomRecord`](../../packages/session/src/store.ts) 除引擎状态、事件与行动外，还包含席位配置、访问凭证、各席独立对话、思考、截止时间、暂停余量和广播游标。`FileStore.save` 将房间主体与逐席对话分开写入；审计另外追加。仅重放引擎事件无法恢复完整房间。现行保存还有 [`RoomPersistenceService`](../../packages/session/src/room-persistence.ts) 的 300ms 合并窗口。

[`RoomViewService.signature`](../../packages/session/src/room-view.ts) 是按观看者构造投影后序列化的变更签名，不等同于持久化记录的加密校验和。测量应明确区分投影签名、日志校验和及状态序列化。

### 原型与测量验收

- 单写者日志每条绑定版本、房间标识、连续序号和校验和；返回提交成功前完成文件同步。快照绑定完整状态和最后序号，旧日志保留时也验证快照与日志对应关系。
- 补丁处理对象字段删除、数组和各类会话元数据。用独立构造的完整 `RoomRecord` 对恢复结果做深等值核对，再分别核对公开及上帝导出；导出相等本身不足以证明完整状态一致。
- 验证完成同步但尚未回执、已回执、尾行只写入一部分三种进程终止边界。同步后但未收到回执的记录可以恢复存在，报告必须明确该不确定区间；重试不能重复应用同一已提交序号。
- 半条尾行只能在末端修剪；修剪后继续追加，再恢复仍须正确。完整坏行、序号断裂、串房记录应拒绝加载，不能当作可忽略尾部。
- 快照写入中断时恢复到合法快照加日志；日志保留的原型不宣称验证了日志压缩或删除。进程强杀不等于断电测试，文件同步不能扩大为跨文件、外部模型请求与行动提交的完整事务保证。
- 同一合成工作负载比较写入、完整恢复、投影签名、磁盘最终占用和累计写入量。日志与快照全部计入存储量；`FileStore` 无逐次同步且有 300ms 合并，必须说明耐久性契约不同，不能直接把差值说成生产吞吐收益。

归档结论可以是“测量完成，暂不迁移”，只要数据及故障边界充分。原型通过不自动构成现行文件存储已被替换或现行恢复缺口已修复。

## ARCH-HTTP-FACTORY

### 已核对的边界

[`main.ts`](../../apps/server/src/main.ts) 在顶层取得目录租约、读取服务配置、创建管理器和语音服务，注册信号并监听端口。路由还闭包引用 `stopping`、SSE 集合、服务器地址与前端中间件。仅将 `createServer()` 包进函数不够。

### 提取验收

- 实例工厂接受管理器及语音依赖；管理器已有存储注入能力，可通过真实 `RoomManager + MemoryStore` 验证。生产入口保留目录租约、配置读取、信号、`listen` 和恢复调度，导入工厂不得产生这些副作用。
- 同进程两个实例拥有独立停止标记、SSE 集合与前端处理，关闭其中一个不影响另一个。依赖的创建与释放责任写清，避免注入管理器被隐式重复释放。
- 请求体覆盖空、恰好 1,000,000 字节、超出一个字节、无效 JSON、数组、`null`、中途断连，以及读取请求体期间进入关闭状态。状态码、错误结构和现有鉴权优先级保持一致。
- 实际 HTTP 验证 SSE 客户端断开与服务关闭两条路径；订阅恰好释放一次，心跳与监听器清理，存量响应结束。额外的事件模拟可精确核对资源计数，但不能替代真实连接。
- 核对导出响应头、授权投影、TTS 事件读取、静态页面与开发中间件、邀请地址使用当前实例地址；已有 HTTP 和进程关闭测试作为回归。

已有 [`attachEventStream`](../../apps/server/src/event-stream.ts) 和 shutdown 测试可复用。若只写独立原型而未用于生产入口，应归档为可行性评估，不称路由提取已生产接入。

## AUDIO-LIFECYCLE

### 已核对的边界

[`SpeechService`](../../packages/session/src/speech.ts) 具备缓存、同内容合并、两路并发预算及提供方超时，返回完整字节。HTTP 路由等待 `render` 完成后发送音频；[`serverSpeechOutput`](../../apps/web/src/speech-output.ts) 还要等待完整 `response.blob()` 才触发 `ready`。因此当前页面没有边生成边播放的首段接口。

页面停止会取消客户端 `fetch`、暂停播放器并释放对象 URL；`SpeechService.render` 未接受该客户端信号，不能由此推断上游合成停止，更不能推断计费撤销。服务端超时信号与客户离开是不同事件。

浏览器音色是页面全局选择；服务端音色属于所选来源。现有席位配置没有逐席音色映射，TTS 请求以已授权的 `eventSeq` 查找发言。未来逐席映射应由已授权事件的发言席位选取，不能接受客户端任意文本或隐蔽身份提示来决定音色。

在初始源码中，[`useSpeechPlayback`](../../apps/web/src/components/SpeechPlayback.tsx) 的失败回调清空当前项与整个队列，而 [`SpeechCursor`](../../apps/web/src/speech.ts) 已将这些事件标为见过；重新开启只从最新发言开始，故失败确实存在丢失待播项的路径。底层播放器停止测试不能证明 hook 队列没有丢失。该事实是否已修复以本轮最终产物为准。

### 测量与行为验收

| 时刻 | 定义 |
| --- | --- |
| 请求开始 | 客户端提交或直接适配器开始；两种起点分开记录 |
| 提供方首音频字节 | 首次获取真实音频负载；JSON 元数据、音频 URL 和响应头不算音频 |
| 提供方完整音频 | 完整负载可校验；二次下载耗时计入 |
| 应用音频就绪 | 当前应用完整音频可交给播放设备；不可称真实听到声音 |
| 播放开始 | 浏览器实际播放事件；若未测浏览器，不填写推算值 |

- 真实 TTS 使用固定短、长文本，记录文本摘要、字数、来源、模型与音色、格式、音频长度、缓存状态和实际失败。仅测一次时标为个例，不宣称稳定延迟。
- 用受控提供方观测停止前后是否仍合成，分别报告页面停止、HTTP 取消、上游收到信号、上游完成四层；没有账单证据时只写计费未知。
- 失败场景包括首条失败时后面已有两条、失败后有新事件、来源失效、暂停期间返回、旧请求晚到。确认失败项及后续项可按明确操作重试，或将真实缺口记录到唯一清单。用户主动停止或关闭自动朗读的弃队列语义与意外失败分开。
- 对慢 TTS 与失败检查后端行动、投影和截止时间继续推进。此结果只能证明语音请求不阻塞后端；若 deadline 在听音频时已开始，不能写成“听完才计时”或“没有占用用户可决策时间”。

逐席音色、流式播放、上游取消是否实施由测量后的产品决定明确记录，不能用“评估完成”替代其能力验收。

## MODEL-QUALITY

### 对照与评分验收

固定合成局面、座位可见投影、工具菜单、消息顺序、具体模型及服务协议、生成参数和超时。保存不含凭证的输入与输出摘要，固定的合成内容可随证据提交；真实服务配置、密钥、URL 中的凭证不进入报告。

最小可解释设计包含两个成对对照：

1. 固定同一受支持的思考档位，只变提示版本；当前提示与删除指定来源边界段的消融版必须精确记下差异，不能把消融版冒称某段历史运行的真实提示。
2. 固定当前提示，只变该型号及该入口实际支持的思考配置。展示最终发给服务的参数，并检查响应或用量是否提供有效佐证；无佐证不能断言服务真正采用了该档位。

历史局面、同时变提示与思考、用不同模型比两个思考档、比较一个旁听输出和一个行动输出都不构成单因素对照。模型只有浮动别名且服务未返回版本时，应标“请求别名固定、供应商实际版本不可确认”，限制因果结论。

| 维度 | 可复核评分 | 不能据此加分 |
| --- | --- | --- |
| 事实记忆 | 正确记住引擎确认的死亡、警徽、查验等已知事实，区分未提供的信息 | 重述提示要求“记住事实” |
| 声称区分 | 将玩家自称、计划与伪造法官口吻维持为未经确认的陈述 | 仅说“我会辨别真假” |
| 行动合法性 | 实际工具、数量、参数、目标及当前任务均合法，最好经引擎执行验证 | 文字说要合法行动、解析器替模型修正 |
| 阵营行为 | 在预先设定的确定性局面中采取有可证目标的行动 | 对有争议策略按评审偏好扣分、要求狼人永远诚实 |

评分规则在看响应前定义。可用三类合成局面分别检验玩家伪造系统消息、私密事实与公开声称冲突、已知阵营目标的行动；若一个局面覆盖多个维度，仍须分别保留判定依据。对非客观的发言语义由盲化人工审阅，不能把字符串出现关键字等同于理解，也不能仅凭提示文本证明质量。

同局面多次重复，交错请求顺序，记录时延和有效回答数。失败、无工具、超时和输出截断保留在分母；若遇到失败后更改协议或参数，新增实验批次，不静默混入原对照。小样本相同分数应报告未观察到差异；得分提高也只限于被测任务，不推广为实局胜率提升。

### 首轮实验方案补充意见

主代理拟使用固定标识 `deepseek-v4-flash-0731`、Token Plan 的 Chat Completions，当前提示与来源边界段消融版在同一思考档比较，当前提示另作 `off / low / medium / high` 对照，分别映射关闭、`low / high / max`，各合成局面每格重复两次并交错请求。源码映射支持这些档位；实际接口支持和模型返回标识仍须由真实响应核实。

三种局面拟为预言家已查验但玩家伪造法官通知、村民面对他人互相声称查杀、狼人夜间选刀。建议保留真实生产工具与投影，不追加“在助手正文报告记忆和理由”这一非生产要求；只按工具参数与实际公开发言评分，没有表达的事实记忆标为无法判断，各局面不适用维度不算通过。

预言家可以策略性隐瞒查验，未公开已知事实不能直接扣记忆分；即使发言与事实冲突，也要区分战略表达和明确误认，有歧义时不能推断模型内在记忆。若狼人目标菜单已经只允许非狼，则选非狼只证明菜单约束下行为一致，不能独立证明阵营推理能力。固定输出上限可能影响深思考下工具生成，报告应保留 `finish_reason`、截断和实际用量，不能把额度耗尽全归因于纯能力差。每格两次属于探索性样本，不支持显著性或实局胜率推断。

### 事件原型发现与整改复核

独立审查复现了初版 `commit` 的引用别名缺陷：调用者提交 `{ set: { deadlines: { test: 100 } } }` 后修改同一嵌套对象为 `999`，内存 `value()` 变为 `999`，日志恢复仍为 `100`；随后写快照还会保存未提交的修改。这一差异不能由原有五项测试排除。

实施代理已在提交入口复制为 `ownedPatch`，应用、序列化、校验和和幂等比较都使用该副本；新增回归覆盖提交后修改嵌套对象及追加消息，核对内存、日志恢复和快照一致。独立复跑六项原型测试通过，测量已重跑，现有测量 JSON 中五个源码 SHA-256 全部与最终文件匹配。该发现已在本轮解决，不作为新的活动问题保留。

审查还核对了日志连续序号、房间绑定、前条哈希与快照末记录绑定、坏完整行拒绝、尾部修剪后续写、稳定 ID 去重，以及同步完成后回执前／后的子进程强杀测试。报告正确说明未确认记录可能已存在、初始化和设备断电未验证、没有日志裁剪。报告对 300ms 合并保存与逐条同步的契约差异、订阅通知不变状态时的签名测量、四房间顺序保存、仅两次快照均保留限制，没有把微基准扩写为生产加速比。

### HTTP 工厂复核

逐段核对原入口与 `http-server.ts`：路由、请求体读取、token 优先级、静态页面与错误响应沿用原实现；服务器地址、SSE 集合、停止标记和前端引用变为实例内部状态。`main.ts` 保留依赖创建、租约、信号、监听和房间恢复。`close` 仍使用既有关闭序列并复用首次关闭的 Promise；调用方仍负责一个实例的前端与注入管理器生命周期。

独立运行 `http-factory`、`shutdown`、`shutdown-integration`、`invite-network`、`human-http` 五个文件，共 20 项测试通过。首次运行因本机连接限制出现 `EACCES`，获准在本机运行后通过；没有把该环境失败当实现缺陷，也没有忽略或记为通过。测试覆盖两实例隔离、真实客户端断连、主动关闭存量 SSE、取消订阅一次、请求体边界及关闭中读取、静态页／中间件、鉴权和导出响应格式。

### 音频证据复核

核对真实测量脚本的起点、流消费探针、RIFF `data` 识别、完整服务返回、冷／热缓存隔离，以及现有 Qwen 下载和缓存路径。第二轮的首样本字节与服务就绪范围分别为 1.992–4.465 秒和 6.349–16.612 秒；这是指定四条样本的观测范围，不是分位数、浏览器延迟或可听时刻。第一轮仅记录传输首字节的限制已保留，不与第二轮冒充同一指标。

独立本地测试证实 HTTP 客户端断开后，提供方信号仍未取消，后台任务继续完成并可供后续相同请求复用缓存。并发、同文合并、失败释放槽位的测试通过。播放队列丢失仍是源码核对结论，未新增 React hook 实测；报告已明确这一点。后端 deadline 与音频未联动，报告没有声称不存在真人时间损失。
