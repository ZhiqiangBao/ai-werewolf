# ARCH-EVENT-STORE：离线可行性评估

测量日期：2026-11-03。结论：**暂维持现有存储，不据此启动生产迁移**。在本机合成的小补丁工作负载下，追加原型的单次提交有明显成本优势，但测试没有证明实际长局的保存频率、补丁大小或端到端瓶颈；恢复耗时相近，生产语义及故障安全仍需设计。数据支持继续按需观察，不足以证明迁移收益超过复杂度。

## 方法和边界

使用 `standard12`、固定种子 `event-store-001` 的引擎模拟局，产生 176 次合法行动、233 条事件；再给 12 席各添加 200 条每条约 256 个汉字的合成消息，构成人为放大的座位上下文。随后每次仅向一席追加一条合成消息，共 40 次；原型每 20 次写一次快照。该局是单种子加人为压力形状，并未验证其分布代表真实长局；消息、动作更新大小与比例也不是实测业务分布。无真实对话、密钥或外部调用。

本机 Windows x64、Node v24.18.1；单进程，同一工作区文件系统，未隔离系统负载。数字是一次运行内部样本，非跨机器统计；p95 为排序后取 `floor((n-1)*0.95)` 的观测值。完整汇总及代码 SHA-256 见 [测量 JSON](ARCH-EVENT-STORE测量.json)。

40 次立即保存共 661.177 ms；40 次原型提交和两次快照共 217.761 ms。这不是生产端到端加速比：当前普通变更通过 300 ms 定时器合并，退出和某些入口会立即 flush；原型逐条 fsync 并改变确认时点。实际保存次数及被合并比例未知。原型和当前存储的持久性承诺也不同。

测试末尾当前房间文件及座位文件共 2,124,184 字节；原型快照和**未裁剪**日志合计 2,104,225 字节，其中日志 43,478 字节。不含审计、目录项、临时文件峰值或旧版本备份。快照并不清理日志，日志随时间增长，不能将此称为压缩或证明长期节省空间。

## 状态与一致性

当前 `FileStore` 将 `RoomRecord` 主体写为房间 JSON，各席 `threads` 写为单独文件，审计另行追加；保存各文件不是一个跨文件事务，正常路径是临时文件后重命名，部分 Windows 错误会回退直接写。`RoomPersistence` 对常规变化按 300 ms 合并；恢复读取并迁移座位对话，运行层还会迁移状态、补 `heardSeq`，并在恢复启动时重建计时及推进。

引擎事件仅是游戏事实与投影的输入，并非整个房间的事件日志。完整恢复还涉及房间设置与凭证、座位独立对话及各协议原生续接、`thoughts`、`heardSeq`、行动、计时和暂停剩余时间、参与者状态，以及调度中的代数、请求、取消、外部调用与回执。内存中的订阅、inflight 控制器等不会直接保存；哪些可重建、哪些行动应重试必须逐项定义。审计与外部服务调用尤其不能假定与游戏状态原子提交。任何未来方案必须维护各席和受众边界并兼容旧存档。

## 原型和故障证据

实验代码在 `packages/session/scripts/event-store-prototype.ts`，完全未接生产。它在**单写者**假设下，以 roomId、版本、连续序号、前条哈希、幂等 ID、补丁和校验和构成日志帧；写入并 fsync 后返回，快照包含完整房间、末序号与对应日志哈希，快照文件 fsync 后重命名，保留全部日志。相同 ID 同样内容返回重复，内容不同则拒绝；写失败后要求重新打开。恢复检查完整帧、序号、房间和快照绑定，遇到完整坏行报错，仅修剪不完整末行。校验和用于发现意外损坏，不是防篡改认证。

自动测试覆盖：完整 `RoomRecord` 恢复深等值，字段删除、数组、座位原生续接、期限、参与者及合成凭证设置；追加动作与事件；提交后修改调用者持有的嵌套对象与追加消息，不影响内存、日志恢复或快照；分别以原型及现有 `FileStore` 恢复的数据调用现有上帝和公开导出并比较；修剪尾部后继续追加再恢复；完整坏行及跨房间日志拒绝；未完成的快照临时文件被忽略。子进程在日志 fsync 后、返回前及返回后分别被强杀，恢复后动作保留一次，使用相同 ID 重试不重复。这里的动作是合成记录补丁，并非生产引擎事务，未确认动作**可能已经存在**；客户端必须用稳定 ID 重试并区分确认状态。

这些测试只证明上述进程级边界：未模拟断电、文件系统或设备实际持久化语义、目录 fsync、磁盘满、并发写者、日志中段破坏后的人工修复、权限隔离、旧档迁移及真实外部模型调用；未验证所有可能的补丁次序或完整游戏重放。初始化快照和日志的创建不是已验证的断电原子事务。原型没有日志裁剪、密钥保护、生产数据迁移、资源上限及多进程租约，不能直接用于生产。

## 重现与验证

在仓库根目录、已安装依赖时运行：

```text
node --import tsx packages/session/scripts/event-store-measure.ts
node node_modules/vitest/vitest.mjs run packages/session/test/event-store-prototype.test.ts
node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit
```

测量覆盖目标 JSON，临时目录建立在工作区并在完成后删除；可传其他输出路径作为脚本第一个参数。本次测试 6/6 通过，类型检查通过。当前运行环境中 PowerShell 的 `pnpm.ps1` 内置模块不可加载，`pnpm.cmd` 的 Corepack 试图联网获取 pnpm 而失败，因此使用已安装的本地工具直接运行；不将上述失败命令计作通过。

如果将来观测到实际保存开销成为瓶颈，应先采集脱敏的每房间保存频率、有效合并比例、序列化/写入/恢复耗时及座位上下文大小，评估低风险的局部写入或版本标记；若仍考虑事件日志，先明确事务与回执、旧档迁移、日志裁剪、外部调用和跨平台崩溃恢复的验收，再用真实形状的合成多房间工作负载和故障注入比较。当前评估不授权或实现迁移。
