## 审计发现

### P1 验收器未检查多余或重复真值

定位：[acceptance.ts](../packages/session/src/observability/acceptance.ts) 第 51–74、87–89 行；相关测试为 [observability-acceptance.test.ts](../packages/session/test/observability-acceptance.test.ts)。

验收器先以 `attemptId` 将 truth 转成 Map，然后遍历观测 HTTP 终态并查表，最终用 `matched === attempts` 参与通过判定。这里的 attempts 和 matched 都来自观测侧。没有检查 truth 中未被使用的条目，重复 truth 键也会被 Map 覆盖；摘要没有独立的 truth 原始条数和唯一数。

由条件可推演：一个正常样本有两次或更多尝试，其中一次的 start/end 整对从观测材料丢失、truth 保留，而 manifest 的运行时 dropped 仍为零时，剩余记录可满足开始／结束配对、计时及 `matched === attempts`，从而仍被判通过。此处是源码推演，本轮没有运行损坏夹具。原有测试只覆盖移除单个终态，没有整对缺失、多余 truth 或重复 truth 的断言。

影响限定为验收门禁可靠性：它不直接证明已经归档的 28,746 次请求存在丢失，也不证明观测主体错误；但它阻止外审依据该判定确认全量完整性。

修复要求：

1. 正常 S01／S02／S03 按运行和尝试标识双向核对唯一集合，分别输出 truth 总数／唯一数、观测开始／结束数、两向差集、重复键和跨运行污染；任何异常均不得通过。
2. 故障场景中未到达服务的网络失败属于独立口径，须用明确分支对账，不能使用宽泛“允许缺 truth”掩盖正常矩阵丢失。
3. 先补整对丢失、额外 truth、重复 truth、混入其他运行、缺字段／非有限耗时和错误源哈希等验收脚本夹具，再读取保留的压缩材料离线重算。若材料完整，优先复核已有产物，无需直接重跑全套 HTTP 负载。
4. 新判定绑定验收脚本版本、原始成员哈希、输入清单和命令；结果通过后补外审复核记录，再讨论永久清理。
