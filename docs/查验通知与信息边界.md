# 查验通知与信息边界

更新：2026-11-01。本次核对预言家、魔镜少女及觉醒隐狼复制的魔镜查验，不改变结算或行动许可。

## 原始记录与问题

已结束的视频样本中，一名狼人席在第 1 天的公开发言里，将「被发金水的玩家能知道自己是否被查验」作为判断另一名玩家查验声明真假的前提。视频保留了原始玩家发言，这个说法出自模型，而非后期旁白。

该前提不符合本项目规则。不过发言者是狼人，仅凭公开发言不能断定是模型理解错误，还是故意误导。原始对局、逐席上下文和本次外部请求记录保留在忽略的数据目录，不随文档提交。

## 引擎已有的事实

- 预言家的 `seer.result` 只发给查验者。
- 魔镜及隐狼复制查验共用 `inspectRole`，`mirror.result` 也只发给查验者。
- 玩家投影和座位上下文均按事件受众过滤。被查验者不会收到查验行为或结果通知，也没有「本夜是否被查验」的知情字段。
- 查验者公开声称的验人信息属于玩家发言，不会因此转成法官确认的事实。法官与结束复盘的上帝视角另按既有权限查看。

## 公共规则的澄清

原预言家公共规则只说明查验内容；「只有你能看到」出现在预言家自己的工具目录里，其他身份不会收到该工具目录。原魔镜公共规则说明「结果仅本人可见」，没有直接排除目标另外收到被查验通知的理解。

现在两类查验的公共规则共用以下文字，所有座位都能读到：

> 法官只向查验者私密反馈查验结果，不向被查验者通知查验行为或结果；未收到通知不代表没有被查验。

这是对消息分发的规则说明，不规定相信谁、如何站边或如何投票。外层系统模板、事件受众与结算保持原实现。审阅稿同步展示实际规则卡；已存在的座位 system 历史不回写。

## 模型核对及局限

使用已授权的 Token Plan `qwen3.8-flash`，沿用 `thinkingMode=off`、温度 0.7，分别在标准十二人和镜隐迷踪的合成平民视角核对上述错误推论。修订前、修订后各两次独立请求，共四次；不推进真实房间，不共享其他座位的私密记录。

四个回答均明确表示：被查验者不会收到通知，不能据未收到通知判断未被查验。修订前模型已经能够回答正确，因此不能把澄清描述成「修好了模型原来必定误解的知识」，也不能据此保证完整对局不会再说错。

修订后的一个魔镜回答还把自称魔镜的发言者直接当成魔镜本人。它对通知范围回答正确，但身份声明可信度仍有独立的推理风险，不能据本次小样本宣称整体推理可靠。此次不据一个样本增加站边策略或反复改写外层提示词。

## 回归覆盖

`visibility.test.ts` 和 `mirror.test.ts` 新增三个对照场景：仅改变预言家、魔镜或隐狼复制查验的目标，比较被查验者、未被查验者、其他玩家及旁观者的完整投影。它们应完全相同，只有查验者自己的知情记录不同。

连同提示词和座位上下文相关回归，四个文件共 59 项通过，TypeScript 检查通过。真实模型核对与自动化回归分别报告，不将四次简短问答计为完整真人对局验证。
