# 共享合成取消实施记录

日期：2026-11-03。

`SpeechService.render` 的原有参数和调用方式保留，末尾增加可选的 `{ signal, timeoutMs }`。每个调用者独立等待，默认总等待上限 240 秒，覆盖读缓存、排队、合成和写入。共享任务自身从创建起也有固定的 240 秒期限；后来加入的等待者不会延长这个期限。到期时拒绝当前全部等待者并向上游发送取消信号，但仍等物理任务结束才释放并发槽和同内容任务占位。同一内容仍共享实际任务；单个等待者取消或超时不会中断其他等待者。最后一个等待者离开时，请求任务取消；已取消但尚未结束的同一任务拒绝新等待者，提示稍后重试，直到旧任务实际结束。最多保留 128 个不同的未结束任务，超过时快速失败。

实际并发槽上限为 2，排队任务取消后移出队列。提供方即使忽略取消信号，也要等其 Promise 实际结束，相关缓存操作也结束后才释放槽。迟到的提供方结果不会作为服务结果发布，取消后不会开始服务层的下一项缓存写入；已开始的文件操作不能撤回，已经完整写成且可校验的缓存可以保留。服务缓存读取期间也会响应调用者取消，后台读取结束后任务才算排空。

试听和对局语音通过 HTTP 请求中止及响应连接提前关闭传递取消信号，不使用请求正文正常读取完毕也可能触发的 `req.close` 判定断连。断开的响应不再发送数据。服务关闭时拒绝新合成、取消所有等待和排队任务，并等待已启动的物理任务和写盘结束；沿用服务关闭宽限，未排空返回超时状态 2，不假报资源已释放。

Qwen 合成在缓存读取、上游结果及自身文件写入关键边界检查取消。`reuseAudio` 原有跨目录缓存复制和已经开始的文件操作不能被强制中断，因而不能保证取消后绝无迟到磁盘写入；有效缓存可以保留，不完整缓存由后续校验处理。同样，忽略 `AbortSignal` 的第三方模块无法由 JavaScript 强制停止，远端是否停止计算或计费也不能由本地取消推断。该限制可能使并发槽持续占用并导致关闭超时。

验证：使用本地可控提供方和真实本地 HTTP 连接，覆盖单个及全部等待者退出、等待超时、队列上限、排队取消、忽略取消的并发槽、迟到成功和失败、同内容重连、缓存读取时取消、试听断连、其他 HTTP 等待者继续、关闭排空及超时。相关取消与生命周期测试及 Qwen、语音协议回归共 9 个文件 32 项通过，工作区 TypeScript 类型检查通过；未调用真实语音服务。此前关于旧实现断连后继续合成的测试和报告描述的是当时的行为，本次不改写历史事实。
