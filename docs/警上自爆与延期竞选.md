# 警上自爆与延期竞选

更新：2026-11-01。新房间默认使用 `sheriff.explodeInElection = postpone_vote`。规则由引擎执行，系统提示词的外层模板未修改；公共规则卡按本局配置生成。

## 新默认流程

1. 警长尚未产生时，第一次竞选自爆立即公开自爆者身份，取消当天未完成的竞选、普通发言与放逐投票，保存原始报名、退水记录和投票轮次。
2. 如果昨夜情况尚未公布，先公布昨夜出局名单。沿用现有死亡职责处理猎枪和后续死亡连锁：猎人被刀、死因不含毒药时可以开枪；死因包含毒药时不开枪。此时不会因为延期而额外改变猎人规则。
3. 胜负尚未成立时，先由自爆者遗言，再由有遗言资格的首夜死者和猎枪带走者按座位号遗言。每人只处理一次；合并批次中不再允许新的自爆打断。随后进入下一夜。
4. 下一白天先公布新一夜的出局情况、处理猎枪等出局职责，再恢复警长竞选。第二夜起夜间出局及该夜猎枪带走者默认没有遗言，沿用原有配置。
5. 不重新报名、不重新竞选发言，直接续投。投票前仅向存活且可自爆的狼人询问一次是否再次自爆；这保证“再爆流徽”确实存在操作窗口，不允许打断已经开始收票的投票。
6. 无人再次自爆则继续投票：保留原警下资格和退水限制；排除已出局、已退水的候选人。没有候选人则无警长，只剩一名候选人则直接当选。平票仍正常进入 PK；若第一次自爆已经发生在竞选 PK，则次日只续投原 PK 轮次和候选人。
7. 续选确认或后续竞选 PK 中第二次自爆，警徽流失，取消该日剩余流程，完成自爆职责后入夜，不再补选。

出局技能处理后若已分出胜负，立即结束，不再安排遗言或续选。自爆者同时是尚未公布的首夜刀口时，死亡与遗言不会重复。

## 夜间公告与参与资格

夜间出局情况由法官明确通报：有死亡则公布名单，无人出局则明确宣布平安夜。未通报表示「尚未公布」，不能等同于平安夜。首日先竞选时，公布前允许上警、发言和投票只是阶段参与资格，不表示确认存活；非上警白天在普通发言前通报，延期直接续投也先通报再投票。竞选开始通知会按当前是否已公布给出准确状态，不透露隐藏的死亡名单或人数。

之前真实对局出现过相近误读：首夜刀口玩家在警上将自己仍能发言理解成没有死亡，其他好人又把竞选时仍能参与与随后公布的夜间出局当成矛盾。请求中的原规则已经有先竞选后公布，但缺少对「尚未公布」状态的显式定义。本次补充公告规则，不增加站边、身份声称或技能使用策略；真实对话与凭证仍保留在忽略目录。

## 配置与旧存档

| 值 | 行为 |
| --- | --- |
| `postpone_vote` | 新默认：首次延期，次日先处理昨夜情况后直接续投，再爆流徽。 |
| `lost` | 保留旧规则：竞选中首次自爆即流徽。 |
| `postpone` | 保留旧延期规则：下一白天重新安排竞选发言，再爆流徽。 |

已开始的房间继续使用保存的规则值，不修改过去的行动或事实。新增 `ElectionState.postponedVote` 是可选字段，只在新延期模式中保存轮次与待续投候选人。旧模式的存档和行动重放仍按旧规则工作。候场房间按当前配置开局；房主可以显式选择旧模式。

若显式配置先公布首夜遗言再竞选，狼人可能在尚未报名的遗言阶段自爆。此时还没有可续投的候选名单，下一白天正常补报名与竞选，不虚构候选人或直接流徽；完成报名后发生的竞选自爆才按直接续投处理。

## 实现与验证

沿用 `dawn.announce → deaths.batch → 角色 onDeath → lastwords` 处理死亡职责；新模式把未公布的夜间死亡与自爆合并为同一批，并调整遗言顺序。猎人技能、毒杀禁枪和后续夜遗言规则没有另写一套。

专项回归见 `packages/engine/test/election-resume.test.ts`：首夜猎枪与连锁、毒杀禁枪、平安夜、重复死亡、直接续投、退水资格、候选人死亡、PK 轮次、二次自爆、胜负与重放。

Terra 使用独立合成房间通过页面验证：首爆后公布 7 号出局，7 号开枪带走 9 号，随后依次 1／7／9 号遗言并入夜；毒杀猎人没有枪口；第二天无新竞选发言或第二夜死者遗言；二次自爆流徽。另完成一轮无人再次自爆的实际续投，警下八人投票，9 号正常当选。测试未调用真实模型，未覆盖或改写已有真实对局。
