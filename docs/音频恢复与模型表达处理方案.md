# 音频恢复与模型表达处理方案

日期：2026-11-03。范围为 `AUDIO-PLAYBACK-RESILIENCE`、`AUDIO-CANCEL-CONTRACT`、`MODEL-UNSUPPORTED-CERTAINTY`。这是实施前设计和后续独立验收的依据，不表示功能已经完成；活动状态与最终处理只在[待解决问题](待解决问题.md)及其归档维护。

本轮用户已授权处理三个具体后续。主代理负责集成、真实实验与交付；本方案审查者不调用真实模型／TTS、不读取密钥、不操作浏览器、不修改生产源码。首次检查工作区只有其他任务的 `.gitignore` 改动。后续实现期间其他代理可在各自约定的文件范围内修改，不将这些改动混作初始基线。

## 处理决定

1. 播放失败保留可恢复的当前项和待播队列；“用户希望自动朗读”和“因失败、人工暂停或当前行动而停止推进”分开。来源变化不等于用户要求丢弃内容。
2. 真人行动窗口开启时，自动朗读主动让行，保留待播内容。后端 deadline 不因浏览器播放而改变，不新增客户端延长时限接口。手动重听仍可由用户逐条选择，并明确行动倒计时继续。
3. 服务端共享合成按等待者管理：单个请求退出只取消自己的等待；全部退出后取消排队或请求提供方取消。物理并发槽由提供方实际完成释放，不由等待者超时释放。
4. 模型先进行有限、可盲评的复现；只有达到预定义复现门槛才试候选提示。评估公开表达的证据强度，不把站边策略、错误猜测或未公开私密信息自动算作模型记忆故障。

## 播放恢复与行动让行

### 状态与权限边界

现有 `SpeechCursor` 表示已见到哪些投影事件，不表示已经播放成功。新的播放调度必须独立保存待播项；不能在失败后关闭采集却继续推进 seen 游标，否则失败期间的新发言仍会消失。

建议以 `{房间、凭证、视角、席位}` 为权限上下文，包含以下独立状态：用户自动朗读意图、当前播放项、有序待播项、失败项／错误、暂停原因、当前输出代数和手动插播。音色或来源变化属于输出配置变化；凭证或视角变化属于权限边界变化，后者必须停止旧输出并丢弃旧上下文内容，不能跨席保留私密队列。

| 触发 | 当前项与队列 | 后续动作 |
| --- | --- | --- |
| 合成或播放失败 | 保留失败项在原位置及全部后续项，新事件继续排队 | 停止自动推进，显示明确重试；重试成功后依次继续，不无限自动重试 |
| 用户暂停 | 保留当前项和队列 | 恢复只解除人工暂停，不能顺带解除行动让行或失败 |
| 用户停止／关闭自动朗读 | 明确丢弃当前自动队列并停止输出 | 保持既有“重新开启从最新一条开始”的意图，说明这是主动弃队列 |
| 切换来源或音色 | 保留未完成项和顺序，失效旧输出代数 | 新来源可从当前未完成条目重播；不接收旧来源迟到的 ready/end/error |
| 来源被删除或无可用来源 | 保留内容，暂停等待选择 | 选择有效来源后可恢复，不静默改用另一服务 |
| 手动重听历史项 | 暂存未完成自动项，不清空自动队列 | 仅手动项先播放；结束后按其他暂停原因决定是否恢复自动项 |
| 房间／凭证／席位改变或卸载 | 清空旧权限上下文并停止输出 | 新上下文重新定位游标；旧请求和事件不能触发新界面播放 |

同一 seq 若同时作为手动项与自动待播项，手动完整播完后可以从自动队列移除这一项；播放开始、准备完成或失败都不能当作播完。重听已完成项是用户明确请求，允许再次播放；队列不重不漏指自动待播序列，不禁止用户重听。取消后重新开始一条可能重播已听的一小段，应如实说明这是从条目开头重试，并非精确断点续播。

不要把“暂停原因”合并为一个会互相覆盖的布尔值。失败后的重试不得自动解除用户暂停；手动重听结束不得解除真人行动让行；收到 submitted 更新也不能解除来源失效。输出驱动任何异步回调都核对当前代数和权限上下文。自动采集、选择下一条、切换驱动和清理 effect 的顺序必须由实际 hook 或等效挂载验证，单纯测试一个状态模型不能证明 React 绑定正确。

### 真人行动语义

仅真正由真人控制的座位页面参与自动让行：房间 `viewer=seat`、本席控制类型为 `human`，对局运行中，存在该席未提交任务，且服务未暂停。房主、旁观者、AI 席观战不因看到 task 字段被误停。

- 推进间隔 `actionAvailableAt` 尚未到时可继续自动朗读，同时可提示即将行动；到点由页面定时器重新判定，不能只等下一条 SSE。使用与 `TaskPanel` 一致的时间语义，客户端时钟只用于体验，不裁决行动有效性。
- 窗口开启立即中止或暂停正在准备／播放的自动项并保留待播顺序；同时有新事件时先应用让行，再决定是否启动下一条，避免短暂播出下一段。
- 任务 `submitted=true`、任务消失／换席、对局结束或暂停时，不再占有“当前需要行动”的自动让行理由；是否恢复仍取决于用户暂停、失败及来源状态。
- 暂停对局后可手动收听，恢复对局时重新检查同一决策及更新后的 `availableAt`。不要用旧绝对时间或旧决策的手动许可绕过新窗口。
- 不能单凭 `alive=false` 禁止让行：已出局真人仍可能有遗言、开枪、警徽等获准任务。相反，只有自爆、退水等可选 interrupt 而没有当前必需 task 时，不宜一直阻塞朗读；它们由用户自行使用。
- 行动窗口内允许用户显式选择一条手动重听，提示“行动计时继续”。该许可只作用于这一次手动播放，不给整个自动队列或整轮决策解禁。窗口前发起的手动播放在窗口首次开启时也应让行一次，之后用户可以重新选择继续听。
- 不改变后端 deadline，不发送延时／暂停房间请求，不改写前端倒计时以假装时限未流逝。网络断开时保留本地播放状态不等于冻结对局；仍提示以服务端最新投影为准。

此方案消除默认自动音频对行动的抢占，但不能承诺“听完所有内容后才开始决策”或“手动重听不消耗时间”。本轮产品语义应直接在界面和文档表达，不能以性能测量替代。

### 播放验收矩阵

使用可控输出驱动记录每次 `play/stop/pause/resume` 和回调代数，至少验证：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 第1条失败，已有第2/3条，失败后新增第4条 | 重试后完整顺序1、2、3、4；失败前后重复投影均不多加，未完成项不消失 |
| 失败后切换来源，旧 ready/end/error 各迟到 | 内容仍在新来源按序播放，旧回调不推进队列、不清新错误、不重启音频 |
| 删除来源后新事件到来，再选择新来源 | 待播序列保留，不隐式退回浏览器或另一家 TTS |
| 暂停中合成返回，失败与暂停并存 | 不自动播放；重试和恢复分别只解除对应阻塞 |
| 手动重听恰为队首／后续待播项／已完成项 | 未完成自动项保留，同 seq 自动播放按既定去重规则处理；手动失败不当作完成 |
| 同时更新新事件与当前真人任务 | 自动驱动不启动新的播放，已在途条目被保留 |
| availableAt 跨越，无新 SSE | 到点让行；服务暂停时不错误触发；恢复后使用新时间 |
| submitted、已出局但有任务、只有 interrupt、AI/房主/观战 | 分别符合上述判定，不依赖未授权数据 |
| 行动中手动重听与下一决策到来 | 仅当前手动项获得许可；新决策撤销旧许可，自动队列继续让行 |
| 同组件从席位A凭证变为席位B／换房，旧回调迟到 | B看不到、听不到、重试不到A的内容；旧输出停止 |

主代理检查实际页面中的错误提示、重试、来源选择和行动让行状态。若受环境限制只有控制器测试而无实际 hook 或挂载测试，应明确未完成绑定层验收，不能写全场景已通过。网页变更必须构建并运行相关现有测试。

## 共享合成取消与资源生命周期

### 请求与物理任务分离

推荐 `SpeechService.render` 增加可选请求取消信号，保留原调用兼容。缓存键保持覆盖来源版本、凭据路由、原文与语言。每个调用拥有独立等待者；共享的是底层合成任务，不能继续用“相同请求必须返回同一个 Promise 对象”作为接口验收。原来的同 Promise 测试应改为提供方只调用一次、两位等待者得到同一有效内容。

任务状态至少区分 cache-check、queued、running、cancelling、settled；每个任务记录独立提供方控制器、等待者集合、代数和实际 Promise。服务维持最多两项未实际 settled 的提供方任务；已经收到取消但未完成的任务也计入这两项。

| 情形 | 等待者结果 | 物理任务与缓存 |
| --- | --- | --- |
| 一个等待者取消，另一个仍在 | 只拒绝退出者，另一个正常等待 | 不取消共享合成 |
| 队列中最后等待者取消 | 立即完成其取消，移出排队 | 不调用提供方，不占物理槽 |
| 运行中最后等待者取消 | 立即完成其取消 | 请求提供方 abort，但槽保留到实际 Promise 完成 |
| 等待者或共享任务超时 | 有界完成等待，不把超时当音频成功 | 请求取消；实际工作未结束则继续占槽 |
| 已取消任务迟到成功／失败 | 不回调已退出等待者、不产生未处理拒绝 | 按预定义缓存政策处理，最后释放物理槽一次 |
| 新请求碰到同 key 已取消未 settled | 推荐明确可重试错误 | 不附回已 abort 任务，不同时启动同 key 新任务 |
| 服务关闭 | 拒绝新 render，结束全部等待者，移除排队，给活动任务发取消 | 等实际收尾到宽限，未完成则诚实报告未排空 |

队列应有明确上限，等待者应有包含排队的最大等待期限。复用任务的新等待者不能无限延长已经开始的物理任务硬期限。可先保持现有240秒任务期限，并通过构造配置／时钟注入做短时间确定性测试；上限值与错误语义由实施者在代码和报告写明，不把测试短期限变成生产默认值。

若提供方永远忽略 abort，进程内不能强制终止一个任意 Promise。正确行为是保留至多两个真实活动槽、使等待者有界结束、拒绝或有界排队新工作，并在服务关闭超宽限时报告未排空；不能为了显示“已关闭”清零计数后继续启动更多工作。若以后需要强制回收任意模块，可另行采用工作线程或子进程；本轮不宣称实现这种能力。

### 迟到缓存与适配器写盘

本轮实施须明确选择迟到成功是否允许缓存，不能只处理 `SpeechService` 一层就宣称所有写盘都取消。当前 Qwen 的 `synthesizeQwen` 会先写其 `.wav/.json` 缓存，再返回给 `SpeechService`；取消检查只放在外层仍可能留下该内层写入。

推荐政策：正常完成并校验的有效音频可以保留已有缓存；任务已经撤销或服务已进入关闭时，不再启动新的缓存发布。若已有原子写入已开始，收尾责任直到完成，并记录这不是计费撤销。取消检查需覆盖适配器写盘前、外层缓存发布前，以及 await 后的代数核对；临时文件按任务唯一命名或同 key 严格串行，避免旧任务删除新任务的文件。

可以选择另一种明确的“零等待者仍完成有效缓存”策略，但必须保留并发槽、超时、排队上限与关闭收尾，并准确描述成本；这种策略不应包装成上游请求已取消。无论采取何种政策，都不能以本地 abort 证明服务方已停止算力或计费。

### HTTP 与关闭边界

客户端取消以响应连接的 close／请求 aborted 为依据，不能将正常读完请求体后的 `req.close` 误判为客户端已离开。每个请求的监听器在完成、取消和失败路径都释放；未断开的另一个同 key 请求不能受影响。客户端已断开时不再尝试写错误 JSON，正常出错仍保持既有 `SPEECH_UNAVAILABLE` 等接口行为。

语音 dispose/whenIdle 或等价收尾接入 HTTP factory 关闭责任，独立实例不互相关闭；同时处理普通发言朗读和来源测试请求。关闭过程不要求调用者先枚举所有请求。只有所有应收尾工作确已完成才能报正常；强制关闭连接与提供方实际停止是两个不同事实。

### 服务验收矩阵

- 两个同文等待者：一个断连，另一位成功，提供方恰好一次调用；两个先后断连时仅最后一位触发取消。
- 两路活动提供方加第三路排队：第三路退出后从队列移除，从未开始；已退出任务在槽空出时不能复活。
- 提供方忽略取消：等待者先失败但物理活跃数仍为2；第三路不开始，直到一项真实 resolve/reject；随后只释放一次，最大实际并发从未超过2。
- 已取消未完成的同 key 新请求符合既定拒绝／后继政策；旧任务完成不会清除新任务映射或写坏新缓存。
- 在缓存读取、请求开始、下载、校验、写盘前后注入取消；拒绝后的迟到成功与失败均不出现未处理拒绝，不再通知退出者。
- 单等待者超时、共享任务硬超时、全部等待者退出及服务关闭都清理自身计时器、监听器和队列项；仍活跃的提供方不是“已释放资源”。
- 真实本机 HTTP 连接验证单人断连及双人共享；测试提供方只使用合成内容，不调用真实 TTS。可控假提供方的 abort 接收证据只证明本地链路。
- 关闭宽限内正常 settled 返回正常；忽略取消直到宽限后返回超时／未排空，后续迟到完成不重新启用服务。现有 HTTP/SSE、管理器保存及租约关闭回归继续通过。

## 模型表达：复现、盲评和候选验证

### 先修正诊断边界

上一轮评分的主问题“仅对跳便说必然一真一假”有直接可达反例：两位发言者都可以是狼人。不要按真实底牌判错，应证明对模型而言同时兼容另一组底牌。

上一轮针对“女巫没救”的附加诊断则需更谨慎：在标准九人首夜、仅一人出局、女巫不能同夜救毒且解药只能救刀口的规则下，成功救人可能必然消除当夜直接死亡；猎人连锁也会有另一名死亡者。因此不能不核对本版型就用“也许救后仍死亡”作反例。该措辞暂不作为已证实错误扣分，应先构造同一可见日志下的合法反例，构造不出且规则可推出时归为合理推断。历史评分不要静默改写；本轮报告说明此项诊断口径收紧。

同理，“9号被狼刀”可用合法的空刀加毒药等隐藏行动检验，但必须实际证明引擎能产生同一可见日志；不能仅凭常识列一个在该配置下不可能的机制。每个“确定性不受证据支持”的裁决都应能指向公开规则允许的反例或明确的消息来源错认。

### 固定输入与隐藏双生局

至少构造两种符合公开配置的完整状态：一个对跳者为真预言家、另一位为狼；两个对跳者均为狼且真预言家在其他席位。被测平民席位及身份、存活、公开事件、发言内容、任务和工具保持一致；相应私密信息仅存在引擎状态。

每个公开变体都从引擎生成这两份合法投影，断言发送给模型的投影、消息与工具相同。不得删去影响玩家可见性的字段来制造相等；如仅排除诊断运行标签，列明字段及理由。隐藏双生局是离线权限及评分依据，不必对字节完全相同的请求再重复付费，也不把同一输入挂两个隐藏标签冒算新增独立样本。

公开变体建议采用两种自然措辞与两种发言顺序，共四个；仍保留真实行动任务和生产工具，不额外索要记忆、理由或思考正文。变体先生成并固定，再开始真实请求。保留各变体的源码摘要、规则、可见投影、工具和输入哈希。

### 有限矩阵与分阶段停止

建议本轮预注册如下上限，可在真实实验开始前由主代理缩小并固定；开始后不得为追求结论追加样本或暗中替换失败：

| 阶段 | 设计 | 最大逻辑调用 |
| --- | --- | ---: |
| 复现 | 4公开变体 × 当前提示的off/high(max) × 2次交错重复 | 16 |
| 候选验证，仅复现门槛达到后 | 4个预先留出的措辞／顺序变体 × off/high(max) × 2次重复 × 基线/候选配对 | 32 |
| 总上限 | 不含上轮30条旧样本；失败计入，不自动补样 | 48 |

先固定模型版本标识、协议、温度、工具模式、时限和输出参数，使用现有明确获授权服务。每次最多90秒，底层请求变体／重试尽可能记账；服务默认上限与实际设置如实记录，不写不存在的固定 cap。保持已有隐式缓存，不新增显式缓存控制。

复现门槛建议为至少两条**明确**不受可见依据支持的确定表达，且来自至少两个公开变体；这是决定是否值得继续候选实验的操作门槛，不是统计显著性检验。只见一条或只有歧义表达时，保留具体样本与未复现范围，不改提示。网络失败或工具失败不计为确定性问题，但保留在全部逻辑调用分母。

若进入候选验证，候选只增加一项普适来源／推断边界提醒，不写“对跳可能双狼”“死者可能被毒”这类直教测试答案的句子。不得要求狼人强制诚实、泄露查验或展示思考。候选的动机和精确差异先固定，再使用留出变体；基线与候选在同一时间段交错配对，不将早期基线与后期候选直接拼接。

### 盲评材料与客观指标

主代理生成随机样本 ID，封存 ID 与变体／提示版本／档位／重复次数的映射及摘要。给评分者的材料仅有共同规则、被测席真正可见的日志与身份、可用工具、实际工具输出，不含实验系统提示差异、底牌、条件标签、文件名暗示、时延或用量。输出原文不能为加强盲化而删改；输出风格可能让评分者猜测条件，作为限制说明。

评分者先提交锁定的逐条判定及证据引用，再揭盲汇总。上一轮已看过的样本只作历史来源，不混入本轮盲评。独立审查者不得同时阅读未揭盲的原始带条件结果；若意外接触，准确记录失盲范围，不能仍宣称该样本盲评。

| 指标 | 判定口径 |
| --- | --- |
| 合法行动交付 | 原样工具经同一引擎接受；失败、无工具和非法参数分别保留 |
| 确认事实／来源归属 | 程序通知、本人私密事实与玩家原话是否混淆；每项给出可见证据 |
| 不受支持的确定表达 | 以官方确认或逻辑必然排除可达反例；记录原句及反例，不按隐藏真相惩罚猜测 |
| 有限推断／站边 | “更信1号”“今天投2号”“我认这张牌”可作为策略，不自动当成事实断言错误 |
| 歧义／不可判断 | 省略、修辞、矛盾句式或可能策略性表达无法可靠归类时单列，不强行通过或失败 |
| 阵营与有用性退化 | 仅核对明确违反角色边界、泄密或不再执行任务；不凭评审偏好评价最优站边 |

报告逐条展示分类、证据、反例和争议理由，不依赖关键字搜索充当语义理解。主指标为逻辑调用中出现明确不受支持确定表达的比例，同时报告可评分响应分母、工具成功率、歧义率和失败数。N/A 和无法判断不计通过；不将这些分类合成缺乏解释的总质量分。

候选只有在留出配对中降低明确问题、未增加合法行动或角色边界失败、未把输出普遍退化成无信息回避时才有采用依据；小样本仍只能说明局部效果。若无清楚改善，保留当前生产提示，记录实验结果。不能以候选文字已添加、输出更长或思考更多宣称问题解决。

## 集成和最终验收

前端、服务端与模型实验尽量按文件划界，HTTP 接线、服务关闭及共享数据由主代理整合。实施者先完成各自相关测试；主代理运行受影响的网页、语音、HTTP、时限、权限与实验器回归及类型检查，网页必须生产构建。真实页面只由主代理操作；真实模型实验只由主代理按固定矩阵运行。

独立复审检查实现是否遵守以上状态和资源不变量，重跑关键并发／竞态测试，核对实验矩阵与盲评封存材料。任何发现先反馈实施者，不修改其源码。最终交付分别报告生产行为已实现、本地故障注入已验证、实际页面已核对和真实服务观测；提供方实际停算或计费未知时继续写未知。

活动问题是否归档以实际结果决定：音频项须完成其生产修复和对应验证，不能仅凭本文设计关闭；模型项可以在充分复现评估后给出采用或不采用候选的有据决定，但若核心现象仍需处理，应保留明确来源与后续验收，不能把未观察到差异当作永久解决。
