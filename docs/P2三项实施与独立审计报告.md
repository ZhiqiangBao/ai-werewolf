## 实施方案与最终落点

### 本席全部任务结束后停止旁听

引擎的 `seatTasksComplete` 根据死亡记录、职责是否展开、警徽归属、当前决策与剩余议程推导完成状态，不新增容易与规则状态失步的持久化停止标记。存活席位始终保持原有同步行为，包括正常胜负产生后的终局和复盘上下文；出局席位只有在全部后续职责结清后才停止。

本人尚有遗言、猎枪、警徽或能力职责时继续接收上下文。尚未展开的同批遗言也被识别；已经完成自己的遗言，不必等待同批其他人的遗言。角色与 Ability 死亡钩子产生的步骤保存职责归属，能力步骤另外绑定持有者与实例，避免把“由其他座位办理的本人职责”漏判为完成。扩展处理器继续展开子职责时须保留 `dutySeat`。

会话调度在寻找最早未读事件和构造波次时排除已结清席位，结清时取消该席在途旁听，入口及返回处再次检查状态。取消后的迟到响应与流式回调不能继续写入或行动；已经被引擎接受的最后一次工具调用及回执仍保留。房主终结继续采用已有整局取消流程。引擎事件、座位历史、真人／旁观者投影和订阅不因此删除或关闭。

### 通用且库存独立的 Ability

`abilities.ts` 注册共享行为定义，`AbilityInstance` 分别持有实例 ID、版本、资源、激活状态和可用夜次。授予能力时深拷贝初始状态；相同定义、同席多个实例及不同持有者之间不共享库存。夜间行动绑定席位与实例，依次调度，解决原隐狼多持有者循环建立决策的冲突。

复制魔镜、毒药、守护、额外爪击、猎人及无主动技能分别注册。魔镜复验限制使用各实例自己的记录，私有知识按获授权席位聚合；毒药、爪击、守护记录及猎枪职责独立。复制守护即使没有原守卫角色在场，也执行本局同守同救规则。

固定工具目录由角色声明的 `abilityCatalog` 和定义组成，不因实例库存改变；同名工具内容不一致会明确拒绝。普通女巫、守卫和猎人保留原规则接口，真实身份、阵营、查验表现、狼队信息与胜负归属不通过替换身份 ID 实现。现有版型人数和隐狼数量限制没有因此放宽；双复制者与叠加实例使用合成扩展场景验证。

### 版本化角色私有数据与迁移

`PlayerState.data` 改用 `Record<string, unknown>`，当前角色字段通过 `RoleDataMap`、`roleData` 和角色 schema 访问。缺省版本按 v0 处理，当前内置角色为 v1；扩展 schema 可逐版迁移。迁移需要改变结构时复制输入，不重跑 `setup`、不重新产生事件或结算历史。

旧隐狼 `learned.skill` 转为独立实例及引用，保留库存、启用时间、刀权与旧查验当时的结果。复制猎人的库存根据技能激活状态、已执行的死亡钩子和当局猎人死因规则迁移，不能只把 `hooked=true` 当成使用过枪；含毒禁枪和未激活状态仍保留未用库存。

旧房间恢复及引擎提交都经过迁移；旧技能、猎枪和警徽的现存决策原地续接，保留 ID、工具、提示、提交记录和议程。已知角色或 Ability 的未来版本、未知能力定义和重复实例阻止推进，受影响房间暂停，仍能按权限查看原有历史，不阻断其他健康房间。数据版本与工具／竞选／版型规则版本分别保存。
