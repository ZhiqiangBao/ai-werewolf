# 发言朗读与提供方接入

更新：2026-11-02。房主、座位和观战页面通过同一播放接口，朗读各自授权投影中法官已接受的 `speech`，包括竞选、PK、白天讨论和遗言。草稿、模型思考、审计正文与狼队密谈不是此功能的朗读输入。

## 页面操作

- 在对局记录顶部选择「朗读来源」。浏览器原生始终列出；不支持时标记为不可用。其余选项由服务端配置提供，可以并列接入多家服务。
- 「开启自动朗读」先读最新一条，再依次读当前视角新提交的发言。多次推送、重连不会重复入队；刷新默认关闭，不会补读整局历史。
- 每条发言旁的「朗读」替换当前播放并清空积压；之后的新发言仍按自动开关入队。
- 支持暂停、继续、停止和 0.8～2 倍速。切换来源或原生音色会停止播放、清队列并关闭自动朗读，需要本人重新开启，不会自动切换计费线路。
- 原生音色来自系统；有些浏览器的语速更改在下一条朗读生效。系统是否使用联网音色由浏览器决定，不应假定原生一定离线。
- 首次音频播放若受浏览器限制，页面提示点击继续。生成期间不阻塞行动提交或法官推进。宽屏的调用记录与发言记录分别滚动，手机宽度保留纵向布局。

## 两层接口

客户端 `SpeechOutput` 位于 `apps/web/src/speech-output.ts`，统一 `play`、`pause`、`resume`、`setRate`、`stop` 以及开始、结束、播放受阻和错误回调。目前有浏览器原生实现和服务端音频实现；事件去重与队列不依赖某一家 TTS。

服务端 `SpeechProvider` 位于 `packages/session/src/speech/providers.ts`：

```ts
interface SpeechAudio { bytes: Uint8Array; mimeType: string }
interface SpeechProvider {
  id: string;
  label: string;
  cacheIdentity: unknown;
  synthesize(text: string, signal: AbortSignal): Promise<SpeechAudio>;
}
```

所有提供方共用音频校验、相同请求合并、持久缓存、最多两个并发合成任务和超时。来源失败直接报错并停止自动队列，不尝试其他服务。

## 在网页配置 TTS

房主在候场或对局页面右上方点击 **TTS 设置**。先选接入类型，再填写显示名称、完整接口 URL 和 API Key；模板提供默认模型／音色时可以直接使用，其他接口按服务商要求补齐。名称只用于显示，不会自动作为模型 ID。

| 类型 | 请求与响应 | 本轮接入范围 |
| --- | --- | --- |
| 兼容语音接口 | POST JSON，`input` 为原文，请求并校验 WAV；可填写 `model`、`voice` | 用于实现相同协议的服务或自建网关，不承诺任意厂商只填三项就兼容 |
| Qwen HTTP | `SpeechSynthesizer` 专用协议，解析 SSE 音频 | 地址、Key、模型和音色由房主显式选择；旧环境 Token Plan 入口保持兼容 |
| 小米 MiMo | `chat/completions`，原文在 assistant 消息中，解码 JSON Base64 WAV | 保留网页朗读；不加入视频 skill |
| MiniMax | 同步 `t2a_v2`，解码 JSON Hex MP3，检查业务成功及完整结束状态 | 使用当前 [同步语音合成 API](https://platform.minimax.cn/docs/api-reference/speech-t2a-http) 模板；未调用真实 MiniMax 账号 |
| 自定义 HTTP · 音频响应 | 自填 JSON 请求模板、密钥头／前缀，响应为音频字节 | 请求模板必须含 `{{text}}`，可显式指定 MIME |
| 自定义 HTTP · JSON 音频 | 同上，另外指定音频字段路径、Base64／Hex 编码和 MIME | 例如 `data.audio`、`choices.0.message.audio.data`；不把 JSON 下载地址误当音频 |

接口 URL 需要包含完整服务路径，例如 `/v1/audio/speech`、`/v1/chat/completions` 或 `/api/v1/services/audio/tts/SpeechSynthesizer`；不是只填域名。模板不会在调用失败后改地址、借用其他 Key 或切换计费线路。URL 中不能包含用户名、密码、查询参数或片段，密钥写在独立栏。

**保存不调用 TTS。** 保存后来源进入本房间的朗读选单；点击「试听」才发送固定测试句并显示音频播放器，再由用户点击播放。支持编辑与删除，编辑时 Key 留空保留原值。关闭弹窗会清空表单中的 Key 和试听音频；不会把 Key 写入 localStorage。浏览器密码管理器自身的保存／填充行为仍由浏览器控制。

网页配置只属于当前房间，候场、进行中与结束后的复盘均可管理。玩家和旁观者只能选择来源、朗读自身获授权的原文，不能查询地址、模型或密钥；拿另一房间的房主凭证也不能管理当前房间来源。房间克隆不会自动复制网页添加的 TTS 凭据。

配置保存在忽略的 `data/speech-connections.json`，密钥使用既有 `SecretBox` 加密，复用 `WEREWOLF_SECRET` 或 `data/secret.key`。迁移时需同时保留主密钥。原来的 `speech-providers.json`、环境变量和 Qwen Code 全局配置不会被改写。网页配置保存即生效，无需重启；其他已经打开的页面可刷新或重新切回窗口更新来源，删除当前所选来源后会停止，要求重新选择。

网页适配和视频适配仍是两个输出契约：网页需要可播放音频，视频需要真实字词时间戳与规范 WAV。添加网页来源不会让它自动成为视频 skill 的来源。

### 后续接入其他厂商

保留 `SpeechProvider` 作为协议适配边界。HTTP/JSON 模板覆盖不了的协议，通过服务端配置的 `module` 实现 `synthesize({text, options, signal})`，统一返回 `{bytes, mimeType}`；需要网页直接配置时，再在 `SpeechConnectionKind`、模板列表和 `connectionConfig()` 中注册适配类型。客户端不能上传 JS、指定模块文件或修改服务器环境变量。

| 厂商／接口 | 需要额外适配的原因 |
| --- | --- |
| [腾讯云实时 TTS](https://cloud.tencent.com/document/product/1073/94308) | WebSocket、AppID/SecretID/SecretKey 与请求签名；不是单一 Bearer Key 的 POST JSON |
| [豆包 HTTP/SSE](https://docs.volcengine.com/docs/doubao-voice/http-chunked-sse-unidirectional-streaming-v3?lang=zh) | 需要处理其专用请求、鉴权／资源标识与流式事件 |
| [百度长文本 TTS](https://cloud.baidu.com/doc/SPEECH/s/ulbxh8rbu) | Access Token、创建异步任务、查询任务及下载结果，需要持久化任务状态 |
| [Azure Speech](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech) | 使用对应区域／资源认证与 SSML 请求，不是这里的 JSON 音频模板 |
| [AWS Polly](https://docs.aws.amazon.com/polly/latest/APIReference/API_SynthesizeSpeech.html) | AWS 凭据、区域和签名／SDK 调用；时间标记与音频也有不同响应 |

以上只预留适配入口并核对官方协议，本轮没有实现或实测这些厂商的原生适配器。服务商支持某项能力，不代表所有模型、音色和计费线路均支持。

## 服务端配置

默认读取 `WEREWOLF_DATA/speech-providers.json`；可用 `WEREWOLF_SPEECH_CONFIG` 指定另一个文件，修改后重启服务。文件不存在时保留已有 Qwen Token Plan 来源，并根据服务进程的环境变量增加小米选项；默认来源仍为 Qwen，网页仍需手动开启播放。文件存在时以其中列表为服务端内置来源；`providers: []` 禁用此文件层的来源，房间网页添加的来源仍独立保留。

```json
{
  "defaultProviderId": "qwen-token-plan",
  "providers": [
    {
      "id": "qwen-token-plan",
      "label": "Token Plan Qwen",
      "type": "qwen-token-plan"
    },
    {
      "id": "my-http-tts",
      "label": "我的语音服务",
      "type": "http-audio",
      "endpoint": "https://tts.example.com/audio/speech",
      "apiKeyEnv": "MY_TTS_API_KEY",
      "body": {
        "model": "your-tts-model",
        "voice": "your-voice",
        "input": "{{text}}",
        "response_format": "wav"
      },
      "cacheVersion": "1"
    },
    {
      "id": "custom-tts",
      "label": "自定义语音",
      "type": "module",
      "module": "./tts-adapter.mjs",
      "options": { "voice": "your-voice" },
      "cacheVersion": "1"
    }
  ]
}
```

示例域名、模型与音色须换成服务商实际配置；不是任何厂商账号的预置承诺。`id` 使用字母、数字、下划线或连字符，不能与保留值 `browser` 重名。浏览器会优先恢复本人选择，未选择时优先可用原生来源，否则使用服务端默认值；自动朗读仍需本人点击开启。

### Qwen Token Plan

可选字段为 `model`、`voice`、`rate`、`instruction`。缺省沿用 `qwen-audio-3.0-tts-plus` 与此前验证的音色和专用 `SpeechSynthesizer` 入口。密钥优先读取 `WEREWOLF_TTS_API_KEY`，缺省只读导入本机 Qwen Code 的 Token Plan 配置。不会改写全局配置，不会改走普通按量线路。原有 WAV 缓存保留并可复用。

### 小米 MiMo

内置 `type: "xiaomi-mimo"`，使用小米自己的 `chat/completions` 音频协议，解码 JSON 中的 base64 WAV；不是通用 `http-audio` 的二进制响应。默认模型 `mimo-v2.5-tts`，音色 `苏打`，语速 1。普通话预置音色还包括 `冰糖`、`茉莉`、`白桦`；英文预置音色为 `Mia`、`Chloe`、`Milo`、`Dean`。`mimo_default` 由所选集群决定默认声音。音色、模型与返回格式以 [小米 TTS API](https://mimo.mi.com/docs/zh-CN/api/audio/tts) 为准。

| 选择的线路 | 进程环境变量 | 没有配置文件时的网页选项 |
| --- | --- | --- |
| 普通 API（`billing: "api"`，缺省） | `XIAOMI_MIMO_API_KEY`；可选 `XIAOMI_MIMO_API_URL`，默认 `https://api.xiaomimimo.com/v1` | 小米 MiMo |
| Token Plan（`billing: "token-plan"`） | `XIAOMI_MIMO_TOKEN_PLAN_KEY` 和 `XIAOMI_MIMO_TOKEN_PLAN_URL`，两个都需要 | 小米 MiMo Token Plan |

Token Plan 地址使用控制台展示的 OpenAI 兼容 `/v1` 地址（中国、新加坡或欧洲集群），不能填 `/anthropic`。不同线路分别取 Key；失败直接报错，不换普通 API、不借用对话模型的密钥。

官方 [Token Plan 说明](https://mimo.mi.com/docs/zh-CN/tokenplan) 限制套餐用于编程工具场景，明确不允许明显非 Coding 的自定义应用后端。短句开发联调成功仅说明接口技术上可用；正式网页后端应配置普通 API 或取得服务商相应许可。是否免费和许可范围均以服务商当前说明为准，程序不自动替用户转换线路。

你在 Windows 用户环境变量中新增的值不会自动进入已启动的 Codex、终端或 Node 服务。重新打开终端并重启项目；如果父进程仍持有旧环境，可在启动服务的 PowerShell 中只读加载这两个值（不会打印 Key）：

```powershell
$env:XIAOMI_MIMO_TOKEN_PLAN_URL = [Environment]::GetEnvironmentVariable('XIAOMI_MIMO_TOKEN_PLAN_URL', 'User')
$env:XIAOMI_MIMO_TOKEN_PLAN_KEY = [Environment]::GetEnvironmentVariable('XIAOMI_MIMO_TOKEN_PLAN_KEY', 'User')
pnpm dev
```

刷新房间页，在「朗读来源」选择「小米 MiMo Token Plan」，再点击单条「朗读」或「开启自动朗读」。如果已有 `speech-providers.json`，环境变量不会覆盖其中的列表，需要手动加入以下提供方（保留已有条目）：

```json
{
  "id": "xiaomi-mimo-token-plan",
  "label": "小米 MiMo Token Plan",
  "type": "xiaomi-mimo",
  "billing": "token-plan",
  "model": "mimo-v2.5-tts",
  "voice": "苏打",
  "rate": 1,
  "instruction": "用自然清楚的普通话朗读，准确读出玩家号码。"
}
```

普通 API 将 `billing` 改为 `api`，并设置对应普通 API 环境变量。可通过 `apiKeyEnv`、`baseUrlEnv` 指定其他环境变量名，配置文件只写名称，不写密钥值。`rate` 为 0.5～2，映射为小米支持的自然语言语速指令，并非精确的服务端倍速参数；网页播放速度仍由播放器独立控制。声音设计可显式选择 `mimo-v2.5-tts-voicedesign` 并在 `instruction` 描述声音，此时不发送预置 `voice`；本次只实测预置音色。

小米当前公开接口没有字词时间戳开关，因此仅接入网页朗读，未加入视频 skill。Qwen 的 `word_timestamp_enabled` 不能套用于小米，能力与查询依据见 [TTS 时间戳能力](TTS时间戳能力.md)。

### HTTP 原始音频

`http-audio` 以 POST JSON 调用指定地址。`body` 中字符串里的 `{{text}}` 替换为完整授权原文，再由 JSON 编码，不能执行表达式或拼接代码。服务须直接返回音频字节；默认使用响应 `Content-Type`，也可配置 `mimeType`。

默认认证为 `Authorization: Bearer <apiKeyEnv 对应环境变量>`；可用 `apiKeyHeader`、`apiKeyPrefix` 调整为服务商要求的头部，也可配置固定 `headers`。密钥、地址和请求参数均留在服务端。HTTP 重定向被拒绝，避免把自定义认证头传给其他地址。返回 JSON 音频 URL、流式事件、特殊签名或其他协议的厂商使用模块适配器处理。

`http-json-audio` 使用相同请求方式，额外填写 `audioPath`（点分隔路径，数组用数字）、`encoding: "base64" | "hex"` 和 `mimeType`。可选 `statusPath/statusValue` 与 `completionPath/completionValue` 用于检查业务成功和完整结束。JSON 响应最多 60 MiB，解码后的音频继续受 40 MiB 上限与公共音频校验约束。错误响应及不完整音频不生成成功缓存。

### 自定义模块

`module` 是相对于配置文件的本机模块路径，也可用绝对路径；服务只加载管理员明确配置的文件，不从客户端接受模块文件或代码。房主网页可配置的 HTTP 地址走前述受限配置接口。模块导出：

```js
export async function synthesize({ text, options, signal }) {
  // 在这里实现厂商 SDK、签名、流式拼接或下载音频 URL。
  // 遵守 signal；只把给定原文发送到选定的服务。
  return { bytes: new Uint8Array(/* 完整音频 */), mimeType: 'audio/wav' };
}
```

支持的返回类型为 WAV、MP3、OGG、WebM、MP4 音频和 FLAC，实际能否解码取决于浏览器。单条限制 40 MiB，最长合成等待 240 秒。改变适配器代码或外部默认音色时，更新 `cacheVersion`，避免使用旧输出。

## 权限、缓存与兼容

- `GET /api/v1/rooms/:id/speech-providers` 需要房间凭证，只返回提供方 id、显示名、默认 id 和脱敏配置错误。
- `GET/POST /api/v1/rooms/:id/speech-settings`、`PUT/DELETE .../speech-settings/:connectionId` 仅接受本房间房主凭证。配置查询不返回密钥明文或密文；`POST .../speech-settings/:connectionId/test` 也仅房主可用，测试文本固定。
- `POST /api/v1/rooms/:id/speech` 接受 `{ "eventSeq": 3, "providerId": "my-http-tts" }`。服务端先生成该凭证的投影，再找对应的已接受 `speech`，不接受客户端自由文本、其他座位原始全局编号、密钥或端点。
- 正常引擎的公开发言均可听；将来若有受众受限的 `speech`，也必须先通过服务端投影授权，其他座位和观战不能借音频接口读取。`wolf.chat` 和思考不会因房主可见而混入朗读。
- 返回音频使用实际 MIME，并设置 `private, no-store`。缓存不作为静态路径公开。音频及元数据在忽略的 `data/speech/`，请求键覆盖文本、来源、模型、音色等配置。服务重启后校验摘要再复用，损坏缓存重新生成。
- 停止页面播放立即取消客户端等待并丢弃迟到结果；已有服务端合成可能继续完成，以供其他页面复用，页面停止不等同于提供方撤销计费。
- 通用 Qwen、音频与缓存工具已移到 `packages/session/src/speech/`，视频原路径保留重导出，原视频配置与提供方接口保持兼容。实时模块不再依赖制作脚本。

该轮界面测试观察到浏览器可能自动填入测试表单值；随后补充了表单 `autocomplete=off` 与 Key 栏 `autocomplete=new-password`。新构建通过类型检查和构建，但浏览器复查因工具无法可靠确认当前 URL 而停止，未将这次自动填充调整列为浏览器实测通过。
