# 发言朗读

更新：2026-11-01。房主、座位和观战页面均可朗读法官已接受的公开 `speak` 发言，包括竞选、PK、白天讨论和遗言。

## 使用

- 对局记录顶部点击「开启自动朗读」：先读当前最新一条，再按顺序播放新发言。
- 每条公开发言旁的「朗读」可以重听该条；会替换当前播放并清空积压队列，之后的新发言仍按自动开关入队。
- 支持暂停、继续、停止和 0.8～2 倍速。停止或关闭自动朗读会清空队列；刷新默认关闭，不会自动补读整局历史。
- 第一次播放可能被浏览器拦截，点击「继续播放」即可。生成音频期间显示「正在准备」，不会阻塞玩家提交行动或法官推进。

宽屏下，模型调用记录和右侧发言记录分别滚动。展开调用详情不会把整页撑长；右侧的播放控件保持在记录上方。手机宽度保持纵向排列。

## 来源、配置与缓存

当前内置浏览器实测不提供 `speechSynthesis`，因此首版复用项目已有的 **Token Plan Qwen TTS** 通道。界面明确标注「Token Plan 语音」，使用统一音色并读出座位号；尚未实现每席独立音色、原生浏览器朗读或语音识别。

服务端优先读取 `WEREWOLF_TTS_API_KEY`，缺省时只读导入本机 Qwen Code 配置中的 Token Plan 密钥。使用已有 `qwen-audio-3.0-tts-plus` 模型与 `SpeechSynthesizer` 入口；不会改写全局配置，不会在失败时切换普通按量付费线路。没有可用密钥、额度不足或服务失败时，页面提示错误并关闭自动队列。

生成的 WAV 与提供方元数据放在忽略目录 `data/speech/`，随 `WEREWOLF_DATA` 更换位置。内容、模型、音色和语速相同的请求复用缓存，多页面同时请求同一条发言只合成一次。浏览器只在当前页面持有音频，不会把缓存、真实发言或邀请凭证提交到 Git。

## 信息边界

`POST /api/v1/rooms/:id/speech` 使用房间凭证，正文为 `{ "eventSeq": 公开发言在本人投影中的编号 }`。服务端先生成该凭证获准看到的投影，再读取对应的公开 `speech`，不接受客户端自由文本、原始全局序号或客户端指定的身份。狼队密谈、私密行动、模型思考与审计正文不能通过此接口朗读。

音频使用 `audio/wav` 返回，响应禁止共享缓存；文件不作为静态路径暴露。当前按完整发言生成后播放，尚未实现流式首音频、预生成或跨页面播放进度同步。首次生成耗时取决于提供方，重复播放可直接复用本地缓存。

## 验证

自动化覆盖公开事件筛选、初次定位、重连去重、关闭期间不补读、不同投影编号、凭证边界、并发合成合并、失败重试和 WAV 长度修正。真实 Token Plan 已生成一条公开发言，内置浏览器成功解码并播放，确认播放进度前进、暂停／继续和 1.5 倍速生效。更多整局记录见 [架构评估与后续演进](架构评估与后续演进.md)。
