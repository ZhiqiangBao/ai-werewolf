# 中文、英文、日文国际化验收

日期：2026-11-03。基线：`627bce95d7685109bf566cd2bb9677914bf2b0ae`。

## 实际行为与语言归属

| 内容 | 使用的语言与来源 |
| --- | --- |
| 首页、导航、配置操作、通用按钮、确认框、辅助标签、日期与数字 | 当前浏览器的界面语言，独立保存在 `werewolf.ui-locale`。缺省中文。 |
| 房间规则、角色、技能、合法行动、目标、法官通知、行动回执、结果与复盘 | 房间配置语言；开局写入规则后固定。投影与模型对局上下文以规则语言为准。 |
| 配置校验、模型连接测试、语音设置及通用 API 错误 | 当前请求的界面语言；`Accept-Language` 包含界面包的基础语言回退顺序。 |
| 房间行动错误 | 通过原有凭证验证后使用房间语言；无效凭证错误使用请求的界面语言。 |
| 玩家名称、发言、模型思考与原始回复、工具名和参数值 | 保留原值，不自动翻译。 |
| 旧房间缺少语言字段 | 固定按 `zh-CN` 兼容，不读取浏览器语言来改变旧对局。 |

界面和房间选择器分别来自已注册资源。房间选择项还会与浏览器内实际注册的游戏语言取交集，避免服务端与网页版本不一致时列出网页无法处理的语言。注册其他语言或方言的操作见 [国际化扩展指南](国际化扩展指南.md)；接口存在不代表任意方言已有完整资源。

## 混语原因与修复

主要原因位于页面消费链路：`EventLog` 调用 `gameRecordEvents(events)` 时没有传房间语言。该函数会根据结构化事实重建预言家、女巫、守卫的客观记录，因此英语或日语局又显示成中文。现在上帝、玩家、旁观页面均显式传入投影／房间语言。

此外修复了圆桌阵营名称、行动选择与目标标签、投票和警长标签、身份及死亡状态、候场版型名、模型行动回执、配置目录与语音错误等动态拼装入口。语言改造没有扩大投影受众，也没有修改角色、合法目标、工具参数或胜负算法。发言状态识别兼容本地化阶段，且保留旧阶段文字的识别。

错误在生成处携带模板和参数，继续保留原有 `code`／`message` 接口。已知地址、协议、思考档位、时间配置和开局校验不再依赖解析中文正文。思考选项提供结构化提示，前端不再用中文正则重建说明。真实对局模型请求优先使用座位投影语言；非对局的连接测试使用独立语言字段，不伪造投影。

## 三角色固定场景

下列场景均使用模拟对局和固定发牌，分别运行 `zh-CN`、`en`、`ja`：

| 流程 | 检查内容 | 结果 |
| --- | --- | --- |
| 预言家 | 查验提示、合法目标、自查错误、好人／狼人结果、本人记录、上帝记录及复盘 | 通过 |
| 女巫 | 刀口、持药信息、救人／用毒／不用药选项、自毒错误、合法用毒、用药结果和回执、死亡原因 | 通过 |
| 守卫 | 守护／空守提示、合法目标、越界目标错误、守护确认、夜间记录及死亡结算 | 通过 |

其他座位与旁观者不能获得这些私密事件；上帝仍按原有权限获得完整记录。各语言相同行动的事实 payload 与死亡原因一致。守卫为单人决策，提交后立即结算，验证的是其私密确认事件；不伪造一个不存在的持久提交状态。

狼人、放逐投票、警长、警徽、猎人、死亡和胜负另由整局语言模拟、动作工具、权限、回执和随机重放测试覆盖。三个模型协议的连接测试使用模拟接口，检查语言字段、成功／失败文案、供应商原文脱敏及投影语言优先级。

## 界面与真实页面检查

组件渲染验证覆盖中文界面＋中文房间、英文界面＋英文房间、日文界面＋日文房间，以及日文界面＋英文房间；同时验证身份卡、行动选项、记录、票型和原话保护。

实际浏览器使用单独的本机内存测试服务，未打开或修改已有真实对局。检查了三语首页、创建房间、规则配置、中文预言家、英文女巫、日文预言家和守卫，以及英语上帝／旁观者页面。混合组合中，日文通用控件与英文刀口、药品、毒药目标同时显示；界面切换没有改变房间语言。上帝可见的守护、查验和刀口记录没有出现在旁观页面。

390 像素窄屏检查中，行动按钮能换行，圆桌与上帝表格没有造成页面横向溢出；实际可用宽度与页面滚动宽度均为 380 像素。长规则正文保留换行和内部滚动。补译了非品牌的装饰文案；品牌名及协议、模型、系统音色名称保留原名。

## 自动验证

使用本机已安装的工具运行；没有调用真实模型、图像或 TTS 服务。当前环境的普通 PowerShell `pnpm` 入口存在模块问题，系统 Corepack 入口尝试联网解析版本也失败，因此验证使用安装依赖中的等价 Node 入口，独立工作区依赖通过离线安装复用。

```text
node --import tsx scripts/check-locales.ts
node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit
node node_modules/vitest/vitest.mjs run --testTimeout=30000 --maxWorkers=4
# 在 apps/web 中：
node node_modules/vite/bin/vite.js build
```

语言检查：三种语言各扫描 1096 个游戏模板和 405 个界面模板，缺项为零；同时检查重复、空译文与占位符。注册测试覆盖新语言的显示、基础语言继承、缺项报告和参数原文保护。静态扫描结合目录枚举，不能代替运行时验收，以上角色和页面检查另行执行。

类型检查和生产构建通过。最终纯国际化分支完整回归为 **102 个测试文件、845 项全部通过**；包含其他任务改动的共享工作区上一轮完整回归为 107 个文件、863 项通过，此后受影响的历史重建和页面测试也通过。构建仍提示主资源包超过 500 kB；没有为本次任务改动构建拆包策略。

## 独立审查与修复

已通过实际安装的 Agent CLI，无头调用 Grok 4.7 `xhigh` 完成方案及源码审查；另外以 `high` 对纯国际化差异做聚焦复核。模型名称来自 CLI 的实际模型列表，没有把其他模型冒充 Grok。

`xhigh` 确认关键三角色的正常链路、视角权限和两类语言分离已经接通，指出以下问题，均已修复并补充回归：

1. 非法 URL 的异常分支没有应用显示语言，导致英日配置错误夹带中文。现在保留结构化信息，同时按请求语言生成提示。
2. 协议、时间和开局校验在异常包装时丢失详细信息。现在透传模板，开局明细按界面语言生成，保留原有调用接口的缺省行为。
3. 旧合刀记录缺少严格 payload 检查，以及部分英文列表标点仍由前端或引擎写死。现在无法可靠重建时保留原文；已知系统模板和药品列表使用房间资源。

`high` 聚焦复核指出的私密记录受众校验和英文受众列表分隔符也已修复。`guard.skip`、`seer.skip`、`witch.idle` 等记录只有在能确认合法的单个本人受众时才重建，其他情况保留原文。

`high` 对发言阶段的 P2 判断未采纳：其材料没有引擎生成处，结论依赖“如果词条或空格不一致”的假设。实际 `flow/day.ts` 的 `SPEECH_LABEL` 正是无空格的 `PK发言`／`竞选PK发言`，与网页匹配使用同一模板。新增测试直接运行引擎 handler，验证三种语言的发言、竞选、PK、竞选 PK 和遗言共 15 个实际阶段均可识别，没有依照假设改动游戏流程。

浏览器配置页发现的规则卡标题漏传语言也已修复，覆盖 `Setup` 与 `HumanLobby`；规则卡和事件组件现在要求显式传入语言，旧房间仍可明确传入 `undefined` 并回退中文。

方案审查建议不让房间语言继承基础包，这一点未采用：用户明确要求保留房间语言与方言的注册及基础语言回退。三套本期基础包要求完整，扩展包可以显式继承，检查结果区分缺项与有意继承。不需要对此明确需求调用仲裁模型。

## 历史与未执行边界

- 已保存的原始事件、对话、审计和模型原生续接不被重写；仅展示时对有明确类型及可靠结构化 payload 的已知系统事件作客观格式化。缺失或非法的目标、查验结果、合刀元组保留原文。
- 旧记录原文、玩家输入、模型输出、服务商原始诊断及专有名称可能与当前语言不同；不会对这些任意字符串全文替换。
- 未运行英文／日文真实模型样本，也未实测外部 TTS 发音。测试通过的是系统文案和模拟协议；提示词不能保证所有模型遵循语言要求。
- 视频只验证现有导出、locale 与 TTS 接口兼容，没有制作三语视频或翻译全部历史素材。

## 提交隔离

独立分支为 `codex/i18n`，工作区位于 `data/i18n-work/isolated`。音频取消／恢复及其他任务的未提交改动未纳入本次提交。重叠的网页播放组件、Game 页面和 HTTP 文件在独立分支上按原始行为单独移植国际化，完整验证该分支不依赖未提交音频代码。共享工作区原有分支和改动继续保留。
