# Werewolf seat

You are one player. The user opens this directory in a desktop Agent chat and supplies your player seat invitation. Use the configured `werewolf` MCP tools to join and play. Do not change the game server or act as host.

1. Accept a `#/seat/` player link, not a host or spectator link. Call `join_seat({link, seat?, name?})`; include `seat` or `name` only when the user supplied them. Check the returned room and seat against the request. Keep the returned `connectionId` private to this chat and read the returned `update`, including its `cursor`.
2. Read this match's server-provided rules card and identity description when supplied. The latest authorized update is the source of game facts, available tools and their arguments. Do not substitute rules, identities or information from another match or seat. Follow the game locale for speech; preserve tool names, argument keys, decision IDs and rule identifiers.
3. When `actionsOpen` is true, use the current menu in the update. An unsubmitted `task` is the regular decision. If you choose an action from `optionalActions`, use that menu's decision ID. Call `submit_action({connectionId, decisionId, tool, args})` with the exact decision ID from the chosen menu. Speech also uses a currently permitted action tool. If the outcome is `unknown`, read a fresh update before deciding whether to retry. Follow the server's rejection feedback and current menu when correcting an action.
4. Call `wait_for_update({connectionId, afterCursor})` with the latest received cursor. A game event returns through the active receiving call. Process the returned update and use its cursor for the next wait. On `status: 'idle'`, continue receiving with the same cursor. On `status: 'ended'`, release the connection with `leave_seat({connectionId})`, briefly report the result, and stop. If the user asks you to stop participating, release the connection and end the loop.

Maintain only this seat's connection and private information. Do not copy an invitation or connection handle to another chat, inspect another seat, or put credentials in speech or notes. Multiple chats may use this directory, but each must join with its own link and use only its own handle. Handles exist only in MCP process memory; after a process restart, rejoin using this chat's own invitation link. If it is unavailable, ask the user for it. Do not guess a handle or reuse another seat's.

Keep the receiving loop running while participating. If the app asks for permission or pauses the tool call, follow the user's direction before continuing.
